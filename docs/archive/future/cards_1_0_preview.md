## 为什么 MVP 不做卡牌

- **核心玩法验证优先**——MVP 要先证明"完美信息棋盘 + 物理推撞 + 建筑保护"这套核心循环本身好玩
- **避免认知过载**——同时引入"棋盘解谜 + 卡组构筑"是双倍学习曲线，新玩家很容易劝退
- **AI 美术成本**——卡牌需要单独的卡面立绘 + 卡牌图标 + UI 框架，是独立资产管线

**MVP 验证成功后，1.0+ 第 1 版迭代时引入**——届时玩家已经熟悉了战斗循环，再加入卡牌系统作为深化层。

---

## 1. 卡牌哲学（1.0+）

**卡牌 = 临时法则改写**，不是主要伤害来源。

- 不要做"杀戮尖塔式高频出牌"——那是另一种游戏
- 卡牌是**关键时刻的工具**——当物理推撞解决不了的时候，打一张卡破局
- 每场战斗只带 3 张，每张限用 1 次 → 卡牌是**稀缺资源**，不是日常工具

---

## 2. 卡牌设计原则（关键决策）

**所有卡牌必须满足"可读性测试"**：

1. **效果一句话讲清楚** — 玩家读完卡面文字立即明白发生什么
2. **结果可预演** — 打出前棋盘上能精确显示卡牌效果的格子/单位
3. **无 UI 状态炸弹** — 不创造"持续 N 回合的特殊状态"等需要专门 UI 跟踪的复杂效果

### 被否决的卡牌（"看着酷但完美信息游戏会废"）

- ❌ **推力倒置 / 零摩擦 / 时间倒流** — 临时改变物理规则，玩家心智需要在两套规则间切换
- ❌ **位移咒（互换位置）** — 涉及"反向连锁"，UI 预演会变得不一致
- ❌ **虚空印记（变深渊）** — 改地形，需要持续状态 UI
- ❌ **反射结界（攻击反弹）** — 改伤害方向，所有连锁路径都要重新预演

---

## 3. 1.0+ 卡牌候选清单（设想，需 UI 验证后才能落地）

### 类一：位置控制

- 《**脉冲推送**》：选任意敌人 → 推 1 格
- 《**牵引**》：选任意敌人 → 拉 1 格
- 《**强力推送**》(稀有)：选任意敌人 → 推 2 格（可触发撞墙 2 伤）
- 《**回退**》：选 1 个本回合已经移动的敌人，取消其移动

### 类二：节奏控制

- 《**重置预警**》：选 1 个敌人，取消其本回合的所有行动
- 《**钉地**》：选 1 个敌人，让它本回合的移动距离变为 0

### 类三：临时建筑

- 《**临时石柱**》：选 1 空格生成临时石柱
- 《**临时屏障**》：选 1 建筑，本回合内免疫所有伤害

---

## 4. 1.0+ 实现路径建议

如果 MVP 验证成功并准备扩展卡牌系统：

1. **先做 UI 决定论扩展**——卡牌效果必须能在棋盘上**预演**（与现有"敌方预警 / 玩家可达集"统一视觉语言）
2. **从 3-4 张最简单的卡开始**——《脉冲推送》《牵引》《临时石柱》三张铺底
3. **每加一张卡都做认知负载测试**——是否破坏"棋盘读得懂"的核心体验？
4. **战前选 3 张** + **每张限用 1 次**——保持稀缺性，不做高频出牌

> **关键认知**：本章节不是 MVP 路线图，是**给未来留个钩子**。MVP 验证战斗循环时，可以先在某些场景假装"如果有这张卡会怎样"——验证卡牌系统是否真有价值再开始做。
