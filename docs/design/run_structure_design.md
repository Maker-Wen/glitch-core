# Run 结构与路线推进设计

> 日期：2026-06-04  
> 状态：第一版执行规格  
> 依赖：[defense_roguelite_core_design.md](defense_roguelite_core_design.md)、[battle_objectives_and_rewards.md](battle_objectives_and_rewards.md)、[run_relic_economy_design.md](run_relic_economy_design.md)

## 1. 目的

本文档补齐 Run 层的执行设计，回答以下问题：

1. 一局 Run 有多长，章节如何推进。
2. 路线图如何生成，节点如何连接和预览。
3. 普通战、精英战、事件、工坊、商店、营地、神龛和 Boss 节点分别如何改变 Run 状态。
4. 奖励、损耗、恢复和腐化如何形成稳定节奏。
5. 存档、继续 Run、失败和通关如何落地。
6. 第一轮 Demo 应该使用什么固定路线和配置。

本文档不替代战斗规则、遗物池和守卫者技能文档。战斗胜负以 [battle_objectives_and_rewards.md](battle_objectives_and_rewards.md) 为准，遗物与价格以 [run_relic_economy_design.md](run_relic_economy_design.md) 为准。

## 2. 核心裁定

- Run 是肉鸽深度的承载层，但不能改变标准战斗胜利条件。
- 标准战斗永远是防守战：撑到最大回合，至少 1 名守卫者存活。
- Run 随机性只出现在路线、节点、事件、奖励、遗物、敌群组合和地图组合。
- 战斗内不做随机命中、随机伤害、隐藏 AI 或实时倒计时。
- 完整第一版 Run 为 3 章；第一轮 Demo 为 1 章 6 节点。
- 守护值和守卫者 HP 是两条 Run 级生命线。
- 守护值归 0，或所有守卫者死亡，都会导致 Run 失败。
- 单个守卫者死亡后从本 Run 名单移除；如果还有 1-2 名守卫者存活，Run 可以残编继续。
- 残编不会触发自动降难。系统只负责清楚预警风险，不偷偷调低关卡。

## 3. Run 状态

Run 状态必须能独立驱动路线、战斗进入、奖励结算和继续游戏。

| 字段 | 类型 | 说明 |
|---|---|---|
| `run_id` | string | 当前 Run 存档 ID |
| `run_seed` | int | 当前 Run 的路线和奖励随机种子 |
| `difficulty_id` | string | 难度配置，Demo 可以固定为 `normal` |
| `phase` | enum | `prep`、`route`、`node_preview`、`battle`、`node_resolution`、`reward`、`chapter_result`、`run_result` |
| `chapter_index` | int | 当前章节，从 1 开始 |
| `chapter_node_index` | int | 当前章节已完成节点数量 |
| `current_node_id` | string | 当前选中的路线节点 |
| `sanctuary_integrity` | int | 当前守护值 |
| `sanctuary_integrity_max` | int | 守护值上限，默认 12 |
| `embers` | int | 余烬货币 |
| `corruption` | int | 腐化值 |
| `wardens` | array | 守卫者 ID、HP、最大 HP、升级、死亡状态 |
| `relics` | array | 已获得遗物 |
| `route_graph` | object | 当前章节路线图 |
| `visited_nodes` | array | 已完成节点 |
| `pending_reward` | object | 待领取奖励，防止重复发放 |
| `chapter_guardian_reward_used` | bool | 本章是否已通过奖励任务恢复守护值 |
| `node_entry_snapshot` | object | 进入节点前的安全快照，用于 MVP 继续 Run |

### 3.1 守卫者状态

| 字段 | 说明 |
|---|---|
| `warden_id` | 守卫者配置 ID |
| `hp` | 当前 HP |
| `hp_max` | 最大 HP |
| `upgrades` | 已获得升级 ID |
| `alive` | 是否存活 |
| `death_node_id` | 死亡节点，结算和回顾使用 |

守卫者没有“倒地后归队”状态。HP 为 1 是濒死，仍可行动；HP 为 0 是死亡，棋子从棋盘移除，本 Run 不再出现。

### 3.2 章节状态

| 字段 | 说明 |
|---|---|
| `chapter_id` | 章节配置 ID |
| `chapter_seed` | 章节路线和奖励种子 |
| `boss_node_id` | 本章 Boss 节点 |
| `available_nodes` | 当前可选择节点 |
| `completed_node_ids` | 已完成节点 |
| `chapter_reward_claimed` | 是否已领取 Boss 后章节奖励 |

章节状态在进入新章节时生成。完成 Boss 并领取章节奖励后，若不是第 3 章，则生成下一章路线。

## 4. Run 长度和章节

为了避免实现歧义，本文档中的“节点数”统一表示含 Boss 的章节总节点数。

| 版本 | 章节数 | 节点节奏 | 目的 |
|---|---:|---|---|
| Demo | 1 | 6 个节点，固定路线 | 验证完整闭环和基础数值 |
| 第一版完整 Run | 3 | 第 1 章 6 节点，第 2 章 7 节点，第 3 章 7 节点 | 验证构筑成长和长期损耗 |
| 后续扩展 | 3-4 | 每章 5-7 个路线节点 + Boss | 增加路线差异和事件池 |

### 4.1 第 1 章：外墙余烬

| 项 | 配置 |
|---|---|
| 总节点 | 6 |
| 主题 | 基础建筑防守、少量地裂、简单远程线压 |
| 主要敌人 | 腐食兽、瘟疫弓手 |
| 精英引入 | 铁角兽可以在精英战首次出现 |
| 裂隙强度 | 0-2，首战可以为 0 |
| 压力标签 | 基础防守、远程线压、裂隙压力、堵路拥挤 |
| 地图模块 | 外墙缺口、石柱庭院、浅裂隙、少量深渊边缘 |
| 目标 | 让玩家理解守护值、建筑 HP、公开意图和奖励任务 |

第 1 章不允许同时出现“裂隙强度 2 + 精英冲撞 + 远程线压”的满压组合。第一章的失败主要来自建筑损失，而不是守卫者被秒杀。

### 4.2 第 2 章：裂隙回廊

| 项 | 配置 |
|---|---|
| 总节点 | 7 |
| 主题 | 裂隙压制、精英冲撞、资源取舍 |
| 主要敌人 | 腐食兽、瘟疫弓手、铁角兽、裂隙司祭、腐爆囊 |
| 裂隙强度 | 1-3 |
| 压力标签 | 基础防守、裂隙压力、远程线压、精英冲撞、深渊边缘 |
| 地图模块 | 多裂隙庭院、断桥、狭路、保护目标分散布局 |
| 目标 | 让玩家在守建筑、占裂隙、处理精英之间做取舍 |

第 2 章开始允许腐化改变路线压力，但必须在节点预览中公开。高腐化不能在进入战斗后才临时追加敌人。

### 4.3 第 3 章：长夜钟楼

| 项 | 配置 |
|---|---|
| 总节点 | 7 |
| 主题 | Boss 脚本、高级敌人组合、终局资源压力 |
| 主要敌人 | 铁角兽、裂隙司祭、钟奴、护壳虫、Boss 召唤物 |
| 裂隙强度 | 2-3 |
| 压力标签 | 基础防守、裂隙压力、精英冲撞、深渊边缘、Boss 脚本 |
| 地图模块 | 钟波线、腐化泥、深渊边缘、关键建筑 |
| 目标 | 检验玩家构筑是否能处理多条公开硬威胁 |

第 3 章可以更难，但仍要遵守硬威胁上限：普通战每回合最多 2 个硬威胁，精英战和 Boss 战最多 3 个硬威胁。

## 5. 路线图模型

路线图使用分层有向图，不使用自由大地图。

```text
起点
  -> 第 1 层节点
  -> 第 2 层节点
  -> 第 3 层节点
  -> ...
  -> Boss
```

每个节点包含：

| 字段 | 说明 |
|---|---|
| `node_id` | 节点唯一 ID |
| `layer` | 节点所在层 |
| `lane` | 节点所在路线列 |
| `node_type` | 普通战、精英战、事件、工坊、商店、营地、神龛、Boss |
| `risk_level` | 1-5，用于 UI 风险展示 |
| `pressure_tags` | 战斗节点压力标签 |
| `rift_strength` | 裂隙强度 0-3 |
| `encounter_config_id` | 战斗配置 ID |
| `reward_table_id` | 奖励表 ID |
| `event_config_id` | 事件配置 ID，非事件节点为空 |
| `outgoing_edges` | 可前往的后续节点 |
| `visited` | 是否已完成 |

### 5.1 生成步骤

1. 根据章节配置读取节点总数、节点权重、敌人池、地图池和 Boss。
2. 固定第 1 个节点为普通战。
3. 固定最后 1 个节点为 Boss。
4. 生成 2-3 条路线列，并在相邻层之间建立边。
5. 按章节权重填充普通战、精英战、事件、工坊、商店、营地和神龛。
6. 给战斗节点分配压力标签、裂隙强度、敌人预算和地图模板。
7. 应用腐化带来的公开路线修正。
8. 运行合法性校验；不合法则重新生成或回退到章节预设。

### 5.2 路线合法性约束

| 约束 | 规则 |
|---|---|
| 首节点 | 每章第 1 个节点必须是普通战 |
| 终节点 | 每章最后 1 个节点必须是 Boss |
| 路线宽度 | 中间层提供 2-3 个可选节点 |
| 可达性 | 每个显示节点都必须能从起点到达，也必须能通向 Boss |
| 连续战斗 | 同一路径不连续出现 3 个战斗节点，除非该路线标记为高风险高收益 |
| 精英后缓冲 | 精英战后下一层至少存在 1 个可达非战斗节点 |
| Boss 前节点 | Boss 前 1 层不能是神龛 |
| 恢复机会 | 每章至少 1 个营地；完整第一版每条主路径至少可到达 1 个营地、商店或工坊 |
| 神龛数量 | 第 1 章不出现；第 2 章后每章最多 1 个 |
| 残编预警 | 若存活守卫者少于 3，所有战斗节点预览显示残编风险 |

高风险高收益路线可以违反“连续战斗”约束，但必须同时满足：

- 路线图上有明显高风险标记。
- 至少提高 1 档奖励，例如额外普通遗物、额外奖励选项或 +4 余烬。
- 不能把高风险路线设为通往 Boss 的唯一选择。

### 5.3 压力标签预算

压力标签不改变胜利条件，只改变敌人池、地图模块、出怪预算和奖励任务推荐。

| 压力标签 | 权重 | 说明 |
|---|---:|---|
| 基础防守 | 0 | 默认存在，不消耗压力预算 |
| 远程线压 | 1 | 弓手、钟奴、长线攻击 |
| 裂隙压力 | 1 | 地裂预告出怪、占位延迟 |
| 深渊边缘 | 1 | 坠落和边缘推位 |
| 堵路拥挤 | 1 | 狭路、路障、建筑阵型 |
| 精英冲撞 | 2 | 铁角兽或同级精英硬威胁 |
| Boss 脚本 | 2 | Boss 公开脚本和毁灭计数 |

| 节点 | 压力预算 | 备注 |
|---|---:|---|
| 普通战 | 2 | 不含基础防守 |
| 精英战 | 3 | 至多 1 个权重 2 标签 |
| Boss 战 | 4 | 必含 Boss 脚本，但不能同时满配所有高压标签 |

压力预算是路线生成约束，不是战斗内动态难度。进入节点前，玩家必须能看到最终压力标签。

## 6. 节点类型

### 6.1 普通战

| 项 | 规则 |
|---|---|
| 作用 | 稳定获得余烬，制造基础损耗 |
| 基础奖励 | 7 余烬 |
| 奖励任务 | 3 个通用任务 |
| 敌人预算 | 普通战总敌人 7-10 个 |
| 硬威胁上限 | 每回合最多 2 个 |
| 裂隙强度 | 第 1 章 0-2，第 2 章 1-2，第 3 章 2 |

普通战是玩家构筑的基础检验，不应该因为低难而无意义。普通战可以毁建筑、压守护值，也可以逼出营地选择。

### 6.2 精英战

| 项 | 规则 |
|---|---|
| 作用 | 高风险遗物和高额奖励来源 |
| 基础奖励 | 11 余烬 + 1 个遗物奖励 |
| 奖励任务 | 3 个通用任务，可以提高稀有权重 |
| 敌人预算 | 精英战总敌人 10-13 个 |
| 硬威胁上限 | 每回合最多 3 个 |
| 裂隙强度 | 第 1 章 1-2，第 2 章 2-3，第 3 章 2-3 |

精英战后必须提供非战斗缓冲选择。精英战不是强制通路，除非当前章节是教程式固定 Demo。

### 6.3 Boss 战

| 项 | 规则 |
|---|---|
| 作用 | 章节终局，检验章节主题 |
| 基础奖励 | 14 余烬 + 章节奖励 |
| 奖励任务 | 3 个 Boss 专属任务 |
| 敌人预算 | Boss 战总敌人 12-16 个 |
| 硬威胁上限 | 每回合最多 3 个 |
| 裂隙强度 | 第 1 章 2，第 2-3 章 2-3 |

Boss 胜利仍按最大回合防守结算。击破 Boss 部件、锚石或弱点只能降低压力、完成奖励任务或改变章节奖励，不能提前结束战斗。

Boss 战失败分两类：

| 失败 | 后果 |
|---|---|
| 队伍覆灭 | Run 立即失败 |
| Boss 溃败 | 本场提前结束，只按保护目标受伤或战前公开 Boss 代价扣守护值；守护值仍大于 0 时回到同一 Boss 节点预览 |

Boss 溃败后不发放奖励，不标记章节完成，死亡和 HP 损耗保留。玩家只能重新挑战同一 Boss 节点；如果守护值归 0 或全队死亡，Run 失败。这样保持“守护值是 Run 级失败线”的统一规则。

### 6.4 事件

| 项 | 规则 |
|---|---|
| 作用 | 资源交换、风险选择、构筑修正 |
| 输入 | 当前守护值、余烬、腐化、守卫者 HP、遗物 |
| 输出 | 余烬、腐化、守护值、HP、升级、遗物或下一战修正 |
| 预览 | 显示事件主题和会影响的资源类型 |

事件进入后必须展示明确选项。玩家确认选项前，必须看到完整收益和代价。

事件不允许：

- 进入下一场战斗后才揭示负面效果。
- 随机伤害某名守卫者而不提前说明候选范围。
- 给“看似免费但实际隐藏腐化”的奖励。

### 6.5 工坊

| 项 | 规则 |
|---|---|
| 作用 | 定向强化守卫者，补队伍短板 |
| 主要商品 | 普通升级、稀有升级、刷新升级选项 |
| 基准价格 | 普通升级 10，稀有升级 14，刷新 3 |
| UI 重点 | 显示守卫者 HP、已有升级、升级类别、购买后余烬 |

Demo 可以把工坊后置。完整第一版每章至少让玩家有 1 次可到达工坊或商店选择，避免成长完全依赖战斗掉落。

### 6.6 商店

| 项 | 规则 |
|---|---|
| 作用 | 购买遗物、小额急救、小额修复守护值 |
| 商品 | 普通遗物、稀有遗物、单人治疗、守护值修复、刷新 |
| 基准价格 | 普通遗物 12，稀有遗物 18，单人治疗 4，守护值 +1 为 6 |
| 库存限制 | 每个商店默认守护值修复 1 次，单人治疗 1-2 次 |

商店用于补洞，不用于完全抹平损耗。商店离开后不能返回购买。

### 6.7 营地

| 项 | 规则 |
|---|---|
| 作用 | 大额恢复节点，迫使人员线和防线线取舍 |
| 默认选项 A | 治疗小队：所有存活守卫者 +1 HP，不超过上限 |
| 默认选项 B | 修复防线：守护值 +2，不超过上限 |
| 后续选项 C | 整备装备：获得 1 个普通升级选项，第 2 章后可出现 |

营地是免费节点选择，但每次只能选 1 项。死亡守卫者不能通过营地复活。

### 6.8 神龛

| 项 | 规则 |
|---|---|
| 作用 | 高收益高腐化路线 |
| 出现章节 | 第 2 章后 |
| 常见收益 | 稀有遗物、诅咒遗物、额外奖励选项 |
| 常见代价 | 腐化 +2、守护值 -1、守卫者受伤 |

神龛必须在路线图上标记为高风险节点。Boss 前 1 层不能出现神龛，避免玩家被迫带着刚获得的高腐化直接进入 Boss。

## 7. 节点预览

节点预览是 Run 策略成立的前提。玩家在确认前进前，必须知道足以影响决策的信息。

### 7.1 战斗节点预览

| 信息 | 示例 |
|---|---|
| 节点类型 | 普通战、精英战、Boss |
| 风险等级 | 1-5 |
| 压力标签 | 裂隙压力、远程线压 |
| 裂隙强度 | 0-3 |
| 敌人提示 | 腐食兽、瘟疫弓手，可能出现铁角兽 |
| 硬威胁上限 | 普通战 2，精英战 3 |
| 地图提示 | 深渊边缘、石柱、狭路、关键建筑 |
| 回合数 | 5 或 6 |
| 保护目标 | 普通建筑数量、关键建筑数量 |
| 基础奖励 | 7 / 11 / 14 余烬 |
| 额外奖励 | 遗物、章节奖励、奖励任务收益 |
| 当前资源 | 守护值、余烬、腐化、守卫者 HP |
| 警告 | 残编、高腐化、Boss 毁灭计数初始 +1 |

预览不需要展示完整地图，但不能隐藏“会改变路线选择”的风险。例如深渊、精英冲撞、Boss 毁灭计数、裂隙强度和关键建筑都必须公开。

### 7.2 非战斗节点预览

| 节点 | 必须展示 |
|---|---|
| 事件 | 事件主题、影响资源类型、是否高风险 |
| 工坊 | 可购买升级类别、价格范围 |
| 商店 | 商品类型、是否包含治疗或修复 |
| 营地 | 可恢复 HP 或守护值 |
| 神龛 | 高腐化标记、可能收益类型、可能代价类型 |

事件和神龛可以在进入后展示具体选项，但不能在玩家确认选择后再追加隐藏代价。

## 8. 奖励节奏

### 8.1 战斗基础奖励

| 节点 | 基础奖励 | 额外奖励来源 |
|---|---:|---|
| 普通战 | 7 余烬 | 奖励任务、少量击杀上限 |
| 精英战 | 11 余烬 + 遗物 | 奖励任务、稀有权重 |
| Boss 战 | 14 余烬 + 章节奖励 | Boss 奖励任务 |

普通战如果保留击杀余烬，整场上限为 3。Boss 召唤的杂兵不提供击杀余烬。

### 8.2 奖励任务收益

| 完成任务数 | 普通战 | 精英战 | Boss 战 |
|---:|---|---|---|
| 0 | 无 | 无 | 无 |
| 1 | +2 余烬 | +3 余烬 | +3 余烬 |
| 2 | +4 余烬，奖励选项 +1 | +5 余烬，奖励选项 +1 | +5 余烬，章节奖励选项 +1 |
| 3 | +6 余烬，奖励选项 +1，章节内守护值 +1 机会 | +8 余烬，稀有遗物权重提高 | +8 余烬，章节奖励选项 +1，稀有权重提高 |

每章通过奖励任务恢复守护值最多 1 次。这个上限跨普通战、精英战和 Boss 战共享。

### 8.3 章节奖励

Boss 胜利后进入章节奖励。第 1 章和第 2 章从以下类别中选择 1 项：

| 类别 | 效果 |
|---|---|
| 遗物 | 普通或稀有遗物 3 选 1；第 2 章后稀有权重提高 |
| 守卫者升级 | 选择 1 名存活守卫者，获得升级 2 选 1 |
| 战线整备 | 守护值 +1，并治疗 1 名存活守卫者 +1 HP |

第 3 章 Boss 胜利后不再发放可用于继续 Run 的章节奖励，而是进入通关结算。

### 8.4 每章收入预期

| 章节 | 节点结构 | 基础余烬 | 预期额外 | 预期总收入 |
|---|---|---:|---:|---:|
| 第 1 章 | 2 普通 + 1 精英 + 1 Boss + 1 事件 + 1 营地 | 39 | 8-16 | 45-60 |
| 第 2 章 | 3 普通 + 1 精英 + 1 Boss + 2 非战斗 | 46 | 12-22 | 55-75 |
| 第 3 章 | 2 普通 + 2 精英 + 1 Boss + 2 非战斗 | 50 | 14-24 | 60-80 |

预期总收入包含事件可能带来的波动。价格目标是玩家每章通常能购买 1-2 个关键成长或恢复，而不是买空所有商品。

## 9. 损耗和恢复节奏

### 9.1 守护值

守护值默认 12 / 12。

| 来源 | 变化 | 说明 |
|---|---:|---|
| 保护目标受伤 | 每 1 点实际伤害 -1 | 没有单场封顶；战斗内 HUD 和行动预演必须实时显示预计损失 |
| 防线溃败 | 不额外扣减 | 保护目标全毁时，建筑 HP 已经自然转化为守护值损失 |
| Boss 溃败 | 按公开 Boss 规则处理 | Doom 本身不等于守护值；若 Boss 规则造成保护目标伤害，按伤害扣减 |
| 营地修复防线 | +2 | 不超过上限 |
| 商店修复防线 | +1 | 基准价格 6 余烬，默认库存 1 |
| 高难奖励任务 | +1 | 每章最多 1 次 |

每章标准恢复预算为 2-4 点。高恢复路线必须牺牲成长或承担腐化，不能让守护值损失变成无成本。

### 9.2 守卫者 HP

| 来源 | 效果 | 说明 |
|---|---|---|
| 战斗结束 | 不自动恢复 | 保留跨战斗损耗 |
| 营地治疗小队 | 所有存活守卫者 +1 HP | 不超过上限 |
| 商店急救 | 1 名存活守卫者 +1 HP | 基准价格 4 余烬 |
| 事件 | 公开选项决定 | 可治疗，也可造成伤害 |
| 死亡 | 从 Run 名单移除 | 第一版不复活 |

如果当前只剩 1-2 名守卫者，路线图仍可继续推进，但战斗节点必须展示残编风险。残编进入 Boss 通常应被 UI 标为高风险。

### 9.3 腐化

| 腐化值 | Run 层效果 |
|---:|---|
| 0-2 | 无 |
| 3-4 | 每章额外 1 个裂隙强化 |
| 5-6 | 精英战硬威胁上限 +1，但仍不能超过 3 |
| 7+ | Boss 战毁灭计数初始 +1 |

腐化只改变公开的战前配置和路线预览。腐化不能在战斗中随机触发隐藏敌人或隐藏伤害。

## 10. 难度曲线

### 10.1 节点压力递进

| 阶段 | 目标压力 |
|---|---|
| 第 1 章前半 | 单一意图教学：近战攻击、建筑受伤、简单挡线 |
| 第 1 章后半 | 引入裂隙和远程线压，奖励任务开始制造取舍 |
| 第 2 章前半 | 裂隙强度稳定出现，玩家需要占位和处理精英 |
| 第 2 章后半 | 腐化、精英战和路线选择开始决定损耗 |
| 第 3 章 | Boss 脚本、裂隙压力和高级敌人组合检验构筑 |

### 10.2 反峰值规则

路线生成和关卡配置必须避免以下组合：

- 普通战同时出现 3 个以上非基础压力标签。
- 第 1 章出现裂隙强度 3。
- 精英冲撞、裂隙强度 3、远程线压和深渊边缘在同一普通战同时出现。
- Boss 战同时满配 Boss 脚本、裂隙强度 3、精英冲撞和远程线压。
- 存活守卫者少于 3 时，强制进入唯一高风险战斗路线。

这些限制不是降低挑战，而是保证 3 名守卫者的行动数有理论解法。

## 11. Run 开始、失败和通关

### 11.1 新 Run

完整第一版流程：

```text
主菜单
  -> 新 Run
  -> 难度选择
  -> 守卫者 5 选 3
  -> 初始遗物 3 选 1
  -> 生成第 1 章路线
  -> 进入路线图
```

Demo 流程：

```text
主菜单
  -> 新 Run
  -> 固定 3 名守卫者
  -> 守护值 12 / 12
  -> 余烬 0
  -> 腐化 0
  -> 无初始遗物
  -> 进入固定 6 节点路线
```

如果存在未结束 Run，点击新 Run 必须二次确认覆盖。

### 11.2 继续 Run

继续 Run 读取最近未结束存档，根据 `phase` 回到对应页面：

| `phase` | 恢复位置 |
|---|---|
| `route` | 当前章节路线图 |
| `node_preview` | 当前路线图，取消未确认预览 |
| `battle` | MVP 回到进入战斗前快照，用同一节点配置重新开始 |
| `node_resolution` | 节点结果页 |
| `reward` | 待领取奖励页 |
| `chapter_result` | 章节结算页 |
| `run_result` | 失败或通关结算页 |

MVP 不要求战斗内逐行动存档。若要支持战斗内继续，后续需要记录确定性行动日志。

### 11.3 失败

| 失败原因 | 触发 |
|---|---|
| 守护值耗尽 | 结算后守护值小于等于 0 |
| 队伍覆灭 | 所有守卫者死亡 |
| Boss 反复溃败 | Boss 造成的保护目标伤害或公开代价使守护值归 0 |

失败结算必须显示：

- 失败原因。
- 到达章节和节点。
- 守护值变化。
- 守卫者死亡列表。
- 已获得遗物和升级。
- 完成奖励任务数量。

### 11.4 通关

完整第一版通关条件：

1. 第 3 章 Boss 战完成。
2. 结算后守护值仍大于 0。
3. 至少 1 名守卫者存活。

通关结算显示总摘要，不再进入奖励选择。

## 12. 存档点

为了避免奖励重复和状态回滚错误，Run 存档按阶段写入。

| 时机 | 保存内容 |
|---|---|
| 创建 Run 后 | 初始资源、守卫者、种子 |
| 生成章节路线后 | `route_graph`、章节配置 |
| 确认进入节点前 | `node_entry_snapshot`、当前节点 ID |
| 战斗或事件结束后 | 节点结果、损耗、待领取奖励 |
| 领取奖励后 | 余烬、遗物、升级、守护值、HP |
| 完成节点后 | `visited_nodes`、可选后续节点 |
| 章节 Boss 后 | 章节结算、下一章入口 |
| Run 结束后 | 失败或通关摘要 |

奖励发放必须使用 `pending_reward`：

1. 节点结束时先生成 `pending_reward` 并保存。
2. 玩家领取奖励时写入 Run 状态。
3. 领取成功后清空 `pending_reward`，再标记节点完成。

这样可以防止崩溃或重进导致重复领奖。

## 13. Demo 固定路线

第一轮 Demo 使用固定 1 章 6 节点路线：

```text
普通战：断墙前哨
  -> 事件：熄灭的灯塔
  -> 普通战：裂缝庭院
  -> 精英战：铁角闸门
  -> 营地：残火营地
  -> Boss：钟楼外环
```

### 13.1 节点配置

| 顺序 | 节点 | 类型 | 压力 | 裂隙强度 | 主要奖励 |
|---:|---|---|---|---:|---|
| 1 | 断墙前哨 | 普通战 | 基础防守、远程线压 | 0 | 7 余烬 + 奖励任务 |
| 2 | 熄灭的灯塔 | 事件 | 余烬 / 守护值 / 腐化取舍 | - | 修复或高余烬 |
| 3 | 裂缝庭院 | 普通战 | 基础防守、裂隙压力、远程线压 | 1 | 7 余烬 + 奖励任务 |
| 4 | 铁角闸门 | 精英战 | 精英冲撞、堵路拥挤、裂隙压力 | 1 | 11 余烬 + 遗物 |
| 5 | 残火营地 | 营地 | 治疗或修复 | - | 治疗小队或修复防线 |
| 6 | 钟楼外环 | Boss | Boss 脚本、裂隙压力 | 2 | 14 余烬 + 通关结算 |

### 13.2 Demo 目标数值

| 指标 | 目标 |
|---|---|
| 初始守护值 | 12 / 12 |
| 预计战前损失 | Boss 前普通玩家守护值剩余 5-8 |
| 预计营地选择 | 低 HP 队伍选治疗，低守护值选修复 |
| 预计通关收入 | 40-55 余烬 |
| 预计获得遗物 | 至少 1 个 |
| 预计获得升级 | 可选，不作为 Demo 必需 |
| 预计失败原因 | 守护值耗尽或 Boss 队伍覆灭 |

Demo 的目的不是一次性展示全部系统，而是验证路线损耗、奖励任务、遗物收益和营地取舍是否能形成完整闭环。

## 15. UI 交接要求

路线图页面必须固定显示：

- 当前章节和节点进度。
- 守护值。
- 余烬。
- 腐化。
- 守卫者头像、HP、死亡状态。
- 已获得遗物简表。
- 可选择节点和路线连接。
- 当前选中节点预览。
- 高风险、残编、高腐化和 Boss 警告。

结算页必须解释：

- 为什么胜利或失败。
- 守护值扣了多少，原因是什么。
- 哪些守卫者受伤、濒死或死亡。
- 奖励任务完成情况和失败原因。
- 获得了多少余烬、遗物、升级或章节奖励。

UI 不能把守护值、建筑 HP 和守卫者 HP 混成一个血条。三者必须有不同图标、位置和结算文案。
