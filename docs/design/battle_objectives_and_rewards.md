# 战斗胜负与奖励任务设计

> 日期：2026-06-03
> 状态：新版规则
> 依赖：[defense_roguelite_core_design.md](defense_roguelite_core_design.md)

## 1. 设计目标

战斗目标必须稳定、可读、可实现：

- 玩家永远知道主目标是撑到最大回合。
- 玩家永远知道建筑损失会扣多少守护值。
- 玩家永远知道守卫者 HP 是跨战斗资源，0 HP 即死亡。
- 清怪、封裂隙、击破部件只影响奖励和压力。
- 结算要鼓励高手追求更优解，但不强制普通玩家完美。

## 2. 三层生命资源

战斗和 Run 共用 3 层生命资源：

| 资源 | 层级 | 默认值 | 归零结果 |
|---|---|---:|---|
| 守护值 | Run 全局 | 7 / 7 | Run 失败 |
| 保护目标 HP | 单场棋盘 | 普通建筑 2，关键建筑 3 | 建筑被毁，结算时扣守护值 |
| 守卫者 HP | Run 角色 | 普通守卫者 2，防线型 3 | 守卫者死亡 |

这 3 层资源不能在 UI 和结算里混写。建筑损失消耗守护值；守卫者受伤消耗队伍战力；守护值和所有守卫者都耗尽时，都会导致 Run 失败。

## 3. 主胜负规则

### 3.1 战斗胜利检查

战斗只在 `max_rounds` 结束后进行胜利检查。

胜利条件：

1. 至少 1 名守卫者存活。
2. 如果本场有特殊毁灭计数，计数未达到失败阈值。

保护目标全毁不会直接判定 Run 失败，但会触发本场防线溃败并进入守护值结算。

### 3.2 即时失败和溃败

| 结果 | 条件 | 后果 |
|---|---|---|
| 队伍覆灭 | 所有出战守卫者死亡 | Run 立即失败 |
| 防线溃败 | 所有保护目标被毁 | 本场提前结束，守护值 -3；若守护值仍大于 0，Run 继续 |
| Boss 溃败 | Boss 毁灭计数满 | 本场提前结束，按 Boss 规则扣守护值；若守护值仍大于 0，Run 继续 |
| 特殊目标溃败 | 特殊剧情目标 HP 归零 | 本场提前结束，按关卡规则扣守护值 |

如果单个守卫者死亡，但仍有至少 1 名守卫者存活，战斗继续。死亡守卫者从棋盘移除，并从本 Run 的可出战名单中移除。

### 3.3 不提前胜利

以下行为不能触发胜利：

- 清空所有敌人。
- 阻止所有未来出怪。
- 封锁所有裂隙。
- 完成全部奖励任务。
- 摧毁 Boss 锚石、部件或弱点。

如果清场发生在中途，战斗继续推进空回合、Boss 回合或后续地裂预告。UI 可以显示“当前安全”，但不能显示胜利。

## 4. 保护目标

保护目标分 3 类：

| 类型 | HP | 守护值损失 | 说明 |
|---|---:|---|---|
| 普通建筑 | 2 | 被毁 -1 | 标准保护对象 |
| 关键建筑 | 3 | 被毁 -2，或触发特殊溃败 | 精英和 Boss 战少量使用 |
| 临时目标 | 1-2 | 根据节点规则 | 事件战、护送战、防线战使用 |

普通战默认使用普通建筑，不建议一开始就放“单个被毁即溃败”的关键建筑。关键建筑适合精英战和 Boss 战。

普通建筑 HP=2 的目的：

- 第 1 次受击给玩家救援窗口。
- 第 2 次受击才毁灭并扣守护值。
- 玩家可以选择牺牲次要建筑，保护更关键的位置和守卫者。

## 5. 守护值扣减和恢复

守护值是 Run 级弹性失败资源，默认上限和初始值为 7。守护值只在战斗结算、事件结算、营地或商店中变化，战斗内不随机波动。

### 5.1 扣减规则

| 事件 | 守护值变化 | 说明 |
|---|---:|
| 胜利，0 保护目标被毁 | 0 |
| 胜利，1 个保护目标被毁 | -1 |
| 胜利，2 个保护目标被毁 | -2 |
| 胜利，3 个及以上保护目标被毁 | -3，单场损失上限 |
| 防线溃败 | -3，不再叠加建筑逐个扣减 |
| Boss 溃败 | -3，Boss 特殊规则可提高到 -4，但必须战前公开 |
| 事件代价 | -1 到 -2 | 进入下一战前公开 |

守护值降到 0 时 Run 失败。若战斗胜利但守护值归 0，结算后失败，不回滚战斗。

### 5.2 恢复规则

| 来源 | 守护值变化 | 约束 |
|---|---:|---|
| 营地：修复防线 | +2 | 不超过上限 |
| 商店：修复防线 | +1 | 价格基准 6 余烬 |
| 高难奖励任务 | +1 | 每章最多 1 次 |
| 遗物 | 预防或降低损失 | 不能永久免疫建筑伤害 |

守护值恢复要稀缺。玩家通常每章只能修回 2-3 点，不能把建筑损失当成无成本资源。

## 6. 守卫者 HP、濒死和死亡

守卫者 HP 是跨战斗资源，战斗结束后不自动回满。

### 6.1 状态定义

| HP 状态 | 战斗状态 | 规则 |
|---:|---|---|
| 2+ | 正常 | 可移动、可行动、可被锁定 |
| 1 | 濒死 | 可移动、可行动、可被锁定；再受 1 点伤害会死亡 |
| 0 | 死亡 | 从棋盘移除，本 Run 不可再出战 |

濒死没有随机死亡判定。敌人也没有隐藏补刀 AI，只会按公开意图攻击。

### 6.2 伤害裁定

| 来源 | 伤害 | 说明 |
|---|---:|---|
| 普通近战攻击 | 1 | 标准威胁 |
| 普通远程攻击 | 1 | 可用挡线、位移或击杀化解 |
| 撞墙、撞建筑、撞单位 | 1 | 按物理结算真值表执行 |
| 地裂占据代价 | 1 | 占住地裂时公开提示 |
| 精英重击 | 2 | 必须有强预警和清楚范围 |
| 坠渊 / 出界 | 直接死亡 | 只在明确深渊地图中使用 |

如果一次伤害使守卫者 HP 降到 0 或以下，结算链结束后移除该守卫者。结算链结束前仍按现有物理规则占格，避免推撞链断裂。

### 6.3 跨战斗保留

| 情况 | 战后结果 |
|---|---|
| 守卫者以 2 HP 结束 | 下一战仍为 2 HP |
| 守卫者以 1 HP 结束 | 下一战仍为 1 HP，保持濒死 |
| 守卫者死亡 | 从 Run 名单移除 |
| 全队死亡 | Run 失败 |

标准战斗以 3 名守卫者为完整编制。若 Run 中仍有 1-2 名守卫者存活，可以残编继续，但关卡不会自动降难；招募、事件或后续系统可以提供补员。

### 6.4 治疗规则

| 来源 | 效果 | 约束 |
|---|---|---|
| 战斗结束 | 不自动恢复 HP | 保持跨战斗损耗 |
| 营地：治疗小队 | 所有存活守卫者 +1 HP | 不超过各自最大 HP |
| 商店：急救 | 1 名存活守卫者 +1 HP | 价格基准 4 余烬 |
| 事件奖励 | 1 名或全队 +1 HP | 必须在选择前公开 |
| 遗物 | 预防濒死、提供护盾或降低治疗价格 | 不提供无代价复活 |

第一版不做复活。死亡如果可以被购买回来，会削弱守卫者 HP 作为全局生命线的意义。

## 7. 奖励任务结构

每场战斗从任务池中抽取 3 个奖励任务。Boss 战使用专属任务池。

奖励任务有 4 条规则：

1. 任务必须在战斗开始时公开。
2. 任务进度必须在 HUD 中可见。
3. 任务失败原因必须可回放或在结算中解释。
4. 任务不改变主胜负。

## 8. 通用奖励任务池

| 任务 | 条件 | 设计目的 |
|---|---|---|
| 完美防守 | 0 个保护目标被毁 | 高水平防守 |
| 低损防线 | 保护目标总受伤 ≤2 | 允许轻微失误 |
| 终局清场 | `max_rounds` 结束时场上无敌人 | 把清怪转为奖励 |
| 物理处决 | 撞击、坠渊、地形击杀累计 3 个敌人 | 鼓励核心物理 |
| 连锁大师 | 单次行动触发 2 次以上碰撞 | 鼓励高阶推演 |
| 裂隙压制 | 占住或延迟地裂出怪 2 次 | 把封印转为奖励 |
| 指定目标无伤 | 指定建筑不受伤 | 制造局部保护重点 |
| 守卫者全员存活 | 3 名守卫者都存活 | 控制伤亡 |
| 无坠落事故 | 守卫者无人坠渊 | 深渊地图专用 |
| 精英猎杀 | 终局前击杀指定精英敌人 | 主动进攻压力 |
| 推离威胁 | 打断 4 次敌方攻击意图 | 强化公开意图价值 |
| 节省行动 | 至少 1 回合结束时保留 1 名守卫者未攻击 | 给高手优化空间 |

## 9. Boss 奖励任务池

| 任务 | 条件 | 说明 |
|---|---|---|
| 钟鸣压制 | Boss 毁灭计数从未增长 | 高难防守 |
| 锚石破坏 | 摧毁全部锚石至少 1 次 | 进攻目标 |
| 暴露窗口 | 在 Boss 暴露期间造成 3 次伤害 | 集火目标 |
| 不入二相 | Boss 未进入第二次强化循环 | 节奏优化 |
| 完美守夜 | Boss 战无建筑被毁 | 高难挑战 |
| 全员存活 | Boss 战 3 名守卫者全活 | 生存挑战 |

Boss 部件不再直接决定胜利。击破部件可以削弱 Boss、降低毁灭计数、完成奖励任务或提高结算奖励。

## 10. 奖励梯度

基础奖励来自节点，额外奖励来自任务完成数量。

| 完成任务数 | 普通战额外奖励 | 精英战额外奖励 |
|---:|---|---|
| 0 | 无 | 无 |
| 1 | +2 余烬 | +3 余烬 |
| 2 | +4 余烬，奖励选项 +1 | +5 余烬，奖励选项 +1 |
| 3 | +6 余烬，奖励选项 +1，章节内守护值 +1 机会 | +8 余烬，稀有遗物权重提高 |

每章通过奖励任务恢复守护值最多 1 次，避免高手滚雪球过强。

## 11. HUD 展示

战斗 HUD 固定展示：

- 守护值：`6 / 7`
- 当前回合：`Round N / max_rounds`
- 主目标：`撑到第 max_rounds 回合结束`
- 本场预计守护值损失：`预计 -1`
- 保护目标：`2 / 4`，并显示每个目标 HP
- 守卫者：每名守卫者当前 HP、濒死、死亡和行动状态
- 奖励任务清单：3 项，显示进度和失败状态

任务完成时只做短高亮，不弹窗。任务失败时灰掉并标注原因，例如“指定建筑已受伤”。

结算页必须分开列出守护值和守卫者 HP：

```text
钟楼被毁：守护值 -1
大魔法师濒死：下一战 1 / 2 HP
完成 2 项奖励任务：+4 余烬
当前守护值：6 / 7
```

## 12. 实现裁定

当前代码中“敌人全灭且无未来出怪即胜利”的逻辑需要废弃。

推荐状态字段：

```text
max_rounds: int
protected_targets: Array
reward_tasks: Array
destroyed_protected_count: int
sanctuary_integrity: int
sanctuary_integrity_max: int
special_doom_count: int
```

胜负检查顺序：

```text
1. 检查即时失败
2. 如果 current_round <= max_rounds，保持战斗
3. 如果已完成 max_rounds，检查终局胜利
4. 结算奖励任务、守护值和守卫者 HP
```
