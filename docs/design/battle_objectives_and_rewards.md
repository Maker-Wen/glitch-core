# 战斗胜负与奖励任务设计

> 日期：2026-06-03
> 状态：新版规则
> 依赖：[defense_roguelite_core_design.md](defense_roguelite_core_design.md)

## 1. 设计目标

战斗目标必须稳定、可读、可实现：

- 玩家永远知道主目标是撑到最大回合。
- 玩家永远知道哪些保护目标不能全部毁。
- 清怪、封裂隙、击破部件只影响奖励和压力。
- 结算要鼓励高手追求更优解，但不强制普通玩家完美。

## 2. 主胜负规则

### 2.1 胜利检查

战斗只在 `max_rounds` 结束后进行胜利检查。

胜利条件：

1. 至少 1 名守卫者存活。
2. 如果本场有保护目标，至少 1 个保护目标存活。
3. 如果本场有特殊毁灭计数，计数未达到失败阈值。

### 2.2 失败检查

失败可以即时发生：

| 失败条件 | 触发时机 |
|---|---|
| 守卫者全灭 | 任意结算链结束后 |
| 保护目标全毁 | 任意建筑或关键目标毁灭后 |
| Boss 毁灭计数满 | Boss 行动结算后 |
| 特殊剧情目标毁灭 | 目标 HP 归零后 |

### 2.3 不提前胜利

以下行为不能触发胜利：

- 清空所有敌人。
- 阻止所有未来出怪。
- 封锁所有裂隙。
- 完成全部奖励任务。
- 摧毁 Boss 锚石、部件或弱点。

如果清场发生在中途，战斗继续推进空回合、Boss 回合或后续地裂预告。UI 可以显示“当前安全”，但不能显示胜利。

## 3. 保护目标

保护目标分 3 类：

| 类型 | HP | 失败关系 | 说明 |
|---|---:|---|---|
| 普通建筑 | 2 | 全毁则失败 | 标准保护对象 |
| 关键建筑 | 3 | 可配置为单个被毁即失败 | 精英和 Boss 战少量使用 |
| 临时目标 | 1-2 | 根据节点规则 | 事件战、护送战、防线战使用 |

普通战默认使用普通建筑，不建议一开始就放“单个被毁即失败”的关键建筑。关键建筑适合精英战和 Boss 战。

## 4. 守护值结算

守护值是 Run 级弹性失败资源，起始建议为 7。

| 战斗结果 | 守护值变化 |
|---|---:|
| 胜利，0 保护目标被毁 | 0 |
| 胜利，1 个保护目标被毁 | -1 |
| 胜利，2 个保护目标被毁 | -2 |
| 胜利，3 个及以上保护目标被毁 | -3 |
| 战斗失败 | -3，并进入伤势结算 |
| 完成指定高难奖励任务 | 可 +1，每章最多 1 次 |

守护值降到 0 时 Run 失败。若战斗胜利但守护值归 0，结算后失败，不回滚战斗。

## 5. 奖励任务结构

每场战斗从任务池中抽取 3 个奖励任务。Boss 战使用专属任务池。

奖励任务有 4 条规则：

1. 任务必须在战斗开始时公开。
2. 任务进度必须在 HUD 中可见。
3. 任务失败原因必须可回放或在结算中解释。
4. 任务不改变主胜负。

## 6. 通用奖励任务池

| 任务 | 条件 | 设计目的 |
|---|---|---|
| 完美防守 | 0 个保护目标被毁 | 高水平防守 |
| 低损防线 | 保护目标总受伤 ≤2 | 允许轻微失误 |
| 终局清场 | `max_rounds` 结束时场上无敌人 | 把清怪转为奖励 |
| 物理处决 | 撞击、坠渊、地形击杀累计 3 个敌人 | 鼓励核心物理 |
| 连锁大师 | 单次行动触发 2 次以上碰撞 | 鼓励高阶推演 |
| 裂隙压制 | 占住或延迟地裂出怪 2 次 | 把封印转为奖励 |
| 指定目标无伤 | 指定建筑不受伤 | 制造局部保护重点 |
| 守卫者全员存活 | 3 名守卫者都存活 | 控制伤亡 |
| 无坠落事故 | 守卫者无人坠渊 | 深渊地图专用 |
| 精英猎杀 | 终局前击杀指定精英敌人 | 主动进攻压力 |
| 推离威胁 | 打断 4 次敌方攻击意图 | 强化公开意图价值 |
| 节省行动 | 至少 1 回合结束时保留 1 名守卫者未攻击 | 给高手优化空间 |

## 7. Boss 奖励任务池

| 任务 | 条件 | 说明 |
|---|---|---|
| 钟鸣压制 | Boss 毁灭计数从未增长 | 高难防守 |
| 锚石破坏 | 摧毁全部锚石至少 1 次 | 进攻目标 |
| 暴露窗口 | 在 Boss 暴露期间造成 3 次伤害 | 集火目标 |
| 不入二相 | Boss 未进入第二次强化循环 | 节奏优化 |
| 完美守夜 | Boss 战无建筑被毁 | 高难挑战 |
| 全员归队 | Boss 战 3 名守卫者全活 | 生存挑战 |

Boss 部件不再直接决定胜利。击破部件可以削弱 Boss、降低毁灭计数、完成奖励任务或提高结算奖励。

## 8. 奖励梯度

基础奖励来自节点，额外奖励来自任务完成数量。

| 完成任务数 | 普通战额外奖励 | 精英战额外奖励 |
|---:|---|---|
| 0 | 无 | 无 |
| 1 | +2 余烬 | +3 余烬 |
| 2 | +4 余烬，奖励选项 +1 | +5 余烬，奖励选项 +1 |
| 3 | +6 余烬，奖励选项 +1，章节内守护值 +1 机会 | +8 余烬，稀有遗物权重提高 |

每章通过奖励任务恢复守护值最多 1 次，避免高手滚雪球过强。

## 9. HUD 展示

战斗 HUD 固定展示：

- 当前回合：`Round N / max_rounds`
- 主目标：`撑到第 max_rounds 回合结束`
- 存活保护目标：`2 / 4`
- 守卫者存活：`3 / 3`
- 奖励任务清单：3 项，显示进度和失败状态

任务完成时只做短高亮，不弹窗。任务失败时灰掉并标注原因，例如“指定建筑已受伤”。

## 10. 实现裁定

当前代码中“敌人全灭且无未来出怪即胜利”的逻辑需要废弃。

推荐状态字段：

```text
max_rounds: int
protected_targets: Array
reward_tasks: Array
destroyed_protected_count: int
special_doom_count: int
```

胜负检查顺序：

```text
1. 检查即时失败
2. 如果 current_round <= max_rounds，保持战斗
3. 如果已完成 max_rounds，检查终局胜利
4. 结算奖励任务和守护值
```
