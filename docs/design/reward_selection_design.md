# 战后结算与奖励选择设计

> 日期：2026-06-04  
> 状态：第一版执行规格  
> 依赖：[battle_objectives_and_rewards.md](battle_objectives_and_rewards.md)、[run_structure_design.md](run_structure_design.md)、[run_relic_economy_design.md](run_relic_economy_design.md)、[warden_roster_and_upgrades.md](warden_roster_and_upgrades.md)

## 1. 目的

本文档补齐战后结算和奖励选择的完整设计，作为后续实现、UI 设计和配置表拆分的交接依据。

本文档回答以下问题：

1. 战斗结束后如何解释胜负、损耗和奖励任务。
2. 普通战、精英战、Boss 战和事件如何生成统一的 `pending_reward`。
3. 奖励选择页如何处理余烬、遗物、升级、章节奖励、守护值恢复、选项 +1 和重抽。
4. 奖励如何写回 Run 状态，如何避免重复领取。
5. Demo 和完整第一版分别需要做到什么粒度。

战斗胜负、守护值扣减、守卫者 HP 和死亡以 [battle_objectives_and_rewards.md](battle_objectives_and_rewards.md) 为准。Run 路线和存档阶段以 [run_structure_design.md](run_structure_design.md) 为准。遗物价格和经济基准以 [run_relic_economy_design.md](run_relic_economy_design.md) 为准。

## 2. 核心裁定

- 战后必须先进入结算页，再进入奖励选择页。结算页负责解释结果，奖励页负责做选择。
- 奖励发放必须经过 `pending_reward`，不能直接在战斗结束瞬间写入全部奖励。
- 固定余烬可以在结算页展示，但在玩家确认领取时才写入 Run 状态。
- 遗物、升级、章节奖励和守护值恢复机会都属于奖励选项，必须可预览、可确认、不可撤销。
- 奖励任务只改变奖励，不改变战斗主胜负。
- 死亡守卫者不能获得升级、治疗或章节整备收益。
- 每名守卫者每章最多获得 1 次升级。
- 每章通过奖励任务恢复守护值最多 1 次。
- 重抽只刷新当前奖励页的可选项，不重新结算战斗，也不改变已完成奖励任务数量。
- Boss 溃败、队伍覆灭或守护值归 0 时不发放战斗奖励，直接进入失败或重试流程。

## 3. 页面职责

### 3.1 战后结算页

战后结算页回答“刚才发生了什么”。

必须显示：

| 区域 | 内容 |
|---|---|
| 战斗结果 | 胜利、防线溃败、Boss 溃败、队伍覆灭 |
| 主目标 | 是否撑到最大回合，是否有守卫者存活 |
| 守护值 | 战前值、扣减原因、战后值 |
| 保护目标 | 被毁数量、受伤数量、关键目标状态 |
| 守卫者 | 每名守卫者 HP 变化、濒死、死亡 |
| 奖励任务 | 完成、失败、失败原因、对应奖励 |
| 遗物触发 | 影响奖励或损耗的遗物触发记录 |
| 下一步 | 领取奖励、Boss 重试、Run 失败或返回路线 |

结算页不做多选奖励。玩家确认后进入奖励选择页或路线图。

### 3.2 奖励选择页

奖励选择页回答“现在拿什么”。

必须显示：

| 区域 | 内容 |
|---|---|
| 固定奖励 | 基础余烬、奖励任务余烬、击杀余烬上限 |
| 可选奖励 | 遗物、升级、章节奖励、守护值恢复机会 |
| 当前资源 | 守护值、余烬、腐化、守卫者 HP |
| 已有构筑 | 已有遗物、守卫者已学升级 |
| 选择影响 | 选择后资源变化、适用对象、限制原因 |
| 操作 | 选择、确认、重抽、跳过 |

奖励选择页不再解释复杂战斗过程，只保留关键结果摘要和选择依据。

### 3.3 章节奖励页

章节奖励页是 Boss 胜利后的特殊奖励选择页。第 1 章和第 2 章使用；第 3 章 Boss 胜利后进入通关结算。

章节奖励页可以复用奖励选择页组件，但奖励池不同：

- 稀有遗物或章节遗物。
- 守卫者升级。
- 战线整备。
- 特殊章节修正。

## 4. 战后流程

```text
战斗结束
  -> 计算战斗结果
  -> 计算守护值和守卫者 HP 变化
  -> 计算奖励任务结果
  -> 生成 pending_reward
  -> 保存 node_resolution
  -> 显示战后结算页
  -> 玩家确认
  -> 如果 Run 失败：进入失败结算
  -> 如果无可选奖励：领取固定奖励并回路线图
  -> 如果有可选奖励：进入奖励选择页
  -> 玩家选择并确认
  -> 写回 Run 状态
  -> 清空 pending_reward
  -> 标记节点完成
  -> 回路线图、章节结算或通关结算
```

### 4.1 不发奖情况

| 情况 | 处理 |
|---|---|
| 队伍覆灭 | 直接进入 Run 失败，不发放奖励 |
| 守护值归 0 | 进入 Run 失败，不发放未领取奖励 |
| Boss 溃败且守护值大于 0 | 不发奖励，回到同一 Boss 节点预览 |
| 事件选择为无收益 | 不生成奖励页，直接写回事件结果 |

如果战斗胜利但结算后守护值归 0，视为 Run 失败，不领取奖励。

### 4.2 只发固定奖励情况

| 情况 | 处理 |
|---|---|
| 普通战胜利且无可选奖励 | 结算页确认后直接领取余烬并回路线图 |
| 事件获得固定余烬 | 事件确认后直接写回余烬 |
| 奖励任务只给余烬 | 结算页确认后直接领取 |

第一轮 Demo 可以允许“固定余烬也进入奖励页”，这样 UI 更统一；完整第一版建议省掉无意义确认。

## 5. 奖励来源

### 5.1 战斗基础奖励

| 节点 | 基础奖励 | 是否可选 |
|---|---:|---|
| 普通战 | 7 余烬 | 否 |
| 精英战 | 11 余烬 + 遗物奖励 | 遗物可选 |
| Boss 战 | 14 余烬 + 章节奖励 | 章节奖励可选 |

普通战如果配置击杀余烬，整场最多 +3。Boss 召唤的杂兵不给击杀余烬。

### 5.2 奖励任务收益

| 完成任务数 | 普通战 | 精英战 | Boss 战 |
|---:|---|---|---|
| 0 | 无 | 无 | 无 |
| 1 | +2 余烬 | +3 余烬 | +3 余烬 |
| 2 | +4 余烬，奖励选项 +1 | +5 余烬，奖励选项 +1 | +5 余烬，章节奖励选项 +1 |
| 3 | +6 余烬，奖励选项 +1，守护值 +1 机会 | +8 余烬，稀有遗物权重提高 | +8 余烬，章节奖励选项 +1，稀有权重提高 |

守护值 +1 机会有 3 条限制：

1. 每章最多触发 1 次。
2. 守护值已满时不生成该选项，改为 +3 余烬。
3. Boss 战第 3 章不生成可用于继续 Run 的守护值恢复机会。

### 5.3 遗物触发奖励

遗物可以修改奖励，但必须写入 `pending_reward.modifiers`，并在结算页显示来源。

| 遗物效果类型 | 示例 | 处理 |
|---|---|---|
| 额外选项 | 腐化冠冕：遗物选项 +1 | 增加对应奖励池展示数量 |
| 稀有权重 | 完成 3 任务后提高稀有权重 | 修改生成权重 |
| 额外余烬 | 处决钩：坠渊击杀 +1 余烬 | 写入固定奖励明细 |
| 守护值恢复 | 守夜誓约：每章第一次完成 3 任务守护值 +1 | 受每章上限限制 |
| 降低价格 | 圣灰灯：营地恢复守护值价格降低 | 不在战后奖励页处理 |

遗物不能在结算后随机追加未知奖励。所有奖励修正都必须可回放。

### 5.4 事件奖励

事件奖励分两类：

| 类型 | 处理 |
|---|---|
| 固定事件结果 | 立即写回 Run 状态，例如 +10 余烬、腐化 +1 |
| 选择型奖励 | 生成 `pending_reward`，进入奖励选择页，例如普通遗物 2 选 1、升级 2 选 1 |

事件选择前必须展示完整收益和代价。事件选择后不能因为隐藏随机结果改变奖励类型。

## 6. `pending_reward` 数据结构

`pending_reward` 是奖励发放的唯一入口。节点结束时生成，玩家领取后清空。

```text
pending_reward:
  reward_id: string
  source_node_id: string
  source_type: battle | event | shrine | chapter | start
  reward_phase: fixed | choice | chapter_choice
  generated_seed: int
  fixed_rewards: array
  choice_groups: array
  modifiers: array
  reroll:
    allowed: bool
    cost_embers: int
    used_count: int
    max_count: int
  claim_state:
    generated: bool
    fixed_claimed: bool
    choice_claimed: bool
    selected_option_ids: array
```

### 6.1 `fixed_rewards`

| 字段 | 说明 |
|---|---|
| `reward_type` | `embers`、`sanctuary_integrity`、`corruption`、`warden_hp`、`flag` |
| `amount` | 数值变化 |
| `target_id` | 目标 ID，可为空 |
| `reason` | 来源说明 |
| `visible_order` | UI 排序 |

固定奖励示例：

```text
fixed_rewards:
  - reward_type: embers
    amount: 7
    reason: 普通战基础奖励
  - reward_type: embers
    amount: 4
    reason: 完成 2 个奖励任务
```

### 6.2 `choice_groups`

奖励页可以同时存在多个选择组，但第一版应尽量每次只要求玩家做 1 个关键选择。

```text
choice_group:
  group_id: string
  group_type: relic | upgrade | chapter_reward | recovery | mixed
  choose_count: int
  display_count: int
  options: array
  can_skip: bool
  skip_reward: fixed_reward | null
```

| 字段 | 说明 |
|---|---|
| `group_type` | 决定卡片模板和过滤规则 |
| `choose_count` | 通常为 1 |
| `display_count` | 基础 2 或 3，受奖励选项 +1 影响 |
| `can_skip` | 是否可跳过 |
| `skip_reward` | 跳过时补偿，通常是 +3 余烬 |

### 6.3 `reward_option`

| 字段 | 说明 |
|---|---|
| `option_id` | 选项唯一 ID |
| `option_type` | 遗物、升级、恢复、章节奖励、余烬 |
| `rarity` | 普通、稀有、诅咒、章节 |
| `target_type` | 全局、守卫者、守护值、下一战 |
| `target_id` | 目标守卫者或资源 ID |
| `title` | 显示名称 |
| `description` | 规则说明 |
| `preview_delta` | 选择后的资源变化 |
| `tags` | 位移、防守、裂隙、风险、任务等 |
| `synergy_notes` | 与当前遗物、升级或奖励任务的协同提示 |
| `disabled_reason` | 不可选原因 |

不可选的选项原则上不应生成。只有在 UI 需要解释限制时，才显示灰态。例如所有守卫者本章都已升级时，升级组选项不生成，改为遗物或余烬补偿。

## 7. 奖励池和权重

### 7.1 遗物奖励池

遗物按稀有度、类型和当前构筑过滤。

| 来源 | 基础展示 | 稀有权重 | 备注 |
|---|---:|---|---|
| 精英战 | 3 选 1 | 普通 70%，稀有 30% | 完成 3 任务后稀有权重提高 |
| Boss 战章节奖励 | 3 选 1 | 普通 30%，稀有 70% | 第 1-2 章使用 |
| 神龛 | 2 选 1 | 稀有 70%，诅咒 30% | 腐化代价已公开 |
| 起始遗物 | 3 选 1 | 普通 100% | Demo 不启用 |
| 事件 | 2 选 1 | 由事件配置决定 | 可带腐化或 HP 代价 |

过滤规则：

- 已拥有的唯一遗物不再出现。
- 会让核心压力永久失效的遗物不进入池。
- 诅咒遗物不在普通精英战池出现。
- 如果当前腐化 7 以上，神龛仍可给诅咒遗物，但必须显示高腐化警告。

### 7.2 升级奖励池

升级奖励按守卫者、章节限制和已学升级过滤。

| 来源 | 展示 | 规则 |
|---|---:|---|
| 普通战成长奖励 | 2 选 1 或 3 选 1 | 每 2 场普通战后出现 1 次 |
| 精英战混合奖励 | 与遗物二选一，或升级 2 选 1 | 第一版可后置 |
| Boss 章节奖励 | 选择 1 名存活守卫者，再升级 2 选 1 | 第 1-2 章使用 |
| 工坊 | 指定守卫者升级 2 选 1 | 花费余烬 |
| 事件 | 由事件配置决定 | 可带 HP 或腐化代价 |

过滤规则：

- 死亡守卫者不进入目标列表。
- 本章已获得升级的守卫者不进入目标列表。
- 已学升级不再出现。
- 如果没有合法升级，奖励组改为遗物或 +8 余烬。

### 7.3 守护值恢复奖励

守护值恢复奖励来自完成 3 个奖励任务、章节奖励或少数事件。

| 来源 | 效果 | 限制 |
|---|---:|---|
| 普通战 3 任务 | 守护值 +1 机会 | 每章最多 1 次 |
| 守夜誓约 | 守护值 +1 | 与每章上限共享 |
| 章节奖励：战线整备 | 守护值 +1 | 不计入奖励任务恢复上限 |
| 事件 | 按事件配置 | 可能有余烬或腐化代价 |

如果守护值已满，恢复奖励自动转化为 +3 余烬，结算页显示“守护值已满，转化为余烬”。

### 7.4 混合奖励池

混合奖励用于章节奖励或高风险路线。

基础规则：

- 每组最多展示 4 个选项。
- 同一组中不要同时出现 3 个同类纯收益选项。
- 至少 1 个选项应该能解决当前损耗，例如治疗、修复或防守遗物。
- 高腐化奖励必须显示腐化变化。

示例：

| 选项 | 效果 |
|---|---|
| 稀有遗物 | 获得 1 个稀有遗物 |
| 守卫者升级 | 选择 1 名存活守卫者获得升级 |
| 战线整备 | 守护值 +1，治疗 1 名存活守卫者 +1 HP |
| 风险收益 | 腐化 +1，获得普通遗物和 +6 余烬 |

## 8. 选项数量和重抽

### 8.1 选项数量

| 奖励来源 | 基础选项 | 奖励任务 +1 后 | 上限 |
|---|---:|---:|---:|
| 普通遗物奖励 | 3 | 4 | 4 |
| 升级奖励 | 2 | 3 | 3 |
| 章节奖励 | 3 | 4 | 4 |
| 事件奖励 | 2 | 3 | 3 |
| 神龛奖励 | 2 | 3 | 3 |

如果池内合法选项不足，显示实际数量，不补重复选项。

### 8.2 重抽规则

| 项 | 规则 |
|---|---|
| 基准价格 | 3 余烬 |
| 默认次数 | 每个奖励页最多 1 次 |
| 作用范围 | 只刷新当前 `choice_group` |
| 不变内容 | 固定奖励、完成任务数、奖励来源、选项数量 |
| 禁止情况 | 余烬不足、已选择确认、事件配置禁止重抽 |

重抽必须消耗当前 Run 余烬。若固定余烬尚未领取，不能用“即将获得的余烬”支付重抽，避免支付顺序混乱。

Demo 可以不做重抽按钮。完整第一版建议做，因为它能提高构筑可控性，并回收少量经济。

### 8.3 跳过规则

| 奖励类型 | 是否可跳过 | 补偿 |
|---|---|---|
| 遗物 | 可以 | +3 余烬 |
| 升级 | 可以 | +5 余烬 |
| 章节奖励 | 不建议 | 如果必须跳过，+8 余烬 |
| 守护值恢复机会 | 可以 | +3 余烬 |
| 事件代价奖励 | 按事件配置 | 通常不补偿 |

跳过用于避免“当前构筑完全不想要这个奖励”的死选项，但补偿不能高到比正常奖励更优。

## 9. 奖励选择交互

### 9.1 基础流程

```text
进入奖励页
  -> 展示固定奖励和可选奖励
  -> 玩家查看卡片详情
  -> 可选：重抽
  -> 玩家选择 1 个选项
  -> 右侧或底部显示选择后变化
  -> 玩家确认
  -> 写回 Run 状态
  -> 显示短反馈
  -> 返回路线或章节结算
```

确认后不可撤销。若要支持撤销，只能在确认前撤回选择。

### 9.2 遗物卡信息

遗物卡必须显示：

- 名称。
- 稀有度。
- 类型标签：位移、防守、裂隙、风险、任务。
- 规则效果。
- 触发时机。
- 是否与当前守卫者或已有遗物有协同。
- 是否有代价，例如腐化 +2。

遗物描述必须避免模糊词。例如不用“有概率”“大幅”“少量”，而使用“每场第一次”“+1”“本章一次”等确定表达。

### 9.3 升级卡信息

升级卡必须显示：

- 适用守卫者。
- 升级类别：动词增强、防守增强、任务增强。
- 当前技能简述。
- 升级后改变的格数、范围、推拉力、时序或任务收益。
- 当前守卫者 HP 和本章是否已升级。
- 与当前遗物的协同提示。

如果升级需要先选择守卫者，推荐交互为：

```text
选择守卫者
  -> 显示该守卫者合法升级 2-3 个
  -> 选择升级
  -> 确认
```

Demo 可以简化为直接展示 3 张“守卫者 + 升级”卡。

### 9.4 章节奖励卡信息

章节奖励卡必须显示：

- 奖励类别。
- 立即变化。
- 对下一章的影响。
- 是否消耗本章奖励任务恢复上限。
- 是否有目标限制。

例如：

```text
战线整备
守护值 +1，治疗 1 名存活守卫者 +1 HP。
不计入本章奖励任务恢复上限。
```

## 10. 奖励写回规则

### 10.1 写回顺序

领取奖励时按固定顺序写回：

1. 校验 `pending_reward` 仍存在，且未领取。
2. 校验选项合法：目标存活、未重复、资源足够、限制未被占用。
3. 写入固定奖励。
4. 写入玩家选择的奖励。
5. 扣除重抽或事件成本。
6. 更新章节限制标记。
7. 清空 `pending_reward`。
8. 标记节点完成。
9. 保存 Run。

如果任一步失败，不能部分写入。实现上应把奖励领取视为一个事务。

### 10.2 资源写回

| 奖励 | 写回 |
|---|---|
| 余烬 | `embers += amount` |
| 守护值 | `sanctuary_integrity = min(max, current + amount)` |
| 腐化 | `corruption += amount` |
| 遗物 | `relics.append(relic_id)` |
| 升级 | 对应守卫者 `upgrades.append(upgrade_id)` |
| 守卫者治疗 | 存活守卫者 HP 增加，不超过上限 |
| 下一战修正 | 写入 `next_node_modifiers` 或节点临时标记 |

### 10.3 限制标记

| 标记 | 触发 |
|---|---|
| `chapter_guardian_reward_used` | 通过奖励任务或守夜誓约恢复守护值 |
| `warden_upgrade_chapter_index` | 守卫者本章获得升级 |
| `reward_claimed_node_ids` | 节点奖励已领取 |
| `seen_relic_ids` | 见过的遗物，用于图鉴或权重 |

章节奖励“战线整备”不计入 `chapter_guardian_reward_used`，因为它是 Boss 后章节奖励，不是奖励任务恢复。

## 11. 特殊情况

### 11.1 奖励池为空

| 情况 | 处理 |
|---|---|
| 遗物池为空 | 改为 +10 余烬 |
| 升级池为空 | 改为 +8 余烬 |
| 守护值已满 | 改为 +3 余烬 |
| 无存活守卫者 | 不应进入奖励页；Run 已失败 |

### 11.2 残编奖励

残编不改变奖励数值，不自动给补偿。奖励页只做清楚提示：

- 当前仅剩 1-2 名守卫者。
- 升级和治疗只能作用于存活守卫者。
- 死亡守卫者不会出现在选择目标中。

后续如果设计补员系统，应单独写文档，不塞进战后奖励。

### 11.3 腐化奖励

带腐化代价的奖励必须在卡面上显示：

```text
腐化 +2
当前 4 -> 6
影响：精英战硬威胁上限 +1，但仍不超过 3
```

如果选择后腐化跨过 3、5、7 阈值，必须显示阈值效果。

### 11.4 死亡与治疗

死亡守卫者不可被治疗、不可获得升级、不可作为章节整备目标。

治疗选项只显示存活且未满 HP 的守卫者。如果全员满 HP，治疗选项不生成。

### 11.5 选项 +1 与显示上限

奖励任务完成 2 个或特定遗物可以让奖励选项 +1。该效果只增加展示数量，不增加可选择数量。

例如：

```text
精英战遗物奖励：3 选 1
完成 2 个奖励任务：展示 4 个，仍然选择 1 个
```

## 12. UI 状态要求

### 12.1 战后结算页布局

推荐信息层级：

1. 顶部：结果标题和主目标状态。
2. 左侧：守护值和保护目标损耗。
3. 中部：守卫者 HP、濒死、死亡。
4. 右侧：奖励任务完成列表。
5. 底部：奖励摘要和下一步按钮。

结算页必须避免把“建筑被毁”“守护值扣减”“守卫者死亡”写成同一种生命损失。

### 12.2 奖励选择页布局

推荐信息层级：

1. 顶部：奖励来源和固定奖励摘要。
2. 左侧或上方：当前 Run 资源。
3. 中部：奖励卡片。
4. 右侧：已选奖励预览和构筑协同。
5. 底部：重抽、跳过、确认。

奖励卡片要稳定尺寸。长描述应换行或使用详情展开，不能撑坏卡片布局。

### 12.3 必要提示

| 情况 | 提示 |
|---|---|
| 守护值 +1 已达上限 | “守护值已满，转化为 +3 余烬” |
| 每章恢复上限已用 | “本章奖励任务修复已使用” |
| 守卫者本章已升级 | “本章已升级，不能再次选择” |
| 腐化跨阈值 | “腐化达到 5：精英战硬威胁上限 +1” |
| 余烬不足重抽 | “余烬不足，无法重抽” |
| 死亡守卫者 | “已死亡，本 Run 离队” |

## 16. 验收用例

| 用例 | 预期 |
|---|---|
| 普通战完成 0 任务 | 获得 7 余烬，无奖励选择 |
| 普通战完成 2 任务 | 获得 11 余烬，如果有选择奖励则选项 +1 |
| 普通战完成 3 任务且守护值未满 | 获得 13 余烬，并出现守护值 +1 机会 |
| 普通战完成 3 任务且本章恢复已用 | 守护值机会不出现，按规则转补偿 |
| 精英战完成 2 任务 | 获得 16 余烬，遗物展示 4 个选 1 |
| 精英战完成 3 任务 | 获得 19 余烬，稀有遗物权重提高 |
| Boss 胜利 | 获得 14 余烬，进入章节奖励或通关结算 |
| Boss 溃败但守护值大于 0 | 不发奖励，回同一 Boss 节点预览 |
| 守护值归 0 | 进入 Run 失败，不领取奖励 |
| 守卫者死亡 | 死亡守卫者不出现在升级和治疗目标中 |
| 奖励页重进 | 读取同一个 `pending_reward`，选项不重新随机 |
| 领取后重进 | `pending_reward` 已清空，不重复发奖 |
