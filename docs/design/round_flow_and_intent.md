## 0. 一句话总结

> **敌人在回合开始时移动 → 红色攻击意图持续显示整个玩家回合 → 玩家做决策 → 回合末敌人执行攻击。**
>
> 移动和攻击是 **同一个回合里的两个独立子阶段** ，不是同一个原子动作。敌人的攻击方向锁定；被推开后，攻击线从敌人当前位置沿原方向继续投射。

## 1. 完整回合结构（精确步骤）

每个战斗轮次（Round 1 ~ Round 5）按以下严格顺序执行：

```
─── 回合 N 开始 ───
  1. 地裂出怪
       触发条件：上一回合预告过的地裂（pending_rift_spawns 非空）
       行为：在地裂格生成新敌人（UNIT_SPAWNED 事件）
       视觉：红光淡入 + 缩放弹出动画

  2. AI 全员规划
       为每个存活敌人计算 EnemyPlan：
         - origin_pos：当前位置快照（用于回溯计划来源）
         - move_to：本回合移动落点（可以 == origin_pos 表示不动）
         - attack_pos：移动到 move_to 后锁定的攻击参考格（可以未设置表示不攻击）

  3. ⭐ 敌人执行【移动】子阶段（可见）
       按敌人 ID 升序逐个移动到 move_to
       视觉：每个敌人一个 0.18s 的滑动动画
       关键：移动完成后，所有敌人**站在它们的 plan.move_to 位置**

  4. 预告下回合出怪（pending_rift_spawns 更新）
       查找 rift_schedule 中 round == N 的条目，全部加入 pending
       视觉：金色脉动 ↑ 标记 + "下回合" 标签，整个玩家回合可见

  5. 守卫者标志位重置
       所有守卫者 has_acted = false, has_moved = false

  6. 阶段切换：PLAYER_ACTION
       玩家可以操作守卫者（移动 / 攻击 / 撤回 / 结束回合）
       屏幕上同时显示：
         - 敌人在它们的 move_to 位置
         - 红色攻击格 + 红色攻击箭头（从敌人当前位置 → 攻击目标）

─── 玩家回合 ───
  7. 玩家执行任意行动序列
       每个守卫者：最多 1 次移动 + 1 次攻击（攻击或结束回合后该守卫者完毕）
       玩家可推开敌人、击杀敌人、走位、撤回

  8. 玩家按"结束回合"键

─── 回合 N 末敌方执行 ───
  9. ⭐ 敌人执行【攻击】子阶段
       按敌人 ID 升序逐个尝试攻击：
       - 用 plan.move_to → plan.attack_pos 计算锁定方向
       - 从敌人当前位置沿锁定方向投射实际攻击格
       - 实际攻击格上有守卫者或可攻击建筑 → 触发 PhysicsResolver.resolve_attack / 建筑伤害
       - 实际攻击格为空、越界或没有可伤害目标 → 攻击槽仍播放，但不造成伤害
       视觉：原子结算链动画（伤害闪光 + 推动 + 撞墙 + 接力）

  10. 胜负检查（_check_battle_end）
        三个条件必须全部满足才判胜利：
        (a) 守卫者未灭团（否则失败）
        (b) 场上敌人 = 0
        (c) pending_rift_spawns = 0（下回合不会冒新怪）
        (d) rift_schedule 中没有 round >= current_round 的未来出怪
        (e) current_round >= 2（至少打过一回合再判胜）

  11. 如果战斗未结束 → current_round += 1，跳回到步骤 1
```

## 2. 敌人意图模型（EnemyPlan）

### 2.1 数据结构

```
EnemyPlan:
  origin_pos: Vector2i   # 计划制定时敌人的位置（用于回溯计划来源）
  move_to:    Vector2i   # 本回合移动落点
  attack_pos: Vector2i   # 本回合攻击参考格（(-1,-1) = 不攻击）
```

### 2.2 移动 + 攻击的关系

| 情境 | move_to | attack_pos | 行为 |
|---|---|---|---|
| 起始邻接守卫者 | == origin_pos | 守卫者格 | 站着打 |
| 不邻接但移动后能到达邻位 | 路径中第 N 格（N = def.move）| 守卫者格 | 移动后打 |
| 太远无法到达邻位 | 朝守卫者方向走 N 格 | (-1,-1) | 只移动不打 |
| 已被孤立 / 无目标 | == origin_pos | (-1,-1) | 站着不动 |

**核心规则** ：
- 移动和攻击在 **时间上分离** （步骤 3 移动 vs 步骤 9 攻击）
- 但 plan **同时** 包含两者（一次规划，两次执行）
- 这与 ITB 的 Vek 行为一致

### 2.3 攻击方向 = move_to → attack_pos

`attack_pos` 不是永远固定的最终受击格，而是用来和 `move_to` 组成锁定方向：

```
locked_dir = Direction.from_cells(plan.move_to, plan.attack_pos)
actual_attack_pos = project_from(enemy.position, locked_dir, enemy.attack_range)
```

敌人被玩家推开或拉走后，不会重新规划，也不会立刻取消攻击。系统用同一个 `locked_dir` 从敌人的当前实际位置重新投射攻击格。

## 3. 锁定原则（Lock Principle）

> 主策划案 §3.4 提到「锁定原则」但未形式化。本节是规范化版本。

### 3.1 定义

**敌人本回合的攻击方向是锁定的，玩家任何操作都不能让敌人重新选目标。但玩家可以移动敌人、移动挡线单位或击杀敌人，从而改变这条攻击线最终打到哪里。**

### 3.2 实际攻击格计算

敌人执行攻击时先计算实际攻击格：

| 敌人类型 | 实际攻击格 |
|---|---|
| 近战敌人 | `enemy.position + locked_dir` |
| 远程敌人 | 从 `enemy.position` 沿 `locked_dir` 扫描到射程上限，遇到第一个单位 / 阻挡建筑 / 阻挡地形时停下 |

随后根据实际攻击格结算：

| 情况 | 结算 |
|---|---|
| 实际攻击格上有守卫者 | 命中该守卫者 |
| 实际攻击格上有可攻击建筑 | 命中该建筑 |
| 实际攻击格为空 | 攻击槽照常播放，但不造成伤害 |
| 敌人已死亡 / 坠渊 / 被移除 | 该敌人攻击槽移除 |
| 锁定方向无效 | 该敌人攻击槽移除 |

### 3.3 设计意图

- **推开 = 改变攻击线** ：玩家用 1 次行动把攻击线平移到空格、建筑、其他守卫者或更安全的位置。
- **攻击槽不静默消失** ：只要敌人还活着且方向有效，它仍会按顺序出手，玩家能理解“它确实攻击了，只是打到了新的位置或打空”。
- **可推演性** ：棋盘始终显示当前真实攻击线；伤害数字只显示在实际会受伤的格子上。

### 3.4 不被锁定的部分

- **移动子阶段（步骤 3）已经在玩家回合开始前完成** ，不可撤销 / 不受玩家操作影响
- **敌人 plan 本身不会重新计算** （即使敌人被推到新位置，`plan.attack_pos` 仍只作为原方向参考）

## 4. 地裂出怪时序（Rift Spawn Timing）

### 4.1 schedule 数据结构

```
rift_schedule: Array of {
  round: int,     # 在哪个回合"预告"
  pos:   Vector2i,
  def:   UnitDef,
}
```

### 4.2 时序流程

```
回合 N（玩家回合期间）
  - pending_rift_spawns 包含的条目：上回合 N-1 在步骤 4 预告的
  - 金色 ↑ 标记可见

回合 N+1 开始
  - 步骤 1：pending 中的条目全部出怪 → 加入 state.units
  - 步骤 2：AI 给它们规划（含新出怪的）
  - 步骤 3：所有敌人移动（含新出怪的）⭐ 关键
  - 步骤 4：查 schedule，把 round == N+1 的条目加入 pending（下回合的 ↑）
```

### 4.3 关键不变量

- **新出怪的敌人在它们的"出生回合"立即参与移动** （步骤 3 包含它们）
  - 而不是「下回合才动」
- **不预告 = 不出怪** ：如果某回合没有预告（pending 为空），那回合不出怪
- **回合 1 默认无活动** ：production 的 rift_schedule 从 round=2 开始，所以回合 1 没有金 ↑ 也没有出怪

### 4.4 预告标记的可见时窗

| 时间点 | pending_rift_spawns | 金色 ↑ 可见？ |
|---|---|---|
| 战斗开始（部署） | 空 | 否 |
| 回合 N 步骤 4 之后 | 含 N+1 的出怪 | ✅ 可见 |
| 回合 N+1 步骤 1 之前 | 同上 | ✅ 可见（最后一刻） |
| 回合 N+1 步骤 1 之后 | 清空（已出怪） | 否 |

预告必须 **在玩家做决策的整段时间内可见** 。如果预告只在某个瞬间出现就被消费，等于玩家从未看到。

## 5. UI 威胁可视化（Threat Visualization）

### 5.1 基本原则

威胁信息 **所有玩家都能看到，永远不隐藏** 。鼠标悬停只调整亮度，不改变可见性。

### 5.2 攻击意图绘制

```
For each enemy with plan.attack_pos != (-1, -1):
  1) 用 move_to → attack_pos 得到 locked_dir
  2) 从 enemy.current_position 沿 locked_dir 投射 actual_attack_pos
  3) 从 enemy.current_position 到 actual_attack_pos 画红色箭头
  4) 如果 actual_attack_pos 会造成伤害，在该格显示伤害数字
```

**注意** ：不画移动路径，不画 origin_pos 幽灵，不画过程动画。只画“从当前敌人位置沿锁定方向打到哪里”的最终意图。

### 5.3 三档亮度

| 状态 | 触发 |
|---|---|
| Focused | 鼠标悬停的那个敌人 — 100% 不透明，粗箭头 |
| Normal | 无 hover 时所有敌人 — ~85% 不透明 |
| Dimmed | hover 别人时其他敌人 — ~55% 不透明，但 **仍然可见** |

### 5.4 攻击槽与伤害提示

- 被推开的敌人如果仍有有效攻击方向， **红色箭头继续显示** ，只是起点变为敌人当前实际位置，终点变为重新投射出的实际攻击格。
- 实际攻击格为空时，红色箭头仍显示，但不显示伤害数字。
- 实际攻击格上有守卫者或建筑时，在棋盘上显示 `-N` 伤害徽标；多个敌人打同一格时合并为总伤害。
- 敌人已死亡、坠渊或被移除时，攻击箭头和伤害提示都移除，但顺序栈可以短暂保留“已移除”的队列反馈。
- 如果玩家行动导致敌人位移，旧攻击线必须先隐藏，等位移动画播放完成后再刷新新攻击线，避免“红线先跳、敌人后动”的时序错觉。

## 6. 玩家行动权预算（Per-Warden Per-Turn）

### 6.1 ITB 标准

每个守卫者每回合： **1 次移动 + 1 次攻击** （任意顺序，但攻击或"结束回合"结束该守卫者的整个回合）

### 6.2 状态字段

```
Unit:
  has_moved: bool   # 本回合移动过（不能再移）
  has_acted: bool   # 本回合攻击过或被显式结束（完全结束）
```

### 6.3 状态转换

| 操作 | has_moved | has_acted | 备注 |
|---|---|---|---|
| 移动 | → true | 不变 | 还能攻击 |
| 攻击 | 不变 | → true | 不能再做任何事 |
| 结束回合（按钮）| → true | → true | 跳过剩余 |
| 回合开始 | → false | → false | 重置 |

### 6.4 自动推进

当 **所有守卫者 has_acted == true** 时，回合自动结束（不需要按结束回合）。

## 7. 技能/动作选择 UI（Ability Selection）

### 7.1 三种等价的操作路径

| 路径 | 流程 |
|---|---|
| **快速点击** | 选守卫者 → 直接点棋盘目标格 |
| **技能驱动** | 选守卫者 → 点底部技能按钮 → 点目标 |
| **技能切换** | 已上膛某技能 → 点另一个技能按钮 |

### 7.2 上膛状态（armed）

```
_armed_ability_id: String
  ""        - 未上膛，所有合法格都高亮（移动绿 + 攻击红）
  "attack"  - 攻击上膛，只高亮攻击格
  "move"    - 移动上膛，只高亮移动格
```

### 7.3 取消上膛

| 操作 | 行为 |
|---|---|
| 再次点击同一技能按钮 | 切换 off |
| 右键（cancel） | 完全取消选中 |
| 点击别的守卫者 | 切到那个守卫者，自动清除上膛 |
| 点空白棋盘 | 完全取消选中 |
| 执行了行动 | 上膛自动清除 |

## 9. 切片演示阶段的临时调整

> 以下数值偏离主策划案，仅为切片演示阶段方便观察玩法。正式实现教学关时会按主策划案调回。

| 项 | 主策划案 | 切片当前 | 调整理由 |
|---|---|---|---|
| 腐食兽 HP | 1 | 2 | HP=1 一击必杀，看不出物理操作的战术深度 |
| 腐食兽移动力 | 2 | 3 | 接战节奏更紧凑，便于演示完整战斗循环 |
| 瘟疫弓手 | 1.0+ 才出 | 切片实装 | 给玩家挡线 / 击线战术体验 |
| 弓手射线锁定 | 直线第一个单位（含友军误伤）| **只锁定守卫者** ；同阵营单位作为挡线物（不会被射中）| 简化 UX，避免"敌人攻击敌人"的迷惑展示 |
| 地裂数量 | 设计未规定（每地图不同）| 2 | 演示充足，不过载 |
| 出怪 schedule | 设计未规定（每地图不同）| round 2/2/3 三条目 | 5 回合战中段压力 |
| 守护值系统 | 12 起始；保护目标每受 1 点实际伤害扣 1 守护值 | 未实装 | 切片不实装建筑 / 守护值 |
| 建筑 | 2-3 栋 | 未实装 | 切片只验证物理 + AI 流 |
| 挑战目标 | 4 个 | 未实装 | 切片不验证元结构 |
| **友军误伤** | 设计允许（撞墙 1 伤含友军）| **禁用** （同阵营撞击 0 伤）| 简化战术决策，玩家专注推/拉/坠渊 |

### 9.1 友军误伤规则（切片版）

bump damage 取决于「 **chain 的原始发起者** 」与「 **被撞单位** 」是否同阵营：

| 原始攻击者 | 被撞 | 伤害 |
|---|---|---|
| 守卫者 | 守卫者 | **0** （友军误伤禁用）|
| 守卫者 | 敌人 | 1（你想砸的就是它）|
| 敌人 | 守卫者 | 1（敌方攻击伤害守卫者）|
| 敌人 | 敌人 | **0** （敌人互撞不互伤）|

**判定核心** ：撞击伤害看「chain 的原始发起者」vs「被撞」的阵营，不看「推动者」vs「被撞」。这样玩家用守卫者推敌人去撞另一只敌人 **会造成伤害** （因为攻击者=守卫者，被撞=敌人，异阵营），而不会误伤友军（攻击者=守卫者，被撞=守卫者，同阵营 → 0 伤）。

详见 [combat_resolution_truth_table.md §8](combat_resolution_truth_table.md)。

## 11. 仍未敲定（After-MVP）

以下条目目前 **未在切片中实现，也未形式化定义** ，1.0+ 阶段需要补：

- **碎裂状态（Cracked）**：撞击后下回合 -1 移动力（主策划案 §3.6 已定义，引擎未实装）
- **弓手射线意图可视化** ：远程攻击的"挡线"战术（需要 LOS 渲染）
- **铁角兽冲撞 AI** ：直线冲刺停在第一障碍（主策划案 §8.5 已定义，引擎未实装）
- **建筑系统** ：保护目标 + HP + 被毁视觉
- **守护值 / Run 元 / 商店 / 营地 / 遗物 / 挑战目标 / Boss** ：完整 MVP 范围

这些都在切片 acceptance（[../architecture/framework_design.md §10](../architecture/framework_design.md)）之外。
