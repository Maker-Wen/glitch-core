## 1. 原子结算链 — 状态生命周期

### 1.1 单位状态字段

```
unit = {
  hp: int (1-4)
  cracked: bool (default false)
  position: (x, y)
  alive: bool (default true)
}
```

### 1.2 链解析中的关键时间点

```
时间点 T0：攻击声明（玩家选完目标 + 动作）
  ↓
时间点 T1：伤害快照（读取目标状态用于伤害计算，Cracksbane 此时检查）
  ↓
时间点 T2：伤害施加（HP -= 1）
  ↓
时间点 T3：推力施加 + 逐格推进开始
  ↓
时间点 T4..Tn：逐格碰撞结算（每碰撞一次产生 sub-step）
  ↓
时间点 Tend：链结束
  - 清除所有 alive=false 的单位
  - 触发回合末效果（建筑 HP 显示更新、地裂出怪等）
```

**核心规则**：
- **T1 的伤害快照在 T4..Tn 之前**——同动作产生的碎裂**不会**触发同动作的 Cracksbane
- **alive=false 的单位在 Tend 前保持实体**（占格、可碰撞、可被推、可施加碎裂给别人）
- **多个 alive=false 单位的清除**统一在 Tend 一次性完成

## 2. 碎裂状态 — 完整规则

| 项 | 裁定 |
|---|---|
| **类型** | 布尔值（cracked: true/false），无叠加 |
| **持续期** | 直到该单位**下一次自己的完整回合结束**后清除 |
| **重复施加** | 同链/同回合多次施加 → **刷新**（不延长），仍是"下回合一次性" |
| **作用** | 该单位下次行动时，预警阶段的"移动力"-1（最低为 0）|
| **谁能获得** | 所有可移动单位（守卫者、敌人）。守卫者也可被碎裂 |
| **谁不能获得** | 建筑、石柱、锚石、地裂（这些是地形/特殊单位） |

### 2.1 触发条件（按 §3.5 原子流程的逐格推进 step 触发）

| 推进 step 类型 | 是否施加碎裂 | 给谁 |
|---|---|---|
| 撞建筑 | ✅ | 撞击的单位 |
| 撞石柱 | ✅ | 撞击的单位 |
| 撞锚石 | ✅ | 撞击的单位（锚石不获得碎裂） |
| 接力撞单位（U 被撞） | ✅ | 被撞的 U（不给推动来的 T）|
| 滑过空格 | ❌ | — |
| 坠渊 | ❌ | 直接死亡，无意义 |

### 2.2 谁施加碎裂

- **玩家攻击产生的撞击** → 施加碎裂 ✅
- **敌人攻击产生的撞击**（如铁角兽冲撞）→ 施加碎裂 ✅
- **Boss 横扫钟波推动产生的撞击** → 施加碎裂 ✅
- **被推单位再次撞别的单位（接力第 2/3 段）** → 施加碎裂 ✅

**统一规则**：只要在原子链中发生"撞墙/撞石柱/撞单位"，就给被撞主体施加碎裂。**不区分谁是发起者**。

### 2.3 时序示例

**场景 A**：赏金猎人（链锤改装 推 2）攻击新鲜铁角兽（HP=3, 无碎裂）

```
T0: 玩家声明：BH 近战攻击 IronHorn 朝东推 2
T1: 伤害快照 — Cracksbane 检查 IronHorn.cracked=false → 伤害=1（不+1）
T2: IronHorn.hp = 2
T3: IronHorn 朝东推 2 格
T4: 第 1 格——空格 → IronHorn 滑入，剩余推力 1
T5: 第 2 格——撞墙 → IronHorn.hp = 1 (撞墙 1 伤), IronHorn.cracked = true
Tend: 清算 — IronHorn 仍 alive (HP=1)

结果：IronHorn HP=1，碎裂状态
```

**场景 B**：另一回合，玩家用大魔法师攻击同一只已碎裂的铁角兽

```
T0: 玩家声明：Mage 远程推 IronHorn 朝南推 1
T1: 伤害快照 — Cracksbane 检查 IronHorn.cracked=true → 伤害=2 (+1)
T2: IronHorn.hp = 1-2 = -1 (死亡标记)
T3: IronHorn 朝南推 1（仍占格，因为 Tend 前不清除）
T4: 第 1 格——撞建筑 → 建筑.hp -= 1, IronHorn.hp -= 1 (撞墙伤，但已死)
Tend: 清算 — IronHorn alive=false，从棋盘移除

结果：IronHorn 死亡 + 建筑 HP -1
```

## 3. 0 HP 单位行为

| 时机 | 行为 |
|---|---|
| HP 归 0 瞬间 | 标记 alive=false，**仍占格** |
| 后续 step 中被推 | 可以被推（按普通单位规则） |
| 后续 step 中作为被撞物 | 可以让推动者停下，被撞者（即将清除）传递剩余推力 |
| 后续 step 中坠渊 | 不影响（已死亡），不额外计算 |
| 链结束 Tend | **统一清除**所有 alive=false 单位 |

> **设计原因**：避免链中"前一刻还存在的单位突然消失导致后续推动落空"。所有死亡延迟到链结束统一处理，让链的视觉/逻辑可预演。

## 4. 同格冲突解析

### 4.1 推动 vs 已存在单位

按 §3.5 接力规则：被撞 U 受 1 伤 + 获得碎裂 + 剩余推力传递。

### 4.2 多个敌人想去同一格（预警阶段）

| 情境 | 裁定 |
|---|---|
| 两个敌人下回合预警都想去格 X | 按**敌人生成 ID 升序**：ID 小的去 X；ID 大的**保持原位**（不重算路径，不绕路）|
| 预演 UI | 必须用相同规则显示——避免预演与实际执行偏差 |

### 4.3 敌人想去玩家守卫者占据的格

按 §4.5 三铁律 — 路径上有守卫者挡路 + 不能绕路 → **近战攻击该守卫者**，本回合不前进。

### 4.4 无路 + 无绕路 + 无挡路攻击者（隔离敌人）

```
裁定：敌人保持原位。
  - 不消失
  - 不自杀
  - 不随机乱跑
  - 预演阶段显示"该敌人本回合静止"
```

## 5. 弓手射击规则（一刀切版）

> **重要**：Oracle 审查发现旧版本 §11.6 与 §4.5 矛盾。**以下是统一版本，覆盖所有旧规则**。

### 5.1 弓手射击锁定流程

```
1. 预警阶段，沿 4 方向直线扫描射程 3 格
2. 锁定方向：
   a. 优先选择**有任何可被击中目标**的方向
      （可被击中 = 守卫者 / 建筑 / 其他敌人）
   b. 多方向都有 → N/E/S/W 优先
3. 锁定目标：
   **沿该方向，直线上的第一个单位（含建筑），无论是什么类型**
   - 第一个是建筑 → 击中建筑
   - 第一个是守卫者 → 击中守卫者
   - 第一个是其他敌人 → 击中其他敌人（友军误伤）
4. 完全无可击中目标 → 不射击，改为正常移动
```

### 5.2 核心原则

**直线上第一个目标被命中。没有建筑优先权。守卫者可以身体挡线保护建筑。**

### 5.3 设计意图

- 完美信息：玩家看到弓手预警，能精确推演谁会被打中
- 战术成立：身体挡线是有效战术，不是"假承诺"
- 一致性：与玩家远程攻击的友军挡线规则**对称**

## 6. 锚石（Boss 战）特例

| 项 | 裁定 |
|---|---|
| 锚石是否会被推动 | 否 |
| 锚石是否获得碎裂 | **永远不会** |
| 敌人撞锚石是否获得碎裂 | ✅ 是的（撞击单位获得碎裂）|
| 玩家撞锚石是否获得碎裂 | ✅ 是的 |
| 锚石 HP 如何被攻击 | 玩家任意近战/远程攻击命中 → 锚石 -1 HP；或被推飞的单位撞 → 锚石 -1 HP |
| 锚石全毁后 | 触发 Boss 暴露相，详见 [boss_knell_lord.md](boss_knell_lord.md) |

## 7. Boss 横扫钟波（Knell Sweep）细节

| 项 | 裁定 |
|---|---|
| 推方向 | 朝该行/列**最近的棋盘边缘**推；并列时按 **N/E/S/W** |
| 推距离 | 2 格 |
| 伤害 | 1 |
| 影响范围 | 该行/列上**所有非建筑、非锚石单位**（含守卫者、敌人、Boss 暴露相弱点格） |
| 是否施加碎裂 | ✅ 撞墙/撞单位时按 §2 规则正常施加碎裂 |
| 守卫者是否会被推下深渊 | ✅ 是的，可能 |

### Chain Pulse（锚链脉冲）叠加规则

```
单位站在 2 个锚石的相邻 1 格内时：
  → 上限 +1 移动（不叠加为 +2）
```

## 8. 友军误伤规则（切片版）

🔴 **MVP 切片更新**：原设计允许「友军误伤」作为战术，但切片演示阶段**禁用 chain 攻击者与被撞单位同阵营的撞击伤害**。

### 8.1 判定核心

bump damage 取决于「**chain 的原始发起者** (`attacker`)」与「**被撞单位** (`other`)」是否同阵营：

```gdscript
var bump_damage: int = 1
if attacker.def.faction == other.def.faction:
    bump_damage = 0  # 禁用友军误伤
```

注意是「攻击者 vs 被撞」，**不是「推动者 (subject) vs 被撞」**。这意味着用守卫者推敌人去撞另一只敌人**会造成伤害**（攻击者=守卫者，被撞=敌人，异阵营），不算友军误伤。

### 8.2 完整裁定表

| 攻击者 | 被撞 | bump 伤害 | 物理推动 | 备注 |
|---|---|---|---|---|
| 守卫者 | 守卫者 | **0** | 正常 | 禁用友军误伤 |
| 守卫者 | 敌人 | 1 | 正常 | 玩家主动制造连锁 |
| 敌人 | 守卫者 | 1 | 正常 | 敌人攻击伤害守卫者 |
| 敌人 | 敌人 | **0** | 正常 | 敌人互撞不互伤 |
| 任一 | 石柱 / 建筑 / 棋盘外缘 | 不受影响 | — | 物理伤害照旧（见 §1.2）|

### 8.3 玩家远程攻击友军挡线

UI 层 `get_legal_attack_targets` **不显示友军作为可点目标**，所以玩家不能直接锁定友军。但通过 chain 接力可能间接撞到友军 → 按 §8.1 判定（0 伤）。

> **设计意图**：MVP 阶段简化为「无友伤」让玩家更专注于把敌人推下深渊 / 撞墙的核心物理操作，不用担心误伤自己的守卫者。1.0+ 引入遗物时可能引入「主动友军误伤换收益」类技能，届时再开放友伤。
>
> 详见 [round_flow_and_intent.md §9.1](round_flow_and_intent.md)。

## 9. 地裂占据延迟规则（最终版）

| 项 | 裁定 |
|---|---|
| 地裂队列 | **最多 1 个排队出怪**（不堆积）|
| 占据者效果 | 受 1 伤 + **同一个排队的出怪延迟 1 回合** |
| 地裂是否消失 | 否，保留 |
| 占据者下回合继续占据 | 继续延迟出怪 + 继续受 1 伤（每回合都付 HP 代价）|
| 占据者死亡或离开 | 排队出怪在它下次到达计数器时正常出现 |

## 10. 守卫者坠渊规则

| 情境 | 是否会坠渊 |
|---|---|
| 敌人冲撞推守卫者出棋盘边缘 | ✅ 坠渊（守卫者本场永久离场，下场满血归位）|
| Boss 横扫钟波推守卫者出棋盘边缘 | ✅ 坠渊 |
| 敌人接力推动撞守卫者，撞击使守卫者出棋盘 | ✅ 坠渊 |
| 玩家自己的远程攻击不小心击中守卫者 | 守卫者按"被击中"逻辑处理（受 1 伤 + 推/拉），可能坠渊 |

## 11. 实现核对清单

物理引擎实现时按此顺序核对：

- [ ] 链解析使用 T0-Tend 时间点模型
- [ ] 0 HP 单位在 Tend 前保持实体
- [ ] Cracksbane 在 T1 检查目标 cracked 状态（不是同链后期）
- [ ] 碎裂状态在被施加单位的下个完整回合结束后清除
- [ ] 同链碎裂多次施加只刷新不叠加
- [ ] 多敌人争同格按 ID 升序，预演与实际一致
- [ ] 弓手锁定"直线第一个目标"，无建筑优先权
- [ ] 玩家远程攻击直线第一个目标（含友军）
- [ ] 锚石不获得碎裂；撞锚石的单位获得碎裂
- [ ] Boss 横扫推方向朝最近边缘，并列 N/E/S/W
- [ ] Chain Pulse 多锚石叠加上限 +1
- [ ] 地裂队列最多 1 个出怪；占据延迟同一出怪
