# 全系统设计基线与交接清单

> 日期：2026-06-04  
> 状态：系统级设计基线第一版  
> 依赖：[defense_roguelite_core_design.md](defense_roguelite_core_design.md)

## 1. 目的

本文档用于补齐“战斗规则之外”的完整游戏系统边界，作为后续实现 agent、UI 设计和内容配置的交接入口。

当前已有文档已经覆盖战斗胜负、守护值、守卫者 HP、敌人、地图题型、出怪预算、Run 结构、UI 页面流、基础 Run 经济和少量遗物。但完整产品还需要工坊、商店、营地、事件、图鉴、设置和部分内容池细则。

本文档不替代子系统细则。它负责回答：

1. 游戏从启动到失败或通关有哪些页面和系统。
2. 每个系统的入口、出口、状态输入和状态输出是什么。
3. 哪些规则已经定稿，哪些还需要单独补文档。
4. 哪些内容属于第一轮可玩 Demo，哪些留到后续版本。

## 2. 产品流程总览

```text
启动游戏
  -> 主菜单
  -> 新 Run / 继续 Run
  -> Run 准备
  -> 守卫者选择
  -> 初始奖励选择
  -> 章节路线图
  -> 节点预览
  -> 节点执行
       -> 战斗
       -> 事件
       -> 工坊
       -> 商店
       -> 营地
       -> 神龛
  -> 节点结算
  -> 章节 Boss
  -> 章节结算
  -> 下一章或 Run 结算
```

第一轮 Demo 可以压缩为：

```text
主菜单
  -> 新 Run
  -> 固定 3 人队伍
  -> 1 章 6 节点路线
  -> 普通战
  -> 事件
  -> 普通战
  -> 精英战
  -> 营地
  -> Boss
  -> Run 结算
```

## 3. 全局状态

Run 状态至少包含以下字段：

| 状态 | 类型 | 说明 |
|---|---|---|
| `run_id` | string | 当前 Run 存档 ID |
| `chapter_index` | int | 当前章节 |
| `node_index` | int | 当前路线节点 |
| `sanctuary_integrity` | int | 当前守护值 |
| `sanctuary_integrity_max` | int | 守护值上限，默认 12 |
| `embers` | int | 余烬货币 |
| `corruption` | int | 腐化值 |
| `wardens` | array | 当前 Run 守卫者名单、HP、升级、死亡状态 |
| `relics` | array | 已获得遗物 |
| `completed_rewards_this_chapter` | int | 本章通过奖励任务恢复守护值次数 |
| `route_graph` | object | 当前章节路线结构 |
| `visited_nodes` | array | 已完成节点 |
| `unlocked_content` | object | 已解锁守卫者、遗物、难度 |

战斗节点进入时从 Run 状态读取：

- 守护值。
- 守卫者名单和当前 HP。
- 遗物列表。
- 当前章节、腐化和节点难度。
- 节点奖励任务。
- 地图和出怪配置。

战斗节点退出时写回：

- 守护值扣减或恢复。
- 守卫者 HP 和死亡状态。
- 奖励任务完成结果。
- 余烬、遗物、升级奖励。
- 是否 Run 失败。

## 4. 主菜单系统

### 4.1 目的

主菜单负责让玩家进入或管理 Run，不承载复杂叙事。第一屏必须明确品牌、当前可继续的 Run 和主要操作。

### 4.2 页面入口和出口

| 页面 | 入口 | 出口 |
|---|---|---|
| 主菜单 | 游戏启动、Run 结算返回 | 新 Run、继续 Run、设置、图鉴、退出 |
| 新 Run 确认 | 主菜单点击新 Run | Run 准备，或返回主菜单 |
| 继续 Run | 主菜单点击继续 Run | 最近存档路线图 |
| 设置 | 主菜单或暂停菜单 | 返回来源页面 |
| 图鉴 | 主菜单或 Run 内暂停菜单 | 返回来源页面 |

### 4.3 第一版主菜单按钮

| 按钮 | 显示条件 | 行为 |
|---|---|---|
| 继续 Run | 存在未结束存档 | 进入当前章节路线图 |
| 新 Run | 始终显示 | 若有未结束存档，弹确认覆盖 |
| 图鉴 | 始终显示 | 打开已见内容说明 |
| 设置 | 始终显示 | 打开设置 |
| 退出 | 桌面版显示 | 退出游戏 |

### 4.4 UI 信息

主菜单显示：

- 游戏标题。
- 当前版本或 Demo 标识。
- 继续 Run 摘要：章节、守护值、存活守卫者、路线节点。
- 主要按钮。

不在主菜单显示复杂系统说明、教程长文或角色详情。

## 5. Run 准备系统

### 5.1 目的

Run 准备用于建立本局的初始条件：队伍、初始守护值、初始资源和初始遗物。

### 5.2 第一版流程

```text
新 Run
  -> 难度选择
  -> 守卫者选择
  -> 初始遗物选择
  -> 确认出发
```

Demo 版本可以简化为：

```text
新 Run
  -> 固定 3 名守卫者
  -> 固定守护值 12 / 12
  -> 无初始遗物
  -> 进入章节路线图
```

### 5.3 守卫者选择

完整第一版建议为 5 选 3：

| 守卫者 | 职责 | 初始 HP |
|---|---|---:|
| 赏金猎人 | 近战推位、边缘处决 | 2 |
| 盗墓人 | 远程拉位、挡线修正 | 2 |
| 大魔法师 | 远程推位、碎裂协同 | 2 |
| 铁誓卫 | 防线、换位、承伤 | 3 |
| 工兵 | 路障、路径阻断 | 2 |

祷告者和决斗士保留为后续候选。第一版如果只做 3 名基础守卫者，UI 仍应按“将来可选”的结构设计，避免后续重做页面。

### 5.4 初始资源

| 资源 | 默认值 | 说明 |
|---|---:|---|
| 守护值 | 12 / 12 | Run 级防线生命 |
| 余烬 | 0 | 不给初始购买，减少前置选择 |
| 腐化 | 0 | 后续通过神龛、事件、遗物获得 |
| 初始遗物 | 0 或 1 | Demo 不给；完整第一版可给普通遗物 3 选 1 |

## 6. 章节路线系统

### 6.1 目的

章节路线系统提供肉鸽的路线选择、风险预览和资源取舍。路线选择必须影响玩家下一场战斗的压力和奖励，而不是只改变背景图。

### 6.2 节点类型

| 节点 | 作用 | 第一版状态 |
|---|---|---|
| 普通战 | 稳定获得余烬和成长 | 必做 |
| 精英战 | 高风险，稳定给遗物 | 必做 |
| 事件 | 资源交换和风险选择 | 必做 |
| 工坊 | 购买或强化守卫者升级 | 第一版可简化 |
| 商店 | 购买遗物、治疗、修复守护值 | 第一版可简化 |
| 营地 | 大额治疗或修复 | 必做 |
| 神龛 | 高收益高腐化 | 可后置 |
| Boss | 章节终局 | 必做 |

### 6.3 路线生成规则

完整第一版：

- 每章 5-7 个节点。
- 第 1 个节点固定普通战。
- 章节末固定 Boss。
- 每章至少 1 个营地或工坊。
- 精英战后至少给 1 个非战斗节点选择。
- Boss 前 1 个节点不能是神龛。
- 同一路径不连续出现 3 个战斗节点，除非奖励明显更高。
- 高腐化路线必须显示风险图标。

Demo 固定路线：

```text
普通战 -> 事件 -> 普通战 -> 精英战 -> 营地 -> Boss
```

### 6.4 节点预览信息

玩家点击节点时必须看到：

- 节点类型。
- 压力标签或事件标题。
- 预计奖励。
- 预计风险：敌人类型、硬威胁上限、特殊地形。
- 裂隙强度：0-3。裂隙出怪计入总敌人预算。
- 当前资源：守护值、余烬、守卫者 HP。

预览不需要展示完整地图，但不能隐藏会改变决策的风险，例如深渊地图、精英铁角兽、Boss 毁灭计数。

## 7. 战斗系统

战斗系统以 [battle_objectives_and_rewards.md](battle_objectives_and_rewards.md)、[enemy_map_encounter_design.md](enemy_map_encounter_design.md) 和 [round_flow_and_intent.md](round_flow_and_intent.md) 为准。

系统级交接只强调 4 条：

1. 战斗胜利只在最大回合后检查。
2. 保护目标每 1 点实际受伤都会通过守护值承接。
3. 守卫者 HP 跨战斗保留，1 HP 濒死，0 HP 死亡。
4. 所有关键结果必须在 HUD 和结算中解释。

战斗节点不使用互斥“战斗类型”决定规则。每场战斗由地图模板、保护目标布局、压力标签、裂隙强度、敌人压力包、每回合出怪表和奖励任务组成。裂隙是常规出怪压力模块，不是特殊关专属；裂隙出怪必须计入普通战、精英战或 Boss 战的总敌人预算。

## 8. 战后结算系统

### 8.1 结算顺序

```text
战斗结束
  -> 显示战斗结果
  -> 结算建筑损失和守护值变化
  -> 结算守卫者 HP、濒死、死亡
  -> 结算奖励任务
  -> 发放基础余烬
  -> 发放额外奖励
  -> 进入奖励选择或路线图
```

### 8.2 结算页必须显示

| 区域 | 内容 |
|---|---|
| 战斗结果 | 胜利、防线溃败、队伍覆灭、Boss 溃败 |
| 守护值 | 战前值、扣减原因、战后值 |
| 守卫者 | 每名守卫者战后 HP、濒死、死亡 |
| 建筑 | 被毁数量、受伤数量、关键目标状态 |
| 奖励任务 | 完成、失败、失败原因 |
| 奖励 | 基础余烬、额外余烬、遗物或升级 |
| 下一步 | 领取奖励、进入路线、Run 失败结算 |

### 8.3 战后奖励类型

| 来源 | 奖励 |
|---|---|
| 普通战基础 | 7 余烬 |
| 精英战基础 | 11 余烬 + 遗物 |
| Boss 战基础 | 14 余烬 + 章节奖励 |
| 奖励任务 1 个 | 额外余烬 |
| 奖励任务 2 个 | 额外余烬 + 奖励选项 +1 |
| 奖励任务 3 个 | 高额余烬，章节内守护值 +1 机会 |

## 9. 守卫者升级系统

### 9.1 目的

守卫者升级提供 Run 内构筑深度。升级应改变解法，不应变成单纯堆数值。

### 9.2 升级类型

每名守卫者有 6 个升级，分为 3 类：

| 类别 | 数量 | 作用 |
|---|---:|---|
| 动词增强 | 2 | 改范围、推拉距离、换位、连锁 |
| 防守增强 | 2 | 修复、屏障、挡线、建筑保护 |
| 任务增强 | 2 | 裂隙、物理击杀、清场、低损任务收益 |

### 9.3 获得方式

| 来源 | 规则 |
|---|---|
| 普通战奖励 | 每 2 场普通战后出现 1 次升级选项 |
| 工坊节点 | 花余烬购买指定守卫者升级 |
| 精英战 | 有概率给升级和遗物二选一 |
| 事件 | 可以用 HP、守护值或腐化换升级 |
| Boss 战 | 章节结束时给核心队伍升级机会 |

### 9.4 升级选择 UI

升级界面显示：

- 当前守卫者 HP、已有升级、核心动词。
- 3 个升级选项。
- 升级影响的技能说明和预览图标。
- 是否和当前遗物或奖励任务有协同。
- 选择后不可撤销。

### 9.5 限制

- 每名守卫者每章最多获得 1 次升级。
- 完整 3 章 Run 中，核心队伍每人约 2-3 个升级。
- 同一升级不可重复获得。
- 不提供永久攻击力堆叠路线。

## 10. 遗物系统

### 10.1 目的

遗物是 Run 构筑的主要差异来源。遗物改变规则、奖励和解法，不直接替代玩家判断。

### 10.2 稀有度

| 稀有度 | 占比 | 设计强度 |
|---|---:|---|
| 普通 | 65% | 小幅改写或稳定收益 |
| 稀有 | 30% | 改变解法或形成流派核心 |
| 诅咒 | 5% | 强收益 + 腐化或守护值代价 |

第一版可以只做普通和稀有。

### 10.3 获得方式

| 来源 | 获得规则 |
|---|---|
| 精英战 | 稳定给 1 个遗物，3 选 1 |
| Boss 战 | 稳定给 1 个稀有遗物或章节遗物 |
| 商店 | 出售 2 个普通遗物和 1 个稀有遗物 |
| 事件 | 风险交换获得遗物 |
| 神龛 | 获得稀有或诅咒遗物，腐化 +2 |
| 起始选择 | 完整第一版可给普通遗物 3 选 1 |

### 10.4 遗物类型

| 类型 | 作用 | 示例 |
|---|---|---|
| 位移遗物 | 改推拉、换位、撞击 | 链锤改装、断钟回响 |
| 防守遗物 | 改建筑、屏障、守护值 | 余烬护符、圣灰灯 |
| 裂隙遗物 | 改地裂占位、出怪延迟 | 裂隙钉 |
| 风险遗物 | 用 HP、守护值、腐化换收益 | 血税契约、腐化冠冕 |
| 任务遗物 | 强化奖励任务收益 | 守夜誓约 |

### 10.5 池规模目标

| 阶段 | 遗物数量 | 目标 |
|---|---:|---|
| Demo | 8 | 验证 3-4 个基本流派 |
| 第一章可玩版 | 16 | 支撑多次 Run 差异 |
| 完整第一版 | 30-40 | 支撑 3 章重复游玩 |

### 10.6 禁止规则

- 不做永久免疫某类核心威胁。
- 不做无代价复活。
- 不做随机命中、随机伤害。
- 不做需要隐藏 AI 配合的遗物。
- 不做大量纯数值加成。

## 11. 工坊系统

### 11.1 目的

工坊负责定向强化守卫者，给玩家弥补队伍短板的机会。

### 11.2 第一版功能

| 功能 | 价格 | 说明 |
|---|---:|---|
| 购买普通升级 | 10 | 指定 1 名守卫者，出现 2 选 1 |
| 购买稀有升级 | 14 | 第 2 章后解锁 |
| 重铸升级选项 | 3 | 刷新当前选项 |

Demo 可以简化为：进入工坊后固定展示 3 个升级，选择 1 个购买。

### 11.3 UI 需求

- 左侧显示队伍状态。
- 中间显示可购买升级。
- 右侧显示当前余烬和购买后余烬。
- 升级卡必须标注作用对象、类别和不可重复状态。

## 12. 商店系统

### 12.1 目的

商店负责小额修补和遗物购买。它不应替代营地的大额恢复，也不应让玩家完全抹平损耗。

### 12.2 商品池

| 商品 | 价格 | 限制 |
|---|---:|---|
| 普通遗物 | 12 | 每店 2 个 |
| 稀有遗物 | 18 | 每店 1 个，第 2 章后提高概率 |
| 单人恢复 1 HP | 4 | 只对存活守卫者 |
| 恢复 1 守护值 | 6 | 不超过上限 |
| 刷新商品 | 3 | 每店最多 1 次 |

### 12.3 UI 需求

- 商品卡显示价格、类型、作用和是否买得起。
- 购买治疗时必须选择目标守卫者。
- 购买守护值修复时显示修复前后数值。
- 商店离开后不能返回购买。

## 13. 营地系统

### 13.1 目的

营地是路线中的大修节点，迫使玩家在建筑线和人员线之间取舍。

### 13.2 第一版选择

| 选项 | 效果 |
|---|---|
| 治疗小队 | 所有存活守卫者 +1 HP，不超过最大 HP |
| 修复防线 | 守护值 +2，不超过上限 |
| 整备装备 | 获得 1 个普通升级选项，第 2 章后可出现 |

Demo 只需要前两个选项。

### 13.3 UI 需求

- 进入营地时显示当前守护值和守卫者 HP。
- 每个选项显示选择后的数值变化。
- 选择后立即生效并返回路线。
- 不做长文本剧情。

## 14. 事件系统

### 14.1 目的

事件提供非战斗路线选择，制造资源交换和风险收益。

### 14.2 事件类型

| 类型 | 作用 |
|---|---|
| 修复事件 | 花余烬或腐化恢复守护值 |
| 伤害事件 | 用守卫者 HP 换升级、遗物或余烬 |
| 腐化事件 | 获得强收益，提高后续压力 |
| 地图事件 | 改变下一战建筑 HP、敌人池或地形 |
| 招募事件 | 后续版本补充守卫者 |

### 14.3 事件规则

- 每个事件 2 个主选项，最多 1 个跳过选项。
- 所有后果必须在选择前公开。
- 事件不能在战斗开始后才揭示负面。
- 事件收益要和同章节战斗收益同量级，不做单次爆炸式成长。

### 14.4 Demo 事件池

| 事件 | 选择 A | 选择 B |
|---|---|---|
| 熄灭的灯塔 | 花 6 余烬恢复 1 守护值 | 获得 10 余烬，腐化 +1 |
| 破损军械库 | 获得普通升级，随机存活守卫者受 1 伤 | 跳过，获得 4 余烬 |
| 难民车队 | 失去 5 余烬，下一战建筑 HP +1 | 不帮助，无效果 |
| 钟声梦魇 | 下一战硬威胁 +1，奖励任务额外 +1 | 守护值 -1 |

## 15. 神龛系统

### 15.1 目的

神龛提供高风险高收益路线。它不是 Demo 必需系统。

### 15.2 第一版规则

| 选择 | 效果 |
|---|---|
| 接受腐化 | 获得稀有遗物，腐化 +2 |

## 21. 交接结论

后续开发不能只按战斗系统开工。至少要先把以下 4 个系统作为同一批实现基线：

1. 主菜单和 Run 开始。
2. 章节路线图和节点预览。
3. 战斗结算和奖励选择。
4. 守卫者升级、遗物获得、营地修复。

否则战斗可以单独跑通，但玩家无法形成完整肉鸽循环，UI 也会缺少页面级信息架构。
