# Boss 节点设计：裂心钟主

> 日期：2026-06-04  
> 状态：Demo 可用执行规格  
> 依赖：[defense_roguelite_core_design.md](defense_roguelite_core_design.md)、[battle_objectives_and_rewards.md](battle_objectives_and_rewards.md)、[run_structure_design.md](run_structure_design.md)、[enemy_map_encounter_design.md](enemy_map_encounter_design.md)

## 1. 目的

本文档替代旧 Boss 击杀胜利模型，给 Demo 终局节点提供可实现配置。

Boss 是公开脚本压力源，不是需要击杀的大血条。Boss 战仍然遵守标准防守胜利：

1. 撑到 `max_rounds` 结束。
2. 至少 1 名守卫者存活。
3. Boss 毁灭计数没有达到溃败阈值。

击破锚石、打击心脏钟或压制 Boss 行动只能降低压力、完成奖励任务、改变章节奖励，不能提前结束战斗。

## 2. Demo 节点基准

| 项 | 规则 |
|---|---|
| 节点 ID | `boss_outer_bell_01` |
| 节点名 | 钟楼外环 |
| 战斗回合 | 6 |
| 裂隙强度 | 2 |
| 初始守护值预期 | Boss 前普通玩家剩余 5-8 |
| 保护目标 | 3 个普通建筑，1 个关键建筑 |
| Boss 毁灭计数 | 初始 0，上限 3 |
| 敌人预算 | 总敌人 12-16 个 |
| 硬威胁上限 | 每回合最多 3 个 |
| 基础奖励 | 14 余烬，Demo 进入通关结算 |

Demo Boss 不做无限回合，不做击杀胜利，不做杂兵刷余烬。

## 3. 棋盘对象

### 3.1 盘外 Boss

裂心钟主本体在棋盘外，只作为 UI 和脚本来源存在。玩家不能直接点击 Boss 本体。

Boss 必须在 HUD 中展示：

- 当前 Boss 脚本行动。
- 下一次 Boss 行动预告。
- 毁灭计数 `0 / 3`。
- 锚石 HP。
- 心脏钟暴露状态和已命中次数。

### 3.2 锚石

| 项 | 规则 |
|---|---|
| 数量 | 2 |
| HP | 2 |
| 是否占格 | 是 |
| 是否阻挡寻路 | 是 |
| 是否阻挡推动链 | 是 |
| 是否可推动 | 否 |
| 是否获得碎裂 | 否 |
| 被攻击 | 玩家攻击命中 -1 HP；被单位撞击 -1 HP |
| 被摧毁结果 | 移除占格，记录 `anchor_destroyed_count +1` |

锚石是压制目标，不是胜利目标。摧毁锚石会降低 Boss 压力，并可能打开心脏钟暴露窗口。

### 3.3 心脏钟

心脏钟是盘内弱点格，只在锚石全部被摧毁后暴露。

| 项 | 规则 |
|---|---|
| 默认状态 | 封闭，不可攻击 |
| 暴露条件 | 2 个锚石全部摧毁 |
| 暴露时长 | 当前回合剩余时间 + 下一整个玩家回合 |
| 命中方式 | 任意守卫者合法攻击命中，或敌人被推撞到心脏钟 |
| 命中收益 | `heart_hits +1`，最多记录 3 次 |
| 是否提前胜利 | 否 |

心脏钟命中收益：

| 命中次数 | 效果 |
|---:|---|
| 1 | 下一次锚链脉冲降级 |
| 2 | 若毁灭计数大于 0，结算时毁灭计数 -1 |
| 3 | 完成“暴露窗口”奖励任务，终局钟鸣降级 |

这些效果必须在预演和 HUD 中显示，不能隐藏到结算页才告诉玩家。

## 4. 毁灭计数

毁灭计数代表 Boss 正在撕开防线。它不是守护值，但会导致本场 Boss 溃败。

| 项 | 规则 |
|---|---|
| 初始值 | 0 |
| 上限 | 3 |
| 达到上限 | Boss 溃败，本场提前结束；守护值只按本场保护目标累计受伤或战前公开的 Boss 代价扣减 |
| Run 失败检查 | 守护值扣到 0 时 Run 失败 |
| 可逆转 | 心脏钟第 2 次命中可以在结算时 -1 |

毁灭计数增长必须来自公开意图。每次可能增长前，UI 必须显示：

- 哪个回合会增长。
- 增长条件是什么。
- 玩家能通过摧毁锚石、命中心脏钟、位移或防守动作如何阻止。

## 5. 6 回合脚本

| 回合 | Boss 行动 | 公开压力 | 反制方式 | 未反制结果 |
|---:|---|---|---|---|
| 1 | 静默开场 | 展示第 2 回合横扫线，生成软威胁 | 处理初始敌人，靠近锚石 | 无毁灭计数 |
| 2 | 横扫钟波 | 1 行或 1 列预警，非建筑单位受 1 伤并推 2 格 | 离开线、推走敌人、利用撞击 | 造成单位损伤和位移事故 |
| 3 | 召唤潮 | 所有已预告裂隙提前出怪；若 2 个锚石都存活，回合末毁灭 +1 | 摧毁至少 1 个锚石，或用遗物延迟裂隙 | 毁灭 +1，裂隙出怪 |
| 4 | 锚链脉冲 | 存活锚石周围敌人移动力 +1 | 摧毁锚石、推离敌人、挡线 | 下回合硬威胁增加 |
| 5 | 丧钟指名 | 指定关键建筑；若至少 1 个锚石存活，回合末毁灭 +1，关键建筑受 1 伤 | 摧毁全部锚石，保护关键建筑 | 毁灭 +1，关键建筑受伤 |
| 6 | 终局钟鸣 | 若心脏钟命中少于 1 次，结算前毁灭 +1 | 在暴露窗口命中心脏钟，或用遗物降级终局钟鸣 | 毁灭 +1 后进入终局检查 |

第 6 回合结束后进行标准胜利检查。只要至少 1 名守卫者存活，且毁灭计数小于 3，Boss 战胜利。

## 6. 敌群预算

Demo 推荐配置：

| 来源 | 数量 | 说明 |
|---|---:|---|
| 初始敌人 | 3-4 | 腐食兽 2，瘟疫弓手 1，按难度加 1 |
| 裂隙出怪 | 4-5 | 分布在第 2-5 回合 |
| Boss 脚本出怪 | 5-7 | 召唤潮和终局前压力 |
| 总敌人 | 12-16 | Boss 召唤杂兵不给击杀余烬 |

第 1 章 Demo Boss 不建议同时使用铁角兽、裂隙司祭和长线弓手满配组合。Boss 脚本已经提供硬威胁，敌群只需要补建筑压力和挡路压力。

## 7. 奖励任务

Boss 战从以下任务中选 3 个：

| 任务 | 条件 | 奖励意图 |
|---|---|---|
| 钟鸣压制 | 毁灭计数从未增长 | 高水平防守 |
| 锚石破坏 | 第 5 回合结束前摧毁全部锚石 | 鼓励主动压制 |
| 暴露窗口 | 心脏钟累计命中 3 次 | 鼓励集中火力 |
| 完美守夜 | 没有保护目标被毁 | 高难保护 |
| 全员存活 | 3 名守卫者都存活 | 控制伤亡 |
| 终局清场 | 第 6 回合结束时场上无敌人 | 把清怪转为额外目标 |

Demo 默认任务组合：

1. 锚石破坏。
2. 暴露窗口。
3. 完美守夜。

这组任务把 Boss 压制目标、心脏钟窗口和建筑保护都放进 Demo 验收，便于验证终局 Boss 的完整交互链。

## 8. 失败和重试

| 情况 | 结果 |
|---|---|
| 所有守卫者死亡 | Run 立即失败 |
| 所有保护目标被毁 | 防线溃败；只按本场保护目标累计受伤扣守护值 |
| 毁灭计数达到 3 | Boss 溃败；守护值只按保护目标累计受伤或战前公开的 Boss 代价扣减 |
| 守护值扣到 0 | Run 失败 |
| Boss 溃败后守护值仍大于 0 | 回到同一 Boss 节点预览，可重试 |

Boss 重试不发奖励，不标记章节完成，守卫者死亡和 HP 损耗保留。

## 9. UI 必显信息

Boss 战 UI 不能把 Boss 当成普通敌人血条展示。

必须展示：

- 主目标：撑到第 6 回合结束。
- Boss 毁灭计数：`0 / 3`。
- 本回合 Boss 行动和下回合 Boss 行动。
- 锚石 HP 和位置。
- 心脏钟是否暴露、剩余暴露时间、命中次数。
- 本场预计守护值损失。
- 3 个 Boss 奖励任务进度。

当前 Demo 实现使用顶部目标摘要承载主目标、预计守护值损失和短状态；右侧独立 Boss 状态区承载本轮 / 下一轮脚本、Doom、锚石 HP、心脏钟暴露窗口和命中奖励效果。Boss Doom 增减、锚石受损 / 破坏、心脏钟命中会刷新战斗提示文本。

禁止展示：

- “击杀 Boss 即胜利”。
- “清空敌人即胜利”。
- “锚石全毁即胜利”。
- 没有解释的 Boss 大血条。

## 10. 配置字段建议

```text
boss_config_id: "knell_lord_demo_01"
max_rounds: 6
doom_count_initial: 0
doom_count_max: 3
anchor_count: 2
anchor_hp: 2
heart_hit_cap: 3
heart_exposure_rounds: 1
boss_script_id: "knell_lord_demo_six_round"
boss_reward_task_pool: ["anchor_break", "perfect_watch", "all_wardens_alive", "doom_suppressed", "heart_window", "final_clear"]
boss_summon_kill_embers: 0
```

这些字段只描述 Boss 节点本身。守护值、守卫者 HP、奖励写回和重试流程仍以 Run 与奖励文档为准。
