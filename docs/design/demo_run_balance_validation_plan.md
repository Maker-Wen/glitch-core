# Demo Run 数值验证与平衡设计方案

> 日期：2026-06-06
> 状态：第一轮审查建议
> 范围：当前 Demo Run 的数据、配置、奖励与验证方案
> 约束：本文档不修改代码，不直接改数值，只给出审查结论和调参建议。

## 1. 结论摘要

当前 Demo Run 已经具备可验证的数值闭环：3 名守卫者、4 个战斗节点、1 个事件、1 个营地、守护值、跨战斗守卫者 HP、基础奖励、奖励任务、遗物领取、升级写回和 Boss Doom 链路都已接入。

第一轮平衡风险集中在 4 个地方：

1. 奖励任务阈值与设计文档不一致，部分任务当前过易，部分任务当前过严。
2. 普通战现在会稳定生成升级选择，且升级是 `HP Max +1 + 治疗 1`，会显著削弱跨战斗 HP 压力。
3. 遗物当前是 `data_only`，可以领取但战斗内不触发，因此还不能验证遗物强度。
4. Boss 默认任务包含 `heart_window` 的 3 次心脏钟命中，当前 1 技能制下需要重点验证是否稳定可达。

本轮建议优先验证“能否稳定过关”和“奖励是否过快滚雪球”，暂不急于扩展新数值池。

## 3. 每类数值的验证目标

### 3.1 守卫者与行动数

验证目标：

1. 每名守卫者单次行动默认解决 1 条硬威胁。
2. 3 名守卫者一回合合计通常能处理 2-3 条硬威胁，但不能稳定处理 4 条以上。
3. 三名当前守卫者贡献不同：赏金猎人负责近战和坠渊，盗墓人负责拉线，大魔法师负责远程推线。
4. HP 2 的守卫者在 4 个战斗节点中会产生濒死压力，但不会因单个小失误频繁永久死亡。

建议指标：

| 指标 | 目标区间 |
|---|---|
| 每场守卫者平均受伤 | 普通战 0-1，精英战 1-2，Boss 战 1-3 |
| 每场守卫者死亡率 | 普通战接近 0，精英 / Boss 允许偶发 |
| 单回合未使用行动数 | 高手可保留，普通玩家多数回合用满 |
| 三名守卫者行动占比 | 不应长期低于 20% 或高于 45% |

### 3.2 敌人强度与硬威胁

验证目标：

1. 普通战每回合硬威胁不超过 2 个。
2. 精英战和 Boss 战每回合硬威胁不超过 3 个。
3. 硬威胁超过行动数时，必须有地图机制或牺牲策略可接受。
4. 铁角兽、护壳虫、钟奴等专属敌人应制造新题型，而不是单纯堆血。

建议指标：

| 指标 | 目标区间 |
|---|---|
| 当前回合硬威胁数 | 普通 <= 2，精英 / Boss <= 3 |
| 同回合建筑受伤预期 | 普通 0-1，精英 / Boss 可到 2 但必须可预演 |
| 敌人终局存活数 | 普通 0-2，Boss 0-3 |
| 敌人因物理死亡占比 | 至少能被玩家稳定触发，不要求每场都高 |

### 3.3 地图、保护目标与守护值

验证目标：

1. 普通建筑 HP 2 提供 1 次救援窗口。
2. 关键建筑 HP 3 在精英和 Boss 战中形成局部重点，但不能变成单点失败。
3. 守护值 12 能承接多场战斗中的 4-6 点建筑伤害。
4. Demo Boss 前普通玩家预期剩余守护值应落在 5-8。

建议指标：

| 指标 | 目标区间 |
|---|---|
| Boss 前守护值 | 普通玩家 5-8，高手 9-12 |
| 单场建筑受伤点数 | 普通 0-2，精英 1-3，Boss 2-4 |
| 防线溃败率 | 普通战极低，Boss 战允许作为明确失败 |
| 营地选择分布 | 治疗和修复都应有真实使用场景 |

### 3.4 奖励任务

验证目标：

1. 完成 0 项代表失败或只保主线。
2. 完成 1 项代表普通玩家达标。
3. 完成 2 项代表熟练玩家获得构筑加速。
4. 完成 3 项代表高水平目标，不应在第一轮路线中稳定白给。

建议指标：

| 指标 | 目标区间 |
|---|---|
| 普通战平均完成任务数 | 1-2 |
| 精英战平均完成任务数 | 1 左右 |
| Boss 战平均完成任务数 | 0-2 |
| 高手 3 任务完成率 | 可高，但应依赖明确操作 |

### 3.5 余烬、升级与遗物经济

验证目标：

1. 余烬收入能解释奖励价值，但当前 Demo 缺少消费节点，不能完整验证价格。
2. 普通战升级不应让 HP 压力过早消失。
3. 精英遗物应让玩家感到构筑变化，但当前战斗内 hook 未接入，暂不验证遗物强度。
4. 跳过补偿 +3 余烬不能比正常奖励更优。

建议指标：

| 指标 | 目标区间 |
|---|---|
| Boss 前余烬 | 当前只能记录收入，暂不评价购买力 |
| Boss 前升级数 | 建议验证 0、1、2、3 个升级状态 |
| 精英遗物选择率 | 在效果接入前只验证 UI 和过滤 |
| 恢复机会触发次数 | 每章最多 1 次，且玩家能理解是否已消耗 |

### 3.6 Boss 节点

验证目标：

1. 第 3 回合前摧毁 1 个锚石应是高手目标，不是唯一生路。
2. 第 5 回合前摧毁全部锚石应可达，但要牺牲其他收益或防守压力。
3. 心脏钟至少命中 1 次应是主线压制目标。
4. 心脏钟 3 次命中应是奖励目标，不应成为默认完成项。

建议指标：

| 指标 | 目标区间 |
|---|---|
| Boss 胜利时 Doom | 0-2 |
| 锚石全毁率 | 熟练玩家可稳定，高压玩家不稳定 |
| 心脏钟 1 次命中率 | 大多数胜利局可达 |
| 心脏钟 3 次命中率 | 高手目标 |
| Boss 溃败率 | 普通玩家可见但不应压倒性 |

| S08 | 裂缝庭院低损防线 | 同 S06 | `low_loss_line <= 1` 的难度 | 如果 1 点建筑伤害后仍可完成，2 点立刻失败，需要 UI 清楚 |
| S09 | 铁角闸门正常路线 | Boss 前未升级或 1 升级 | 精英敌人组合是否可解 | 关键建筑应可守住，但需要牺牲一部分任务 |
| S10 | 铁角闸门双铁角压力 | 触发第 4 回合铁角兽 | 同场第 2 只铁角兽是否过载 | 第 4 回合硬威胁不应超过 3 |
| S11 | 铁角闸门关键目标压力 | 关键建筑 HP 3 | `key_target_undamaged` 是否合理 | 受 1 伤即失败，但不应导致主线失败 |
| S12 | 营地治疗选择 | 至少 1 名守卫者 HP 1 | 跨战斗 HP 压力 | 治疗小队应明显有价值 |
| S13 | 营地修复选择 | 守护值 5-8 | 守护值压力 | 修复 +2 应能改变 Boss 入场容错 |
| S14 | Boss 不打锚石 | 3 人，守护值 5-12 | Doom 脚本基础失败路径 | 第 3、5、6 回合 Doom 会接近或达到上限 |
| S15 | Boss 只破 1 锚石 | 同 S14 | 第 3 回合压制目标 | 第 3 回合 Doom 应被压制，第 5 回合仍有压力 |
| S16 | Boss 全破锚石 | 同 S14 | 锚石 HP 2 x2 的行动成本 | 可达但应牺牲部分防守或清怪 |
| S17 | Boss 心脏钟 1 命中 | 全破锚石后 | 主线压制第 6 回合 Doom | 1 命中应明显降低失败风险 |
| S18 | Boss 心脏钟 3 命中 | 全破锚石后 | `heart_window` 奖励可达性 | 应是高水平目标，不应多数路线自动完成 |
| S19 | 残编进入 Boss | 1-2 名守卫者存活 | 残编不可自动降难的风险 | 应明显更难，但仍能解释失败原因 |
| S20 | 2 个普通战都拿升级 | 两个普通战均领取 HP 升级 | 升级滚雪球风险 | Boss 前 HP Max 提升可能显著降低死亡压力 |
| S21 | 精英遗物领取 | 精英胜利后任意遗物 | 遗物数据与过滤 | 只能验证选择和写回，不能评价战斗强度 |
| S22 | 奖励恢复满值转化 | 守护值 12，普通战 3 任务 | 恢复机会转 +3 且消耗本章槽 | 需要确认玩家是否理解“满值也消耗槽” |

## 5. 当前高风险数值点

### 5.1 奖励任务阈值不一致

当前 `push_threat` 是 1 次敌方攻击落空即完成，而设计文档写的是 4 次。当前 `rift_suppression` 是 1 次延迟即完成，而设计文档写的是 2 次。它们会提高普通战完成 2-3 项任务的概率，并放大额外余烬、奖励选项 +1 和守护值恢复机会。

相反，`low_loss_line` 当前是建筑总受伤 <= 1，设计文档写的是 <= 2。这个任务在钟奴裂痕、铁角冲撞或多建筑受伤场景下可能比文档预期更严。

### 5.2 普通战升级过早进入

当前普通战会直接生成升级选项，且完成 2 个任务后展示 3 个。设计文档更接近“每 2 场普通战后出现 1 次成长奖励”。如果两场普通战都领取升级，Boss 前可能出现 2-3 名守卫者 `HP Max 3` 的状态，跨战斗 HP 压力会被明显削弱。

### 5.3 当前升级是纯 HP 整备

当前升级统一为 `最大 HP +1，并立即治疗 1 点`。这有两个风险：

1. 它不像设计目标中的动词增强，不能帮助验证推拉、范围、裂隙或建筑防守构筑。
2. 它会直接提高生存和治疗上限，导致“营地治疗”和“守卫者死亡压力”更难评估。

### 5.4 遗物无法进入战斗验证

遗物池已经数据化，但 `effect_ops.status` 仍是 `data_only`。因此精英战和 Boss 章节奖励目前只验证 UI、过滤和写回，不能验证遗物是否破坏战斗压力。

### 5.5 Boss 默认任务可能过硬

Boss 默认任务是锚石破坏、暴露窗口、完美守夜。其中 `heart_window` 需要心脏钟 3 次命中。当前只有 1 技能制，摧毁 2 个 HP 2 锚石至少需要 4 次有效伤害，之后还要 3 次心脏钟命中。该任务可能成为“理论可达但实战过窄”的高风险目标。

### 5.6 Boss 第 3 回合压力需要单独审查

Boss 第 3 回合会同时出现：

- 若 2 个锚石都存活，Doom +1。
- Boss 脚本刷 2 个腐食兽。
- 顶部裂隙刷 1 个腐食兽。
- 既有敌群可能仍在场。

虽然总敌人数在预算内，但第 3 回合可能形成敌群 + Doom 的峰值。需要按硬威胁数而不是总敌人数验证。

### 5.7 腐化代价当前不可验证

事件“拆取透镜”给 +9 余烬和腐化 +1，但当前腐化阈值尚未改写战斗配置。该选项在当前 Demo 中更接近无痛收益，不能用于判断风险经济是否成立。

### 5.8 满守护值转化会消耗章节恢复槽

当前普通 / 精英战完成 3 任务且守护值已满时，恢复机会转化为 +3 余烬，并在领取后标记 `chapter_guardian_reward_used = true`。这符合“每章只触发一次”的实现逻辑，但体验上可能让玩家困惑：完美防守反而提前消耗了后续真实恢复机会。

## 6. 第一轮调参建议

### 6.1 先做验证口径统一，不急着大改数值

第一轮应先决定当前任务阈值是“Demo 降低门槛”还是“实现偏差”。建议至少在评审中明确：

| 任务 | 建议第一轮口径 |
|---|---|
| 推离威胁 | Demo 可先验证 2 次目标；如果仍稳定完成，再回到设计的 4 次 |
| 裂隙压制 | 建议验证 2 次目标，因为当前裂缝庭院有 3 次裂隙 schedule |
| 低损防线 | 建议先按设计恢复为 <= 2 的验证目标，再观察是否过宽 |

本文不直接改数值，只建议把这 3 个任务列为第一轮人工和自动化对照项。

### 6.2 限制普通战升级滚雪球

建议第一轮对比 3 种路线：

1. 普通战都不拿升级。
2. 只在第 2 个普通战后拿 1 个升级。
3. 当前实现下两个普通战都可拿升级。

如果第 3 种路线显著降低 Boss 死亡风险，应考虑把普通战升级改成“固定路线只出现 1 次”或“普通战 2 任务以上才出现升级选择”。

### 6.3 将当前 HP 升级标记为整备奖励

在设计判断上，当前 `HP Max +1 + 治疗 1` 更像整备奖励，不像守卫者技能升级。第一轮建议不要用它代表完整升级系统强度。真正要验证角色构筑时，应至少接入 1-2 个会改变推拉、范围、裂隙或建筑防守的升级。

### 6.4 Boss 先分层验收

Boss 不建议只看胜负，应拆成 4 层目标：

1. 撑到第 6 回合并 Doom 未满。
2. 第 5 回合前摧毁全部锚石。
3. 心脏钟至少命中 1 次。
4. 心脏钟命中 3 次并完成 `heart_window`。

如果第 1 层和第 2 层都稳定，第 4 层可以保持高难。若第 2 层已经不稳定，则不要急着调 `heart_window`，先调敌群峰值或锚石可达性。

### 6.5 腐化暂不参与平衡结论

在腐化阈值未接入战斗配置前，不建议评价“+9 余烬、腐化 +1”的真实代价。当前只能验证事件 UI 和资源写回。第一轮报告里应把腐化标成“经济数据可记录，风险效果未生效”。

### 6.6 遗物只验证奖励链路，不验证强度

当前遗物不触发战斗效果。第一轮建议只验证：

- 遗物池过滤是否正确。
- 已拥有唯一遗物是否不重复。
- 死亡守卫者绑定遗物是否被过滤。
- 精英和 Boss 奖励展示数量是否符合任务完成数。

遗物强度、遗物组合和战斗破坏性应等 hook 接入后另开一轮验证。

## 7. 自动化模拟与埋点支持需求

### 7.1 自动化模拟

需要补充一个 Demo Run 验证器，目标不是替代人工试玩，而是快速发现不可解或过易的数值组合。

建议模拟能力：

| 能力 | 用途 |
|---|---|
| 枚举当前合法移动 / 攻击 | 判断是否存在可解路径 |
| 使用 `preview_action()` 评估行动后意图 | 计算本行动减少了多少硬威胁 |
| 贪心策略：优先阻止建筑伤害 | 得到普通玩家近似结果 |
| 贪心策略：优先完成奖励任务 | 得到高手目标近似结果 |
| Boss 专用策略：优先锚石和心脏钟 | 验证 Boss 压制链路 |
| 路线级模拟 | 验证守护值、守卫者 HP、奖励和营地选择的连续影响 |

第一版不需要复杂 AI，只要能跑固定配置并输出每轮压力、行动、损耗和奖励结果即可。

### 7.2 配置静态检查

建议增加配置 lint，运行时不进入战斗也能发现预算问题。

检查项：

1. 每个战斗节点的初始敌人、脚本出怪、裂隙出怪总量是否落在预算内。
2. 普通战、精英战、Boss 战的裂隙强度是否符合节点类型。
3. 同一回合是否同时生成过多铁角兽、远程线压和 Boss Doom 条件。
4. 奖励任务是否在当前实现中有计数来源。
5. 配置任务阈值是否与设计文档目标一致。
6. Boss 锚石、心脏钟和保护目标坐标是否可达、可攻击、不会互相阻断。

### 7.3 战斗埋点

建议每场战斗记录以下字段：

| 字段 | 用途 |
|---|---|
| `node_id`、`config_id`、`map_id` | 聚合不同节点结果 |
| `round`、`phase` | 定位压力峰值 |
| 当前敌人数、敌人类型分布 | 验证预算 |
| 当前硬威胁数 | 验证行动数是否足够 |
| 预计建筑伤害、预计守卫者伤害 | 衡量意图压力 |
| 玩家每次行动的 actor、action、target | 分析角色贡献 |
| 行动后被打断的敌方意图数 | 验证 `push_threat` |
| 物理击杀、坠渊、撞墙、撞单位次数 | 验证物理解法 |
| 地裂预告、出怪、被占据延迟次数 | 验证裂隙压制 |
| 建筑受伤、建筑被毁、守护值损失 | 验证防线压力 |
| 守卫者受伤、濒死、死亡 | 验证 HP 经济 |
| 奖励任务进度、完成、失败原因 | 验证任务阈值 |

### 7.4 Run 级埋点

建议每个节点结束时记录：

| 字段 | 用途 |
|---|---|
| 节点前后守护值 | 验证 Run 弹性 |
| 节点前后守卫者 HP | 验证跨战斗损耗 |
| 奖励任务完成数量 | 验证奖励梯度 |
| 固定余烬、奖励余烬、心脏钟余烬 | 验证收入 |
| 选择的奖励 option_id | 验证升级 / 遗物偏好 |
| 事件 choice_id | 验证事件取舍 |
| 营地 choice_id | 验证治疗和修复价值 |
| Boss Doom、锚石、心脏钟数据 | 验证终局链路 |

### 7.5 关键分析报表

第一轮需要 6 张报表即可：

1. 每节点胜率、失败原因和平均守护值损失。
2. 每节点平均奖励任务完成数。
3. 每回合硬威胁峰值。
4. 守卫者 HP 轨迹和死亡分布。
5. Boss Doom / 锚石 / 心脏钟完成漏斗。
6. 奖励选择和最终资源分布。

## 8. 第一轮验收标准

第一轮 Demo Run 平衡可以按以下标准判断是否进入下一轮：

| 项 | 通过标准 |
|---|---|
| 主线可通 | 熟悉规则的玩家可以稳定打到 Boss，并有合理胜率 |
| 普通战压力 | 普通战多数回合有取舍，但不因单次失误崩盘 |
| 精英战压力 | 至少 1 个任务经常失败，胜利和完美之间有差距 |
| Boss 压力 | Doom、锚石、心脏钟三条线都能被玩家理解 |
| 奖励梯度 | 1、2、3 任务完成的奖励差异能被感知 |
| Run 损耗 | Boss 前守护值和守卫者 HP 有明显但不绝望的损耗 |
| 数据一致性 | 当前实现阈值和设计目标的差异已被记录并有决策 |

## 9. 下一轮建议工作顺序

1. 先跑人工矩阵 S01-S22，记录是否出现不可解或稳定白给。
2. 再做静态配置 lint，确认总敌人数和硬威胁峰值。
3. 接入最小模拟器，优先覆盖断墙前哨、裂缝庭院、铁角闸门和 Boss 四张图。
4. 决定奖励任务阈值是按 Demo 特调还是回到设计目标。
5. 决定普通战升级出现频率，避免 HP 升级过早吃掉压力。
6. 等遗物 hook 接入后，再单独做遗物强度和构筑流派验证。
