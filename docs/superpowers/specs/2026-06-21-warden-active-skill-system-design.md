# 守卫者主动技能系统设计

> 日期：2026-06-21  
> 状态：设计已确认，待实现  
> 范围：接入现有 3 名守卫者的 9 个主动技能；不包含升级、遗物、敌方技能资源化或新增美术动画。

## 1. 背景

当前战斗代码已经有技能栏 UI、行动预览、事件动画、敌人意图和物理结算，但守卫者实战仍是每名角色 1 个基础攻击。技能栏中的第 2、3 个按钮只是禁用占位，无法产生合法目标、预览或战斗效果。

设计文档已经定案为 3 技能制：每名守卫者固定携带 3 个主动技能，移动和待命不占技能槽。当前实现需要先把这个玩家可见的三技能制跑通，再考虑升级和遗物改写。

## 2. 目标

1. 现有 3 名守卫者拥有 9 个可执行主动技能。
2. 每个技能支持合法目标高亮、点击执行、预览和 Undo。
3. 技能使用后该守卫者本回合行动结束，保持“先移动再行动”的当前节奏。
4. 主技能替代现有 `BattleAction.attack()` 的玩家入口，同时保留 `attack()` 兼容现有测试和内部调用。
5. 新增状态字段必须能被 `BattleState.clone()` 正确复制，保证预览无副作用。
6. 第一版只实现基础技能数值，不接升级、遗物、动态技能强化文案。

## 3. 非目标

1. 不新增 `.tres` 技能资源和效果 DSL。
2. 不实现角色升级、遗物、强化后的技能文案改写。
3. 不新增复杂技能动画。表现层优先复用现有事件和棋盘标记。
4. 不重做敌人 AI。只在法阵减速和新增状态影响敌方移动规划时做必要接入。
5. 不修改固定路线地图和敌人配置，除非技能状态需要读取现有地裂、建筑和 Boss 数据。

## 4. 设计原则

1. 技能合法性以 `BattleEngine` 为唯一来源，UI 不重复写规则。
2. 预览沿用 `BattleEngine.preview_action()` 的 clone 机制，不单独维护预测状态。
3. 所有自动选择必须确定性，例如反手抛侧推方向使用固定顺序。
4. 防守技能必须有清楚上限，避免直接吃掉建筑压力。
5. 新状态必须能在回合开始、敌方执行、战斗结束时自然衰减或清理。

## 5. 架构

### 5.1 行动模型

`BattleAction` 增加：

| 字段或类型 | 用途 |
|---|---|
| `Kind.SKILL` | 玩家主动技能行动 |
| `skill_id: StringName` | 技能 ID |
| `BattleAction.skill(actor_id, skill_id, target_pos)` | 构造技能行动 |

现有 `BattleAction.attack(actor_id, target_pos)` 保留，内部行为等价于当前守卫者的主技能：

| 守卫者 | `attack()` 映射 |
|---|---|
| 赏金猎人 | `bounty_chain_strike` |
| 盗墓人 | `graverobber_hook_rope` |
| 大魔法师 | `mage_repulsion_bolt` |

这样可以减少已有测试和预览调用的迁移成本。

### 5.2 技能目录

新增轻量代码表 `scripts/battle/warden_skill_catalog.gd`，职责是提供技能元数据，不直接改状态。

建议接口：

```gdscript
static func skills_for_warden(def_id: StringName) -> Array[Dictionary]
static func get_skill(skill_id: StringName) -> Dictionary
static func primary_skill_id_for_warden(def_id: StringName) -> StringName
```

技能元数据包含：

| 字段 | 用途 |
|---|---|
| `id` | 技能 ID |
| `name` | UI 名称 |
| `desc` | 当前基础效果短描述 |
| `slot` | 0、1、2 |
| `target_rule` | 引擎选择目标时使用的规则标签 |
| `max_uses_per_battle` | 每场次数，0 表示不限 |

### 5.3 战斗引擎

`BattleEngine` 增加以下能力：

| 接口 | 用途 |
|---|---|
| `get_legal_skill_targets(unit_id, skill_id)` | 返回某技能合法目标 |
| `get_legal_skill_targets_for_selected(unit_id)` | 可选辅助，返回 `{skill_id: cells}` |
| `_do_skill(state, action)` | 校验并执行技能 |
| `_resolve_skill_*()` | 各技能的显式结算函数 |

现有 `get_legal_attack_targets()` 保留，结果等价于主技能合法目标。

### 5.4 战斗状态

`BattleState` 增加状态：

| 字段 | 用途 |
|---|---|
| `skill_uses: Dictionary` | 每场技能使用次数，key 建议为 `"unit_id:skill_id"` |
| `protected_shields: Dictionary` | 保护建筑临时护盾，key 为 `Vector2i` |
| `sigils: Array[Dictionary]` | 法阵状态，包含 `pos`、`owner_id`、`remaining_rounds` |
| `bounty_executes: Dictionary` | 悬赏处决进度，key 为 `unit_id` |

这些字段必须在 `clone()` 中深拷贝。战斗开始时为空；无需写入 Run 存档，因为当前战斗结束即失效。

## 6. 技能定义

### 6.1 赏金猎人

| 技能 ID | 名称 | 目标 | 效果 | 限制 |
|---|---|---|---|---|
| `bounty_chain_strike` | 链锤击 | 相邻敌人 / Boss 锚石 / 暴露心脏钟 | 1 伤，推 1；攻击 Boss 部件时只造成 1 伤 | 不限次数 |
| `bounty_guard_shoulder` | 护卫肩撞 | 相邻单位 | 与目标换位；若目标是敌人，造成 1 伤，不推 | 不限次数 |
| `bounty_execute` | 悬赏处决 | 相邻敌人 | 造成 1 伤；若本技能直接击杀目标，悬赏进度 +1 | 每场 2 次 |

悬赏处决第一版只认“本技能直接伤害导致死亡”。不认后续撞墙、坠落、连锁或环境伤害，避免“不推却要求撞毁”的语义冲突。

### 6.2 盗墓人

| 技能 ID | 名称 | 目标 | 效果 | 限制 |
|---|---|---|---|---|
| `graverobber_hook_rope` | 倒钩索 | 直线 3 格第一个敌人 / Boss 锚石 / 暴露心脏钟 | 1 伤，向自己拉 1；攻击 Boss 部件时只造成 1 伤 | 不限次数 |
| `graverobber_rift_wedge` | 裂隙楔 | 3 格内地裂 | 延迟该地裂下一次出怪 1 回合；若地裂上有敌人，先造成 1 伤 | 不限次数 |
| `graverobber_backhand_throw` | 反手抛 | 直线 2 格第一个敌人 | 先向自己拉 1；若目标到达相邻且侧向有空格，自动侧推 1 | 不限次数 |

反手抛侧推方向固定为：以盗墓人到目标的方向为前方，优先左手侧，再右手侧。两侧都不可用时只执行拉 1。

裂隙楔的延迟规则：找到 `pending_rift_spawns` 或 `rift_schedule` 中目标地裂的下一次出怪，把对应 round 推迟 1 回合。若目标地裂当前已有 pending 出怪，则优先推迟 pending 出怪；否则推迟后续 schedule 中最早一次。

### 6.3 大魔法师

| 技能 ID | 名称 | 目标 | 效果 | 限制 |
|---|---|---|---|---|
| `mage_repulsion_bolt` | 斥力弹 | 直线 3 格第一个敌人 / Boss 锚石 / 暴露心脏钟 | 1 伤，向远离自己方向推 1；攻击 Boss 部件时只造成 1 伤 | 不限次数 |
| `mage_ward_fire` | 护火 | 2 格内保护建筑 | 若受损，恢复 1 HP，不超过初始 HP；若满血，给 1 次临时护盾 | 不限次数 |
| `mage_sigil` | 法阵 | 3 格内空地 | 放置持续 2 回合的法阵；敌人规划移动时触碰法阵，本次移动 -1 | 每场 2 次 |

护火护盾不叠加。护盾只抵消下一次敌方攻击阶段中该建筑受到的 1 点伤害；如果没有触发，在本次敌方攻击阶段结束后过期。

法阵不叠加，不造成伤害。触碰定义为敌人本次规划路径的起点、途经格或终点包含法阵格。多个法阵同时命中同一个敌人时，仍只减 1 移动。

## 7. 目标规则

### 7.1 单位目标

| 规则 | 合法目标 |
|---|---|
| `adjacent_enemy_or_boss` | 相邻敌人、Boss 锚石、暴露心脏钟 |
| `adjacent_unit` | 相邻任意活单位 |
| `line_enemy_or_boss_range_3` | 四向直线 3 格内首个敌人、Boss 锚石、暴露心脏钟 |
| `line_enemy_range_2` | 四向直线 2 格内首个敌人 |

直线技能沿用当前远程攻击规则：阻挡地形和任意单位会挡线；UI 只暴露第一个可命中目标。

### 7.2 地裂目标

裂隙楔合法目标：

1. 目标格是 `Grid.TileType.RIFT`。
2. 与盗墓人曼哈顿距离不超过 3。
3. 目标格存在下一次 pending 或 schedule 出怪，或者目标格上有敌人。

如果地裂没有可延迟出怪且没有敌人，不能作为目标，避免空放。

### 7.3 建筑目标

护火合法目标：

1. 目标格是存活保护建筑。
2. 与大魔法师曼哈顿距离不超过 2。
3. 建筑受损，或建筑满血但没有护盾。

满血且已有护盾的建筑不能继续作为目标，避免浪费行动和误导玩家。

### 7.4 空地目标

法阵合法目标：

1. 目标格在棋盘内。
2. 与大魔法师曼哈顿距离不超过 3。
3. 目标格不是阻挡地形、不是建筑、不是 Boss 部件、不是地裂。
4. 目标格没有单位。
5. 目标格没有现存法阵。

## 8. 效果结算

### 8.1 伤害和位移

主技能继续复用 `PhysicsResolver.resolve_attack()`，保持撞墙、撞单位、坠落、护壳虫减推力等既有规则。

护卫肩撞和悬赏处决是直接伤害技能，不触发推拉。若目标死亡，仍按现有 `UNIT_DAMAGED`、`UNIT_DIED`、`UNIT_REMOVED` 事件顺序处理。

反手抛分两段结算：

1. 使用 `resolve_attack()` 拉 1。
2. 读取目标结算后的当前位置；如果仍存活且与盗墓人相邻，检查左手侧和右手侧空格。
3. 若找到侧向空格，执行一次强制位移，产生 `UNIT_PUSHED` 事件。

### 8.2 建筑恢复和护盾

护火恢复建筑时产生 `TILE_DAMAGED` 的负数会让现有表现语义混乱，因此新增事件类型更清晰：

| 事件 | 用途 |
|---|---|
| `TILE_REPAIRED` | 建筑 HP 增加 |
| `TILE_SHIELDED` | 建筑获得护盾 |

如果希望第一版少改表现层，也可以用 `BattleEvent.extra` 标记，但设计上推荐新增事件，避免后续 UI 难以区分受伤和恢复。

敌方攻击建筑时，伤害流程调整为：

1. 先计算钟奴裂痕等伤害修正。
2. 若目标有护盾，最终伤害减少 1，最低为 0，并消费护盾。
3. 实际伤害大于 0 时才调用 `grid.damage_tile()` 和记录保护目标受伤。

敌方攻击阶段结束后清理未触发护盾。

### 8.3 法阵减速

法阵影响敌方移动规划，不直接伤害。

接入点在敌人计划移动前：

1. AI 仍按原逻辑选择目标和路径。
2. 生成路径后判断路径是否触碰法阵。
3. 若触碰，敌人本次可移动步数减少 1，再重新取截断后的移动终点。
4. 减速后的敌人仍会按新位置重新规划攻击。

法阵持续时间在每个新回合开始时递减。持续 2 回合表示放置后影响接下来两次敌方移动规划，到期移除。

## 9. UI 和预览

### 9.1 技能栏

`BattleScene._warden_skill_slots()` 改为读取 `WardenSkillCatalog`。技能按钮状态由以下条件决定：

1. 守卫者未 `has_acted`。
2. 技能次数未耗尽。
3. 当前至少存在一个合法目标。

按钮描述使用基础效果文案。升级和遗物未接入前，不显示强化来源。

### 9.2 Armed 模式

点击技能按钮后，`_armed_ability_id` 记录技能 ID。棋盘高亮只显示该技能合法目标。

点击目标格时：

1. 如果 armed 是 `move`，执行移动。
2. 如果 armed 是具体技能 ID，执行 `BattleAction.skill()`。
3. 如果没有 armed，点击敌人仍可以执行主技能，保持当前快捷操作。

### 9.3 预览

悬停合法目标时构造对应 `BattleAction.skill()` 并调用：

1. `preview_action()` 取本技能事件。
2. `preview_enemy_intent_ui_state()` 取行动后敌人意图。
3. 合并建筑伤害预览和敌人意图预览。

地裂楔、护火、法阵这类非直接伤害技能，第一版至少要保证敌人意图预览刷新；若没有直接伤害事件，也不能显示错误红色伤害预览。

### 9.4 棋盘标记

第一版需要新增轻量表现：

| 状态 | 表现 |
|---|---|
| 建筑护盾 | 建筑 HP 条或建筑格上显示护盾边框 |
| 法阵 | 目标格显示稳定的法阵标记 |

如果现有 `DiamondBoardView` 改动风险较高，可以先用现有 overlay 机制画简单颜色标记，后续再补正式图标。

## 10. 回合和次数规则

1. 任意主动技能成功执行后，守卫者 `has_acted = true`。
2. 移动后仍可使用主动技能；使用主动技能后不能再移动。
3. 每场次数技能只在技能成功执行后计数。
4. 预览不得消耗次数。
5. Undo 必须恢复技能次数、护盾、法阵、建筑 HP 和地裂 schedule。
6. 战斗结束不需要把技能状态写回 Run。

## 11. 兼容性

1. `BattleAction.attack()` 保留并映射到主技能。
2. `get_legal_attack_targets()` 保留并返回主技能合法目标。
3. 现有测试中直接调用 `attack()` 的用例应继续通过。
4. 新 UI 使用 `SKILL`，但旧快捷点击敌人的路径仍可走主技能。

## 12. 测试计划

### 12.1 单元测试

新增或扩展测试：

1. `BattleAction.skill()` 能携带 `skill_id`，clone 预览无副作用。
2. 每名守卫者 3 个技能均返回正确合法目标。
3. 护卫肩撞换位、敌人受 1 伤、不推。
4. 悬赏处决每场 2 次，直接击杀才增加进度。
5. 裂隙楔推迟 pending 出怪；没有 pending 时推迟下一次 schedule。
6. 反手抛按固定侧向规则侧推；两侧 blocked 时只拉。
7. 护火修复不超过初始 HP；满血给护盾；护盾不叠加。
8. 法阵每场 2 次，持续 2 回合，多个法阵对同一敌人不叠加。
9. `BattleAction.attack()` 与主技能结果一致。

### 12.2 集成测试

1. 技能使用后 `has_acted = true`，全员行动结束后自动进入敌方执行。
2. `preview_action()` 不改变技能次数、护盾、法阵和地裂 schedule。
3. `preview_enemy_intent_ui_state()` 能反映护火、法阵、裂隙楔后的敌人意图变化。
4. Undo 能恢复技能状态。
5. Boss 锚石和心脏钟仍可被主技能攻击。

### 12.3 UI 测试

1. 技能栏 3 个按钮均显示正确名称、描述和可用状态。
2. 次数耗尽的技能禁用。
3. Armed 技能只高亮对应目标。
4. 没有 armed 时点击敌人仍执行主技能。
5. 护盾和法阵标记能在状态变化后刷新。

## 13. 风险和缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 护火过强 | 建筑压力下降，低损任务变简单 | 护盾不叠加，且敌方攻击阶段后过期 |
| 法阵过强 | 敌人难以形成硬威胁 | 每场 2 次，多个法阵不叠加，只减移动不减攻击 |
| 裂隙楔让裂隙压制任务偏易 | 奖励滚雪球 | 本轮先接受，后续按模拟结果调任务阈值 |
| 反手抛侧推语义不清 | 玩家无法预期结果 | 固定左手优先，并在预览中显示最终位移 |
| 新状态破坏预览或 Undo | 难以调试 | 所有新增状态写入 `BattleState.clone()`，并补回归测试 |
| `attack()` 与主技能双路径分裂 | 旧测试和新 UI 行为不一致 | `attack()` 只作为主技能别名，实际走同一结算函数 |

## 14. 实现顺序

1. 增加技能目录和 `BattleAction.SKILL`。
2. 增加 `BattleState` 技能状态字段和 clone。
3. 在 `BattleEngine` 接入技能合法目标与主技能映射。
4. 实现 3 个主技能，保证旧攻击测试通过。
5. 实现赏金猎人第 2、3 技能。
6. 实现盗墓人第 2、3 技能。
7. 实现大魔法师第 2、3 技能和敌方移动减速。
8. 改 UI 技能栏、armed 模式和预览。
9. 补单元、集成和 UI 测试。
10. 跑 Godot 测试和关键战斗冒烟验证。
