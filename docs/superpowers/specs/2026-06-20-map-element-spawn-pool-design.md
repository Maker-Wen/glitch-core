# 地图元素池与生怪池设计

> 日期：2026-06-20  
> 状态：阶段 2 已实现；候选池仍为 preview-only，固定运行时表已按预演结果回流校准  
> 范围：Demo 战斗地图的地块特色、危险地块、环境元素池、受控随机生怪池、公平性校验。  
> 结论：地图采用“固定题型骨架 + 元素池 + 生怪池 + 预告与校验”的结构，避免完全随机破坏可解性，同时让同一张地图每局有变化。

## 1. 目标

当前 5 张正式战斗地图已经有建筑、石柱、裂缝、部署区和固定刷怪表，但空地大多只是普通可走格，地图之间仍容易读成同一种棋盘。后续地图需要让空地承担明确战术角色，并让裂缝、危险地块、阻挡物和刷怪点具备可控变化。

本设计解决四个问题：

1. 地图特色不足：每张图必须有清晰的地块主题。
2. 空地语义弱：空地需要被分成路线、保护圈、瓶颈、推撞口袋、危险区等角色。
3. 刷怪过死：敌人生成点需要有变化，但不能完全随机。
4. 公平性风险：随机内容不能造成开局必伤建筑、远程白嫖建筑或玩家部署区保护不到目标。

## 2. 设计原则

### 2.1 固定题型，不固定所有细节

每张地图保留固定骨架，例如：

| 地图 | 固定题型 |
|---|---|
| 断墙前哨 | 基础防守、远程线压、首战教学 |
| 裂缝庭院 | 左右岸防守、中线裂缝 |
| 石柱墓园 | 石柱墓道、推撞连锁 |
| 铁角闸门 | 精英冲撞跑道、闸门瓶颈 |
| 钟楼外环 | Boss 锚石、心脏窗口、外环调度 |
| 断桥边缘 | 深渊边缘、推落处决 |

骨架决定地图身份；元素池和生怪池决定每局变化。

### 2.2 所有危险必须提前预告

危险地块不能突然结算。裂缝出怪、Boss 钟声、裂地喷发、冲撞跑道和深渊高风险区域都应提前显示，玩家至少有一个行动窗口处理。

### 2.3 危险要能被反利用

危险地块不是单纯惩罚玩家。优先设计成可被玩家利用的战术工具：

- 把敌人推入深渊。
- 占住裂缝延迟出怪。
- 诱导敌人站进喷发区。
- 利用冲撞跑道让铁角兽撞墙或撞柱。
- 在 Boss 钟声落点前移动敌人或建筑威胁。

### 2.4 随机必须受控

敌人和元素不从全棋盘随机，而是从地图定义好的语义池中抽取。每个池子需要有适用地图、权重、禁用区域、预告规则和校验规则。

## 3. 地块角色层

在现有 `Grid.TileType` 之外增加一层设计语义。第一阶段可以只做配置和表现，不改变移动规则。

| 角色 | 作用 | 是否默认改变规则 |
|---|---|---|
| `attack_lane` | 敌人主要推进路线 | 否 |
| `protect_ring` | 建筑保护圈，部署区应覆盖或贴近 | 否 |
| `choke` | 瓶颈、闸门、墓道 | 否 |
| `push_pocket` | 推撞口袋、撞柱、坠落准备位 | 否 |
| `rift_influence` | 裂缝影响区、裂地视觉区 | 否 |
| `hazard_preview` | 下回合危险预告格 | 是，预告后结算 |
| `boss_window` | Boss 锚石/心脏/钟声窗口 | 按 Boss 规则 |
| `deploy_buffer` | 部署缓冲区，保护玩家首回合响应 | 否 |

配置示例：

```gdscript
"terrain_roles": [
    {"role": "attack_lane", "cells": [Vector2i(1, 0), Vector2i(1, 1), Vector2i(1, 2)]},
    {"role": "protect_ring", "cells": [Vector2i(2, 3), Vector2i(3, 3), Vector2i(2, 4)]},
    {"role": "push_pocket", "cells": [Vector2i(0, 3), Vector2i(1, 3)]}
]
```

第一阶段 UI 可以用地表贴图、边框或轻量高亮表现这些角色，但不需要全部接入规则。

## 4. 元素池

地图元素池负责给固定骨架增加变化。每张图配置 1 到 3 个可抽元素包，普通战每局抽 1 到 2 个，精英/Boss 可以抽固定包加一个变化包。

### 4.1 元素包类型

| 元素包 | 内容 | 设计作用 |
|---|---|---|
| `rift_cluster` | 裂缝点、裂缝影响区、裂缝刷怪池 | 形成预告刷怪压力 |
| `hazard_cluster` | 裂地、深渊边缘、腐蚀地面、钟声落点 | 形成地图特色危险 |
| `blocker_cluster` | 石柱、废墙、临时路障 | 改变路线和射线 |
| `push_cluster` | 推撞口袋、撞墙点、坠落边缘 | 让位移技能有价值 |
| `flank_cluster` | 侧翼入口、边缘伏击点 | 增加二线压力 |
| `boss_cluster` | 锚石、心脏窗口、Boss 召唤点 | Boss 图专属 |

配置示例：

```gdscript
"element_pools": {
    "rift_cluster": [
        {
            "id": "midline_rifts_a",
            "weight": 2,
            "rifts": [{"id": "r_mid", "pos": Vector2i(3, 1)}],
            "terrain_roles": [{"role": "rift_influence", "cells": [Vector2i(3, 1), Vector2i(3, 2), Vector2i(3, 3)]}]
        }
    ],
    "push_cluster": [
        {
            "id": "left_wall_pocket",
            "weight": 1,
            "terrain_roles": [{"role": "push_pocket", "cells": [Vector2i(0, 3), Vector2i(1, 3)]}]
        }
    ]
}
```

### 4.2 每张图的推荐元素池

| 地图 | 必选元素 | 可变元素 |
|---|---|---|
| 断墙前哨 | 建筑保护圈、两条进攻路 | 少量废墙/推撞口袋 |
| 裂缝庭院 | 中线裂缝影响区 | 上裂缝、下裂缝、左右侧翼刷怪 |
| 石柱墓园 | 石柱墓道、推撞口袋 | 裂缝位置、额外墓碑阻挡 |
| 铁角闸门 | 冲撞跑道、闸门瓶颈 | 左右裂缝、侧翼伏击 |
| 钟楼外环 | Boss 窗口、外环调度线 | 钟声落点组合、Boss 召唤点 |
| 断桥边缘 | 深渊边缘、断裂中心 | 裂缝、边缘刷怪、推落口袋 |

## 5. 危险地块

危险地块分为固定危险、预告危险和 Boss 危险。第一版优先实现预告和表现，规则从少到多接入。

### 5.1 危险类型

| 危险 | 规则 | 适用地图 | 优先级 |
|---|---|---|---|
| `rift_spawn_warning` | 本回合预告，下回合裂缝出怪 | 裂缝庭院、石柱墓园、铁角闸门、Boss | P0 |
| `abyss_edge` | 标记可推落边缘；单位从标记方向被推出地图时坠落 | 断桥边缘 | P1 |
| `cracked_ground` | 本回合预告，下回合喷发；第一版对站在预告格上的单位造成 1 伤，不伤害建筑 | 裂缝庭院 | P1 |
| `charge_lane` | 铁角兽下回合冲撞路线高亮；第一版已接入 enemy intent overlay | 铁角闸门 | P1 |
| `bell_wave` | Boss 钟声预告行列；第一版下回合对站在预告格上的单位造成 1 伤，不伤害建筑 | 钟楼外环 | P1 |
| `corrupt_mire` | 进入后下回合 Move -1 | 后续章节 | P2 |

### 5.2 结算原则

1. 危险在玩家行动前必须可见。
2. 危险造成的伤害不应在首战出现。
3. 普通战同回合最多出现 1 种主动危险。
4. Boss 战可以出现 Boss 危险和裂缝预告，但必须错峰。
5. 危险不得直接导致开局不可避免的建筑伤害。

### 5.3 `charge_lane` 第一版

`charge_lane` 第一版不新增额外伤害规则，而是把铁角兽已有的锁定攻击意图升级为整条冲撞危险预告：

- 铁角兽有攻击计划时，`BattleEngine` 在 enemy intent row 中输出 `hazard_type=charge_lane` 和 `hazard_cells`。
- `hazard_cells` 从铁角兽当前位置沿锁定方向延伸到攻击目标，或最多延伸到攻击射程。
- `DiamondBoardView` 在普通攻击箭头之前绘制整条红橙危险带，让玩家看到完整冲撞路线。
- 玩家推开铁角兽后，冲撞方向保持锁定，但整条路线会随铁角兽当前位置平移；如果错开建筑或守卫，则预告变成 miss。
- 玩家击杀铁角兽后，该危险行随 intent row 变为 removed，不再显示。

这版的目标是先解决“铁角兽危险只显示目标点、不像地图危险”的可读性问题。后续如果要把 `charge_lane` 发展成真正的地块危险，可以再增加撞墙、撞柱、沿途单位受影响等规则，但必须继续保持可预告和可反制。

### 5.4 `cracked_ground` 第一版

`cracked_ground` 第一版是地图主动危险，不绑定敌人 intent：

- `BattleConfigCatalog` 输出 `cracked_ground_schedule`。第一批只接入裂缝庭院，安排在第 2、3 回合的中线空地。
- `BattleEngine` 在本回合玩家行动前把 schedule 变成 `pending_cracked_ground`，棋盘立即显示裂地预告。
- 下一回合开始时，`pending_cracked_ground` 先于刷怪和敌人移动结算；站在预告格上的单位受到 1 点环境伤害。
- 第一版不伤害建筑，不生成新裂缝，也不会把阻挡格或已有 rift 纳入预告。
- 玩家可以撤离守卫者，也可以把敌人推入预告格，让危险成为可反利用的地形压力。

### 5.5 `abyss_edge` 第一版

`abyss_edge` 第一版只标记危险边缘，不改变棋盘格本身：

- `BattleConfigCatalog` 输出 `abyss_edges`，以格子 + 方向记录可推落边。第一批只接入断桥边缘候选图，左右边各保留中段 4 个危险边。
- `BattleState.is_abyss_edge(from_cell, direction)` 判断单位是否从被标记的边缘方向离开棋盘。
- `PhysicsResolver` 在推撞导致单位出界时复用原有坠落事件；如果来源边是 `abyss_edge`，`UNIT_FELL.extra.abyss_edge=true`。
- `DiamondBoardView` 在对应边缘画危险线、外侧阴影和刻痕，让玩家能提前读出推落口袋。
- 中央断裂区的 `void_cells` 仍是地图元数据，不会在第一版里改写 `Grid` 的可走性或阻挡规则。

### 5.6 `bell_wave` 第一版

`bell_wave` 第一版是 Boss 图专属主动危险，使用和裂地一致的提前预告节奏：

- `BattleConfigCatalog` 输出 `bell_wave_schedule`。第一批只接入钟楼外环，安排在第 3、5 回合预告，和第 2、4 回合裂隙预告错峰。
- `BattleEngine` 在本回合玩家行动前把 schedule 变成 `pending_bell_wave`，棋盘立即显示钟声波纹预告。
- 下一回合开始时，`pending_bell_wave` 先于刷怪和敌人移动结算；站在预告格上的单位受到 1 点环境伤害。
- 第一版不伤害建筑，不伤害 Boss 锚石，也不推开单位，避免 Boss 图出现不可防守的建筑扣血。
- 玩家可以撤离守卫者，也可以把敌人留在钟波格上，让 Boss 危险成为可反利用的节奏压力。

## 6. 生怪池

生怪池按语义分组，而不是按单个固定坐标写死。每个池子提供候选点、敌人类型、回合范围和公平性标签。

### 6.1 生怪池类型

| 池子 | 作用 |
|---|---|
| `front_lane_pool` | 正面推进怪 |
| `left_flank_pool` | 左翼伏击 |
| `right_flank_pool` | 右翼伏击 |
| `rift_pool` | 裂缝刷怪 |
| `elite_pool` | 精英和护卫 |
| `boss_summon_pool` | Boss 召唤 |
| `cleanup_pool` | 后段补压，避免终局无事可做 |

配置示例：

```gdscript
"spawn_pools": {
    "front_lane_pool": {
        "cells": [Vector2i(1, 0), Vector2i(6, 0)],
        "enemy_weights": {"rot_beast": 3, "bone_grub": 1},
        "rounds": [1, 2, 3],
        "warns_before_spawn": false,
        "max_per_round": 1
    },
    "rift_pool": {
        "rift_ids": ["r_mid", "r_top"],
        "enemy_weights": {"rot_beast": 2, "bone_grub": 1},
        "rounds": [2, 3, 4],
        "warns_before_spawn": true,
        "max_per_round": 1
    }
}
```

### 6.2 回合结构

推荐保留现有三层压力：

1. `initial_enemies`：开局题面，首回合可读。
2. `scripted_spawns`：固定或池化的边缘补怪。
3. `rift_schedule`：提前一回合预告的裂缝刷怪。
4. `cracked_ground_schedule`：提前一回合预告的主动危险地块。
5. `abyss_edges`：固定地图边缘方向标记，用于推落处决和棋盘危险边表现。
6. `bell_wave_schedule`：Boss 图专属主动危险地块，和裂缝预告错峰。

池化后实际流程为：

```text
地图模板
-> 抽元素包
-> 生成有效地块角色层
-> 根据元素包生成 spawn_pools
-> 抽 initial_enemies / scripted_spawns / rift_schedule / hazard_schedule
-> 公平性校验
-> 输出 BattleConfigCatalog 可消费的运行时配置
```

## 7. 公平性校验

随机生成必须经过校验。校验失败时优先换同池候补点，再换敌人，最后降级为固定安全表。当前实现分两层：`BattlePoolCandidateGenerator` 做静态公平性校验，`BattleCandidatePlaytester` 用真实 `BattleEngine` 做自动可解性预演。

### 7.1 必要校验

| 校验 | 规则 |
|---|---|
| 部署保护 | 部署区到关键建筑保护圈距离必须足够近 |
| 开局必伤 | 初始敌人不能在玩家行动前必定攻击建筑 |
| 远程白嫖 | 弓手初始点不能直接无解瞄准建筑；如果部署区可在射线上放置守卫者拦截，则降级为 `adjusted` 警告 |
| 硬威胁上限 | 普通战同回合硬威胁不超过 2，精英/Boss 不超过 3 |
| 裂缝预告 | 裂缝和主动危险必须提前显示 |
| 占位处理 | 刷怪点被占用时延后或换同池候补点 |
| 路径可达 | 敌人从出生点到至少一个有效目标存在路径 |
| 建筑可守 | 至少一个守卫者首回合能进入建筑保护圈或阻挡关键线 |
| 主题一致 | 抽到的元素包必须符合地图 pressure_tags |
| 自动预演 | 固定 seed 候选必须通过部署搜索和多回合模拟，保护目标 0 伤、0 摧毁 |

### 7.2 校验输出

校验器返回三种结果：

| 结果 | 行为 |
|---|---|
| `valid` | 直接使用 |
| `adjusted` | 使用调整后的点位或敌人 |
| `rejected` | 放弃本次随机，回退固定安全配置 |

调试预览中应显示本局抽到的元素包、刷怪池、静态校验结果和自动预演结果，方便设计迭代。当前预演工具已输出 `valid`、`adjusted`、`rejected` 三类静态结果；`adjusted` 代表候选可用但有高压提示，例如铁角闸门右侧弓手线需要玩家用部署格拦截。

自动预演返回 `approved`、`review`、`rejected`：

| 结果 | 行为 |
|---|---|
| `approved` | 模拟胜利，保护目标 0 伤、0 摧毁，守卫 0 死亡 |
| `review` | 没有硬失败，但存在高可见威胁或其他人工复核点 |
| `rejected` | 模拟出现失败、保护目标受伤或保护目标摧毁 |

`BattleCandidatePlaytester` 会在部署区内搜索多组部署点，再用 beam-search 控制器执行多回合预演。当前固定 seed `240620` 的 5 张正式图 x 3 个 variant 全部 `approved`。

### 7.3 批量预演与失败回流

`BattleCandidateBatchPlaytester` 用同一套生成器和自动预演器批量扫描多 seed、多 variant。它不改变运行时地图选择，只输出设计诊断：

| 输出 | 用途 |
|---|---|
| `result_counts` | 查看候选最终是 `approved`、`review` 还是 `rejected` |
| `validation_counts` | 区分静态公平性警告和硬拒绝 |
| `solvability_counts` | 区分真实战斗预演是否造成建筑伤害或失败 |
| `issue_counts` / `warning_counts` | 汇总最常见的问题文本 |
| `pool_risks` | 按 `source_pool` 聚合风险，定位是哪个生怪池造成压力 |
| `examples` | 保留少量失败/复核样本，显示 seed、variant、元素包、刷怪表和逐回合摘要 |

默认命令：

```bash
godot --headless -s tmp/pool_candidate_batch_preview.gd
```

当前默认样本为 5 张正式图 x 5 个 seed x 3 个 variant，共 75 个候选。最近一次批量结果：

| 指标 | 结果 |
|---|---|
| 自动预演 | 75/75 `approved` |
| 硬失败 | 0 `rejected` |
| 静态复核 | 0 `review` |
| 建筑伤害 | 0 |
| 建筑摧毁 | 0 |
| 守卫死亡 | 0 |

批量预演曾发现近建筑刷怪、侧翼远程线和 Boss 边缘裂缝叠压会造成“能胜利但建筑受伤”或高复核压力。回流调整如下：

- 裂缝庭院：开局前线腐兽从 `(1,0)` 后移到 `(2,0)`，保留前压感但移除近建筑开局白嫖风险。
- 铁角闸门：右侧开局弓手改为 `(7,6)` 腐兽，左侧弓手延后到 R3；裂缝池拆为早期 `r_right` 与后期 `r_left`/`r_right`，避免侧翼远程和裂缝在同一窗口叠压。
- 断墙前哨：候选前线池只保留 R1，不再 R2 重复前压；右侧 R4 侧翼改为纯近战，减少远程越过保护圈攻击建筑。
- 石柱墓园：右侧侧翼候选改为纯近战，避免后段弓手贴近建筑造成不可保护伤害。
- 钟楼外环：Boss 候选 `rift_pool` 收紧为只使用 `r_top`，R4 只保留中上点 `(3,1)` 的 `bell_thrall` 召唤；固定表同步改成中上裂缝 R2/R4，避免左右边缘裂缝与 Boss 目标窗口叠压。

这些调整已经同时回流到 preview-only 候选池和 `BattleConfigCatalog` 固定运行时表；正式战斗仍默认使用固定表，候选池暂不直接替换运行时。

## 8. 分阶段实现

### 阶段 1：配置和表现

- 在地图配置中加入 `terrain_roles`、`element_pools`、`spawn_pools` 字段。
- 先不改变 `Grid.TileType`，地块角色只作为表现和调试信息。
- 给预览页和战斗 UI 加轻量角色层显示。
- 当前固定路线仍可使用固定安全表。

### 阶段 2：受控随机生怪

- 从 `spawn_pools` 抽取 `initial_enemies`、`scripted_spawns`、`rift_schedule`。
- 加入公平性校验和自动可解性预演。
- 加入多 seed 批量预演，能把失败样本按地图、问题文本和 `source_pool` 回流给池子配置。
- 当前实现停留在预演层：`BattlePoolCandidateGenerator` 可以按 seed 生成候选表，但不替换 `BattleConfigCatalog` 的固定运行时表。
- 首战正式表保持固定；固定表已用同一套预演器校准到 0 建筑伤害，后续是否启用轻量随机，需要继续扩大 seed 样本并通过人工设计复核。
- Boss 图预演使用固定脚本 + 召唤池，不完全随机；Boss 候选裂缝池当前只使用中上裂缝和蛆群，避免左右边缘裂缝与 Boss 目标窗口叠压。
- 为避免后半程不可防守，候选池已收紧部分 R4/R5 压力：断墙右路去掉 R2 近建筑补刷，裂缝庭院开局点后移，石柱墓园右侧改纯近战，铁角闸门拆分早晚裂缝池，Boss 去掉 R5 额外候选召唤并固定中上召唤。
- 可通过 `godot --headless -s tmp/pool_candidate_preview.gd` 查看 5 张正式图的多 variant 候选结果。
- 可通过 `godot --headless -s tmp/pool_candidate_batch_preview.gd` 查看多 seed 批量预演和失败回流报告。

### 阶段 3：危险地块规则

- `charge_lane` 第一版已接入：铁角兽 enemy intent 会导出整条冲撞危险带，并在棋盘上显示。
- `cracked_ground` 第一版已接入：裂缝庭院会提前预告裂地格，下回合开始对站在格上的单位造成 1 伤，不伤害建筑。
- `abyss_edge` 第一版已接入：断桥边缘候选图会标记左右危险边，单位从标记方向被推出地图时复用坠落事件，并在事件 extra 中标记 `abyss_edge=true`。
- `bell_wave` 第一版已接入：钟楼外环会提前预告钟波格，下回合开始对站在格上的单位造成 1 伤，不伤害建筑。
- 每个危险都必须有预告事件和 UI 表现。
- 更新模拟预演，统计建筑伤害、敌人威胁、危险反利用次数。

### 阶段 4：扩展地图池

- 将 5 张正式图扩展为同题型多变体。
- 每个章节增加新的元素池，而不是复制整张地图。
- 根据预演结果调权重。

## 9. 每张图的第一版改造建议

| 地图 | 第一版要加的特色 |
|---|---|
| 断墙前哨 | 两条进攻路、建筑保护圈、少量推撞口袋；不加主动危险 |
| 裂缝庭院 | 中线裂缝影响区、裂地预告、左右岸刷怪池 |
| 石柱墓园 | 墓道瓶颈、推撞口袋、裂缝位置池 |
| 铁角闸门 | 冲撞跑道预告、闸门瓶颈、侧翼刷怪池 |
| 钟楼外环 | Boss 窗口、钟声落点池、Boss 召唤池 |
| 断桥边缘 | 深渊边缘规则、断裂中心、坠落处决池 |

## 10. 非目标

- 不做全随机地图生成。
- 不让敌人在任意空地随机出生。
- 不在首战加入复杂危险地块。
- 不一次性加入所有危险地块规则。
- 不让视觉地貌自动改变规则，除非明确列入危险地块。
- 不牺牲 ITB 式可读预告来换变化。

## 11. 验收标准

1. 每张正式地图都有 `terrain_roles`，空地能被解释为路线、保护、瓶颈、推撞或危险区。
2. 至少 3 张地图有可抽取的 `element_pools`。
3. 至少 3 张地图有语义化 `spawn_pools`，并能生成不同但同主题的刷怪表。
4. 裂缝和主动危险都提前预告。
5. 随机结果经过公平性校验，不能出现开局必伤建筑。
6. 玩家部署区能保护关键建筑或阻挡关键威胁。
7. 预演工具能输出抽到的元素包、生怪池、静态校验、自动预演、建筑伤害和逐回合摘要。
8. 批量预演工具能按地图和 `source_pool` 聚合失败/警告样本，帮助回流调池。
9. 固定安全配置仍可作为回退，保证 Demo 路线可跑。
