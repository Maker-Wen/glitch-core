# 任务委托面板整卡选择重做设计

> 日期：2026-06-21  
> 状态：待实现  
> 范围：据点内 `任务委托` 面板的卡片信息层级、整卡交互、选中态、返回据点位置和视觉表现。  
> 结论：采用 **A 方向：三张委托卡 + 整卡可点 + 标题栏返回 + 非 shader 选中态优先** 。Shader 仅作为第二阶段视觉增强。

## 1. 背景

当前任务委托面板已经从路线图改为三张可接委托卡，但视觉和文案仍偏字段清单：

1. 卡片右下角的 `查看详情` 与奖励文案争空间，按钮位置像表格操作。
2. `返回据点` 放在屏幕底部左侧，离面板主体较远，并抢占主视觉。
3. 卡片文案混入设计师口吻，例如“教学式普通战”“奖励玩家”“Demo 精英战”，不适合直接展示给玩家。
4. 面板说明文字解释了系统补位规则，但玩家做当下选择时并不需要读这段长说明。

本次重做把任务面板重新定义为“当前行动选择界面”，不再承担教学、规则解释或详细战斗说明。

## 2. 设计目标

任务委托面板只回答四个问题：

1. 当前可接哪些委托。
2. 每个委托是什么类型。
3. 风险大概多高。
4. 接这个委托能获得什么报酬或进入什么取舍。

更细的信息放到事件页、营地页、商店页或战斗 HUD 中。任务卡必须能被快速扫读，玩家不需要先解析长句，也不需要再经过一层确认页。

## 3. 最终方向

### 3.1 结构

保留三卡结构：

- 固定显示最多三张当前可接委托。
- 每张委托卡整张可点击，点击后直接执行对应委托。
- 不再在卡片右下角放独立小按钮。
- 卡片内部不展示路线层级、连线、完整压力标签、回合数、奖励任务或守卫者状态。
- 面板顶部状态区保留当前决策必需资源：`余烬`、`守护值`、`守卫者`。`腐化` 仅在大于 0 或影响当前判断时显示。

### 3.2 返回位置

`返回据点` 从屏幕底部移入任务面板标题栏右侧，作为低权重导航按钮。

原因：

1. 它不再抢占底部主视觉。
2. 它与当前面板上下文绑定，玩家理解为“关闭任务委托面板”。
3. 底部可以只保留轻提示，或者完全留空，让背景和卡片呼吸。

不采用顶部资源条返回作为第一版方案。顶部资源条是全局状态区域，如果只在任务委托页加入返回，会和其他据点页不一致。

## 4. 信息层级

### 4.1 卡片必须展示

| 字段 | 示例 | 规则 |
|---|---|---|
| 任务名 | `断墙前哨` | 使用节点标题 |
| 任务类型 | `防守委托`、`裂隙压制`、`事件委托` | 从节点类型和压力标签推导 |
| 风险 | `低危 1/5`、`中危 2/5`、`高危 3/5` | 点击即执行，所以卡片必须保留精确刻度 |
| 报酬 / 取舍 | `报酬 7 余烬`、`重燃 / 拆镜` | 用玩家可理解的结果表达 |

### 4.2 卡片可展示

卡片可以有一行世界内短情报：

| 原节点 | 短情报示例 |
|---|---|
| `断墙前哨` | `外墙有远程火线压近。` |
| `裂缝庭院` | `浅裂隙正在扩张。` |
| `熄灭的灯塔` | `灯塔内仍有余火。` |
| `前线军需点` | `军需箱仍可开封。` |
| `巡火营地` | `守夜人留下补给。` |

短情报规则：

1. 最多一行，建议 12 到 16 个中文字。
2. 必须是世界内口吻。
3. 不解释玩法细节。
4. 不出现“教学式”“奖励玩家”“Demo”等设计师口吻。

### 4.3 不在卡片展示

以下内容移到后续节点页面、战斗 HUD 或完全隐藏：

- 完整 `summary`。
- 普通战回合数可隐藏，Boss 等特殊委托可在短情报中提示。
- 奖励任务。
- 守卫者 HP。
- 守护值、腐化、余烬全量状态。
- 多个压力标签的完整列表。
- “完成一个委托后补入新任务”的长说明。
- 路线层级、连线、可达规则。

## 5. 交互

### 5.1 整卡可点

每张委托卡本身就是主要交互目标。

交互规则：

1. 鼠标悬停、键盘 focus 和手柄焦点都视为选中态。
2. 点击卡片直接调用 `_confirm_mission(node_id)` 或等价执行入口。
3. 卡片子节点不拦截鼠标事件。
4. 卡片热区不小于当前按钮安全尺寸要求。
5. 不再通过 `委托确认` 页二次确认普通委托。

### 5.2 选中态

第一版选中态不用 shader，使用稳定的控件层效果：

1. 卡片整体上移 3 到 4 px。
2. 外边框变为更亮的琥珀色。
3. 增加一层半透明内框。
4. 增加轻微火光外发光。
5. 可显示小印章、角标或符号，但不使用 `已选` 这类容易误解为“已经确认”的文案。
6. 文本颜色不被发光层影响。

实现建议：

- 使用外层 `Button` 或可 focus 的 `Control` 作为整卡点击区域。
- 用 `StyleBoxFlat` 的 hover / focus / pressed 表达基础状态。
- 额外叠加 `ReferenceRect` 或 `ColorRect` 表示内框和高亮。
- 不使用缩放动画，避免布局抖动。

### 5.3 Shader 增强

Shader 可以作为第二阶段增强，不作为第一版依赖。

如果后续要加：

1. 给选中卡片新增独立高亮 overlay。
2. 把 `ShaderMaterial` 挂在 overlay 上，而不是挂在整张卡上。
3. Shader 只做边缘流光或噪声微光，不影响文字、鼠标事件和透明度。
4. 支持关闭或降级为静态高亮，避免动效过强。

第一版不直接上 shader 的理由：

1. 当前据点 UI 是动态创建的 `ColorRect`、`ReferenceRect`、`Button`，没有现成 UI shader 管线。
2. 非 shader 方案已经能满足选中识别。
3. Shader 调试成本更高，且容易污染文字可读性。

## 6. 视觉方向

采用羊皮纸委托板的世界感，但控制信息密度：

1. 面板像嵌在据点火光中的任务板。
2. 卡片像单张委托纸，而不是深色数据卡。
3. 选中卡片稍微抬升，有火光边缘和印章。
4. 背景仍可见，但面板遮罩需要保证 4.5:1 以上文本对比。
5. 不使用大量圆角、渐变装饰或过亮发光。

## 7. 文案规则

### 7.1 标题区

标题区建议：

```text
任务委托
断墙外环 · 选择下一次行动
```

不再显示完整补位规则。补位是系统机制，玩家完成任务后自然看到新委托即可。

### 7.2 风险表达

卡片使用文本风险：

| `risk_level` | 卡片文案 |
|---|---|
| 1 | `低危` |
| 2 | `中危` |
| 3 | `高危` |
| 4 | `危急` |
| 5 | `死线` 或 `Boss` |

卡片主文案可以是文本风险，但旁边需要保留 `1/5` 到 `5/5`。点击即执行时，玩家不应失去精确风险信息。

### 7.3 报酬表达

普通战：

```text
报酬 7 余烬
```

精英战：

```text
报酬 11 余烬 · 遗物
```

事件：

```text
重燃 / 拆镜
```

营地：

```text
治疗 / 修复
```

商店：

```text
消耗余烬 · 补给
```

Boss：

```text
终局报酬 14 余烬
```

## 8. 直接执行关系

任务委托面板瘦身后，不再依赖确认页承担普通委托判断。点击卡片后的行为按节点类型分流：

| 节点类型 | 点击卡片后 |
|---|---|
| 普通战 / 精英战 / Boss | 直接设置 `current_node_id` 并进入战斗 |
| 事件 | 直接进入事件选择页 |
| 营地 | 直接进入营地选择页 |
| 商店 | 直接进入商店页 |

因此卡片需要展示足够的最小决策信息：

- 任务类型。
- 精确风险。
- 报酬或取舍方向。
- 一行世界内短情报。

`_show_mission_detail` 可以删除、保留为调试入口，或暂时不再从任务委托面板调用。后续如果需要详情，只能作为长按 / 辅助查看，不应阻断主流程。

## 9. 实现影响

主要涉及：

| 模块 | 调整 |
|---|---|
| `GameManager._show_mission_board` | 面板标题区、返回位置、卡片布局 |
| `GameManager._add_mission_card` | 改为整卡可点，移除右下角小按钮，点击直接执行委托 |
| 文案 helper | 增加短情报、风险文本、卡片报酬文案 |
| 测试 | 更新任务板文案断言、按钮查找方式和卡片点击行为 |

建议新增 helper：

- `_mission_risk_label(node)`。
- `_mission_card_intel(node)`。
- `_mission_card_reward_line(node)`。
- `_add_mission_card_selection_state(card, selected)` 或等价样式函数。

## 10. 验收标准

1. 任务委托面板仍显示三张可接委托卡。
2. 鼠标悬停、键盘 focus 或手柄焦点在卡片上时，该卡显示选中态。
3. 每张卡整张可点击，点击后直接执行该委托。
4. 卡片内不再出现 `查看详情` 小按钮。
5. `返回据点` 位于面板标题栏右侧，不再位于屏幕底部。
6. 卡片不展示设计师口吻 summary。
7. 卡片可快速读出任务名、类型、精确风险和报酬 / 取舍。
8. 现有主菜单、据点、事件、营地、商店返回流程继续通过。

## 11. 自评结论

### 11.1 直接点击执行的风险

直接点击执行会减少一步确认，但也提高误触成本。当前设计可接受，前提是满足三点：

1. Hover / focus 选中态足够明显。
2. 卡片热区、返回按钮和标题区之间留出清晰间距。
3. 卡片上保留精确风险和报酬，不让玩家盲点。

不建议增加二次确认。二次确认会回到当前面板最想避免的“多一层详情页”问题。

### 11.2 信息是否足够

卡片直接执行时，信息最小集必须比“只看卡片标题”更多：

1. 任务名告诉玩家去哪里。
2. 类型告诉玩家会进入战斗、事件、营地还是商店。
3. 精确风险告诉玩家代价级别。
4. 报酬 / 取舍告诉玩家为什么接。
5. 顶部状态告诉玩家当前是否适合冒险。

因此本设计不再删除顶部状态，只删除长描述和设计师口吻。

### 11.3 Shader 是否必要

Shader 不必要。第一版选中态使用控件层就足够可靠。Shader 适合后续加在独立 overlay 上做视觉增强，不应成为交互识别的唯一依据。

### 11.4 返回按钮位置

标题栏右侧是当前最合适的位置。它足够可见，但不占用卡片区域，也不会和底部背景、火光和任务提示抢视觉。

## 12. 非目标

本次不做：

- 不改路线生成和委托补位规则。
- 不新增主动刷新机制。
- 不新增 Boss 独立通缉区。
- 不制作新的位图 UI 资产。
- 不实现 UI shader 第一版。
- 不重做事件、营地、商店页面。
