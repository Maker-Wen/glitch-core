# 商店面板正式版重做设计

> 日期：2026-06-22  
> 状态：待实现  
> 范围：Run 内 `商店行动` 节点页面的文案、布局、视觉层级和测试覆盖。  
> 结论：采用 **B 方向：摊位式货架**。删除调试/设计说明文字，把商品做成三列补给摊位，顶部保留资源状态。

## 背景

当前商店面板已经能完成购买流程，但画面仍像 debug 页：

1. 左侧展示节点 `summary`，内容是设计说明，不适合正式版本直接给玩家看。
2. 红色说明“商店会消耗 1 个战略 tick，且不会压制任何前线。”是开发/规则调试文案，不应出现在正式版。
3. 左侧信息块占据大量面积，却没有提供购买决策所需的正式视觉焦点。
4. 右侧商品能看出功能，但更像表格行，缺少军需点、货架和正式交易柜台的氛围。

本次只重做商店节点页面，不调整 Run 路线、商店库存、价格、购买效果或返回任务布告的流程。

## 目标

1. 商店页不出现 debug、设计师口吻或系统解释文字。
2. 玩家进入页面后能快速知道当前资源、可买商品、花费和收益。
3. 画面符合正式版暗色、火光、军需补给的美术基调。
4. 购买按钮、禁用态和返回按钮继续清晰可用。
5. 测试覆盖确保调试文案不再渲染，购买流程不回到据点。

## 非目标

1. 不新增确认弹窗。
2. 不新增商店刷新、二次购买、买空库存或持久库存系统。
3. 不修改 `RunState.resolve_shop_node()` 的经济逻辑。
4. 不重做事件页、营地页或任务委托页。
5. 不依赖新增联网资源或运行时下载资源。

## 最终方向

采用 **摊位式货架** 布局。

页面从左右说明区改为“顶部资源 + 三列商品摊位”：

| 区域 | 新职责 | 删除内容 |
|---|---|---|
| 顶部资源带 | 节点名、当前余烬、守护值、存活守卫者、腐化 | 完整 `summary`、战略 tick 说明、前线压制说明 |
| 商品货架 | 三个并列商品摊位、货品符号、价格、收益、购买按钮、资源不足禁用态 | 长句描述、表格式行信息 |

页面不再放长段说明。若需要一行氛围文案，只使用世界内短句，例如：

```text
封存的军需箱仍带着余温。
```

这类短句不解释系统，不出现“tick”“压制”“Demo”“奖励玩家”等词。

## 信息结构

### 顶部

保留现有顶部状态条，展示章节和全局资源。

页面标题：

```text
商店行动
```

节点标题放在主面板顶部：

```text
前线军需点
```

或当前节点实际标题。标题下方可放一条世界内短句，不能超过一行。

### 顶部资源带

资源带展示：

1. 当前余烬。
2. 守护值。
3. 存活守卫者。
4. 腐化。

建议文案：

```text
余烬 0
守护值 12 / 12
存活守卫者 3 / 3
腐化 0
```

不再显示：

```text
第一战后的早期商店。适合把首战余烬转成生存或遗物。
商店会消耗 1 个战略 tick，且不会压制任何前线。
```

### 商品货架

货架标题：

```text
购买 1 项
```

每个商品摊位展示：

1. 商品名，去掉开头“购买”二字，让标题更像货品。
2. 小型货品符号，占据摊位上半部，治疗、修复、遗物三个类型要有明显差异。
3. 一行价格。
4. 一行效果。
5. 购买按钮。

示例：

```text
简易急救包
余烬 -3
所有存活守卫者 HP +1
```

```text
路障材料
余烬 -4
守护值 +1
```

```text
裂纹护符
余烬 -5
获得遗物
```

商品标题来自现有配置时可以在 UI 层去掉 `购买` 前缀，不改变数据源，避免影响测试和奖励原因。

## 视觉规则

1. 背景仍使用全局暗色底，必要时叠加低透明度火光色块。
2. 主面板像军需摊位或交易柜台，三列摊位使用稳定等宽布局。
3. 商品摊位保持 8px 以内圆角或无圆角，与现有硬朗 UI 一致。
4. 货品符号用程序化矩形、线条和高光先实现，不新增外部素材依赖。
5. 治疗符号偏绿色或暖白，修复符号偏琥珀，遗物符号可用冷蓝暗纹点缀，但不能变成紫蓝主色调。
6. 价格用琥珀色，收益用浅正文色，资源不足禁用态降低透明度并保留可读性。
7. 不使用大段红色警告框。只有资源不足时，按钮禁用并可用 muted 色提示。
8. 文本不压边、不重叠，商品摊位高度保持稳定。

## 交互

1. 点击 `购买` 后沿用 `_resolve_shop_choice(option_id)`，回到任务委托页。
2. 余烬不足时沿用 `_run.can_afford_effects()` 禁用按钮。
3. `返回任务布告` 保留在页面底部左侧，行为不变。
4. 所有按钮继续满足现有安全尺寸和键盘 focus 规则。

## 实现方案

在 `scripts/core/game_manager.gd` 中改造 `_show_shop_node()`：

1. 移除左侧 `summary` 渲染，并改为单一主面板。
2. 移除红色 tick/前线压制说明。
3. 新增顶部资源带 helper，集中渲染余烬、守护值、存活守卫者和腐化。
4. 新增三列商品摊位 helper，使用现有 `ColorRect`、`ReferenceRect`、`_decor_rect()` 和 `_panel()` 即可。
5. 新增小型货品符号 helper，根据商品效果推导治疗、修复或遗物符号。
6. 新增商品标题清理 helper，把 `购买简易急救包` 显示为 `简易急救包`。
7. 新增商品价格和效果拆分 helper，优先从 `effects` 生成短行，不再依赖长 `description`。
8. 保留 `_effects_text()` 可供其他页面使用，不在本次全局改动。

测试更新 `scripts/tests/test_main_menu_hub_flow.gd`：

1. 商店卡仍能直接打开 `商店行动`。
2. 商店页不包含 `战略 tick`、`不会压制`、`第一战后的早期商店`、`Boss 前补给节点` 等调试/设计说明。
3. 商店页包含资源状态、商品名、价格和购买按钮。
4. 购买后仍回到 `任务委托`，且不回到 `断墙据点`。

## 验证

1. 运行 `test_main_menu_hub_flow.gd`。
2. 如果 Godot CLI 可用，运行相关 Run 流测试。
3. 手动或截图检查 1280x720 下商店页无文本重叠、无红色 debug 框、三列摊位视觉稳定。

## 风险

1. 当前 UI 由 `game_manager.gd` 代码动态拼装，继续在单文件内增加 helper 会让文件更大。本次 helper 只服务商店页，命名保持局部清晰。
2. 如果未来商店商品出现复杂效果，短行生成可能需要扩展。第一版只覆盖当前 `embers`、`warden_hp`、`sanctuary_integrity`、`relic`。
3. 删除长 `description` 展示后，商品需要靠短效果行表达清楚；测试应覆盖当前三类商品。
4. 三列摊位比清单式布局更吃宽度。第一版按当前 1280x720 横屏布局实现，后续如支持窄屏再补响应式规则。
