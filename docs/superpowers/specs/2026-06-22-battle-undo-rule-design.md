# 战斗撤回规则设计

> 日期：2026-06-22
> 状态：待实现
> 范围：战斗内撤回规则、提交点和 UI 表达。
> 结论：正式玩法采用 **本回合内撤回，提交后锁定** ；当前版本不保留跨阶段 Debug 撤回。

## 1. 背景

当前战斗撤回使用 `BattleEngine._history` 保存完整 `BattleState.clone()` 快照，最多保留 50 步。任意非撤回 action 执行前都会入栈，撤回时直接 `pop_back()` 恢复状态。

这个机制适合 Demo、调试和关卡验证，但作为正式玩法偏强：

1. 可以连续跨多个回合回退。
2. 可以从战斗回到部署阶段。
3. 可以看完敌方执行结果后回退到结束回合前。
4. 玩家能免费试探建筑损失、守卫者死亡和敌方攻击结果。

本设计把正式撤回定义为容错工具，而不是读档工具。

## 2. 设计原则

一句话原则：

> 误操作可修正，后果不可试探。

具体含义：

1. 玩家应该能修正误点、操作顺序和本回合内的局部尝试。
2. 玩家不能在看到敌方执行、战斗结算或下一回合局势后免费回滚。
3. 撤回不能替代完美信息预览。攻击线、目标格、伤害预览仍然是主要决策工具。
4. 当前版本只实现正式撤回，避免隐藏工具入口绕过正式玩法压力。

## 3. 正式玩法规则

### 3.1 玩家回合撤回

玩家行动阶段内允许自由撤回本回合操作：

1. 每次移动、攻击、技能释放前记录正式撤回快照。
2. 玩家可以连续撤回，直到当前玩家回合开始状态。
3. 撤回不会跨过当前玩家回合边界。
4. 撤回后视图全量重建，避免动画、预览和特效残留。

允许撤回的 action：

| Action | 是否记录正式撤回 | 说明 |
|---|---:|---|
| `MOVE` | 是 | 修正移动位置或行动顺序 |
| `ATTACK` | 是 | 修正攻击目标或技能前后顺序 |
| `SKILL` | 是 | 恢复技能次数、冷却、护盾、法阵等状态 |
| `END_TURN` | 否 | 提交点，不可撤回 |
| `UNDO` | 否 | 撤回操作本身不入栈 |

### 3.2 结束回合提交点

玩家点击结束回合后，本回合操作锁定：

1. 正式撤回栈清空。
2. 敌方执行阶段不可撤回到结束回合前。
3. 敌方造成的建筑伤害、守卫者死亡、敌方攻击落空、奖励任务进度变化都成为正式结果。
4. 下一回合开始时创建新的撤回窗口。

### 3.3 部署阶段撤回

部署阶段允许撤回部署操作，但确认部署后锁定：

1. 每次 `DEPLOY` 前记录部署撤回快照。
2. 玩家可以撤回摆错的守卫者位置。
3. `CONFIRM_DEPLOY` 是提交点，确认后清空正式撤回栈。
4. 进入战斗后不能回到部署阶段。

这样保留布防容错，但不允许玩家看到第一轮敌方位置、意图或局势后重新摆阵。

### 3.4 战斗结束

战斗结束后正式撤回不可用：

1. 撤回按钮禁用。
2. 键盘快捷键遵守同样限制。
3. 结算面板、Run 状态写入和奖励选择不受撤回影响。

## 4. Debug / QA 规则

当前版本不实现跨阶段 Debug 撤回。

原因：

1. 少一套历史栈，正式规则更清晰。
2. 避免未来误接隐藏入口，绕过提交点。
3. 当前还没有关卡编辑器或 QA 面板，跨阶段撤回没有稳定使用场景。
4. 真需要时，应作为显式开发工具重新设计，并通过独立调试开关开放。

保留现有 F1 调试胜利等开发辅助功能，但这些功能不属于撤回系统。

## 5. 状态模型

正式撤回需要从当前全局 `_history` 拆出当前窗口语义：

| 状态栈 | 用途 | 生命周期 |
|---|---|---|
| `turn_undo_history` | 正式玩家撤回 | 当前部署窗口或当前玩家回合 |

正式撤回栈的生命周期：

1. `start_battle()`：清空正式撤回状态。
2. 进入 `GARRISON`：开启部署撤回窗口。
3. `DEPLOY` 前：压入 `turn_undo_history`。
4. `CONFIRM_DEPLOY`：清空 `turn_undo_history`，部署锁定。
5. 进入 `PLAYER_ACTION`：开启本回合撤回窗口。
6. `MOVE` / `ATTACK` / `SKILL` 前：压入 `turn_undo_history`。
7. `END_TURN`：清空 `turn_undo_history`，本回合锁定。
8. 进入 `BATTLE_END`：清空并禁用正式撤回。

## 6. UI 表达

撤回按钮必须表达当前可用性：

| 状态 | 按钮 |
|---|---|
| 当前窗口有可撤回快照 | 可点击 |
| 当前窗口无快照 | 置灰 |
| 敌方执行中 | 置灰 |
| 战斗结束 | 置灰 |

建议帮助文案：

```text
只能撤回本回合内的操作
```

结束回合按钮附近可以提示：

```text
结束后本回合操作将锁定
```

这类文案只在需要解释风险时出现，不常驻占用战斗 HUD 主信息层。

## 7. 与预览系统的关系

撤回不是主要推演工具。正式玩法应继续优先强化预览：

1. 敌方攻击线持续显示。
2. 技能目标和影响格清晰显示。
3. 关键伤害、推拉结果、建筑受击风险尽量在操作前表达。
4. 撤回只负责修正玩家在本回合内的执行顺序和误操作。

## 8. 后续可选：整回合回溯资源

第一版不实现整回合回溯资源。

如果后续需要增加更强容错，可以设计为稀有正式资源：

1. 每场战斗 1 次，或由遗物、难度、Run 资源提供。
2. 使用后回到当前玩家回合开始。
3. 不能回到部署阶段。
4. 不能跨多个回合连续倒退。
5. 默认不能在敌方执行中或战斗结束后使用，除非明确设计成稀有救命资源。

该功能应独立于基础撤回，不复用基础撤回按钮的常规语义。

## 9. 测试要求

实现后至少覆盖以下测试：

1. 玩家回合内连续撤回可回到本回合开始。
2. 结束回合后无法撤回到结束回合前。
3. 下一回合开始后，不能撤回到上一玩家回合。
4. 部署阶段可撤回部署操作。
5. 确认部署后不能撤回到部署阶段。
6. 战斗结束后按钮和快捷键都不可触发正式撤回。
7. 技能撤回能恢复技能次数、冷却、护盾、法阵、建筑 HP、地裂 schedule 和奖励进度。

## 10. 非目标

本设计不处理以下内容：

1. 不调整敌方 AI、攻击意图或伤害结算。
2. 不设计存档读档或 Run 层回档。
3. 不实现整回合回溯资源。
4. 不改变战斗胜负条件。
5. 不重做预览系统，仅明确撤回与预览的职责边界。
6. 不实现跨阶段 Debug 撤回；后续如需要，应作为独立开发工具重新设计。
