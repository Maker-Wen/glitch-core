# Web HTML5 Build Design

## Goal

Produce a browser-playable GlitchCore build that can be sent to other people as a static HTML5 package.

## Approach

Use the existing Godot `Web` export preset. The release export writes the game to `build/web/index.html`, with adjacent runtime files generated by Godot. This keeps the browser build aligned with the current Godot project instead of introducing a separate web runtime.

## Deliverable

The distributable unit is the full `build/web` directory. The `index.html` file is the browser entry point, but it must stay beside the generated `.js`, `.wasm`, `.pck`, icon, and worklet files.

## Run Model

The build should be opened over HTTP. Direct `file://` double-click launch is not treated as supported because Godot Web builds load WebAssembly and packed data files through browser fetch APIs.

## Tooling

- `tools/export_web.sh` rebuilds the Web export with Godot.
- `tools/serve_web.sh` serves `build/web` on a local HTTP port for verification and handoff testing.
- `docs/web_build.md` documents rebuild, local preview, and sharing steps.

## Verification

After export, serve `build/web` locally and load `http://127.0.0.1:8060/` in a browser. A valid build shows the Godot canvas and starts the GlitchCore game without missing runtime files.
