# 关卡结束奖励列表面板设计

> 日期：2026-06-21  
> 状态：已实现  
> 范围：战斗胜利后的关卡结束页、奖励列表项组件、领奖流程。  
> 不包含：战斗失败、Boss 重试、Run 失败、商店 / 营地 / 事件独立页面重做。

## 1. 结论

战斗胜利后只显示一张 `获得奖励` 面板。

面板只承担领奖职责，不再展示完整战报、总收益预览、奖励任务统计、战损短条或设计解释文本。

玩家看到的是：

```text
获得奖励
断墙前哨 · 委托完成

[奖励项] 余烬 +7       完成普通委托
[奖励项] 额外余烬 +4   额外目标奖励
[奖励项] 防线修复 +1   本章首次完美守住防线

返回任务委托
```

## 2. 设计原则

1. 奖励是主内容，结算信息不抢主视觉。
2. 普通胜利页不要求玩家做构筑选择。
3. 额外目标不作为独立统计模块，只体现在奖励来源说明里。
4. 严重负面结果不进入本页：战斗失败、Boss 未压制、Run 失败仍走对应失败 / 重试流程。
5. 奖励项必须是可复用组件，后续余烬、修复、遗物、升级、章节奖励都使用同一个列表项结构。

## 3. 页面结构

### 3.1 面板层级

| 区域 | 内容 | 说明 |
|---|---|---|
| 标题区 | `获得奖励` | 固定标题 |
| 副标题 | `{关卡名} · 委托完成` | 例如 `断墙前哨 · 委托完成` |
| 奖励列表 | 多个奖励项组件 | 按来源顺序展示 |
| 主按钮 | `返回任务委托` | 领取奖励并回到任务委托榜 |

页面不展示以下内容：

- `总收益预览`
- `奖励任务 2 / 3`
- `守护值 -0`
- `守卫者 3 / 3`
- `保护目标 0 被毁`
- 底部说明或设计解释

这些信息在普通胜利时不是玩家当前决策所需。若出现死亡、守护值归 0、Boss 未压制等强结果，进入失败 / 重试短报，而不是塞进奖励页。

### 3.2 奖励项组件

奖励项组件命名建议：

```text
RewardListItem
```

组件输入字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `reward_type` | `String` | `embers`、`sanctuary_integrity`、`relic`、`upgrade`、`chapter_reward` 等 |
| `title` | `String` | 展示名，例如 `余烬`、`防线修复` |
| `amount_text` | `String` | 右侧数值，例如 `+7`、`+1`，非数值奖励可为空 |
| `description` | `String` | 来源短句，例如 `完成普通委托` |
| `icon_key` | `String` | 图标键，第一版使用文字徽标或现有图标 |
| `rarity` | `String` | 可选，遗物 / 章节奖励使用 |

组件视觉结构：

```text
[图标] [标题]
       [来源短句]
                         [+数值]
```

组件规则：

1. 单行高度稳定，不因文案长短导致布局跳动。
2. 标题和数值必须比来源短句更强。
3. 组件本身不可点击，第一版没有选择态。
4. 没有 `amount_text` 时，右侧区域隐藏或显示奖励类别短标签。
5. 组件可重复使用在战后奖励页、事件结果页、Boss 章节奖励页。

## 4. 奖励数据规则

战后奖励页只消费确定奖励列表。

当前 `pending_reward.fixed_rewards` 可以直接映射为奖励项：

| `reward_type` | 显示 |
|---|---|
| `embers` | `余烬 +N` |
| `sanctuary_integrity` | `防线修复 +N` |
| `warden_hp` | `守卫者治疗 +N` |
| `relic` | `获得遗物：{title}` |
| `upgrade` | `获得升级：{title}` |
| `chapter_reward` | `章节奖励：{title}` |

如果当前奖励数据中存在 `choice_groups`，本次实现不在 UI 上展示选择卡。

本次处理：

1. 停用战斗胜利后的选择奖励生成，只保留确定奖励。
2. 若节点需要给遗物 / 升级 / 章节奖励，也在奖励生成阶段先确定结果，再作为奖励列表项展示。

这能保证页面语义稳定：玩家进入本页就是领奖，不是做选择。

## 5. 流程

### 5.1 战斗胜利

```text
战斗结束
-> apply_battle_resolution
-> build_pending_reward
-> 打开获得奖励页
-> 玩家点击返回任务委托
-> claim_pending_reward
-> mark_current_node_visited
-> 返回任务委托榜
```

胜利后不再进入 `战果短报`。

### 5.2 非胜利

| 结果 | 页面 |
|---|---|
| 普通战非致命失败 | 失败短报，返回任务委托 |
| Boss 未压制但 Run 继续 | Boss 重试短报 |
| 队伍覆灭 | Run 失败 |
| 守护值归 0 | Run 失败 |

非胜利结果不显示奖励列表。

## 7. 缺口检查

| 项 | 结论 |
|---|---|
| 是否需要总收益预览 | 不需要 |
| 是否需要奖励任务统计 | 不需要 |
| 是否需要战损短条 | 普通胜利不需要 |
| 是否需要选择奖励 | 本次不需要 |
| 是否需要奖励项组件 | 必须需要 |
| 是否需要新美术资源 | 不阻塞，第一版使用文字徽标或现有图标 |
| 是否影响失败 / Boss 重试 | 不应影响 |
| 是否影响奖励防重复领取 | 不应改变，继续走 `pending_reward` / `claimed_reward_ids` |

## 8. 验收标准

1. 普通战胜利后直接显示 `获得奖励` 面板。
2. 面板中只出现奖励列表和 `返回任务委托` 按钮。
3. 页面不出现总收益预览、奖励任务统计、战损短条或底部说明。
4. 奖励列表由同一种奖励项组件重复渲染。
5. 点击 `返回任务委托` 后奖励写入 Run 状态，当前节点被标记完成。
6. 非胜利流程仍显示失败 / Boss 重试 / Run 失败，不显示奖励列表。
7. 重进奖励页不会重复生成或重复领取奖励。
